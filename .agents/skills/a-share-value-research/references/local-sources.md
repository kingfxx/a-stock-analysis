# 本地资料与来源

## 已实现适配器

`investment-sina-v1` 读取用户现有 SQLite 的公开资料表：`instruments`、`financial_reports`、`report_overrides`、`raw_daily_prices`、`valuation_observations`、`dividend_events`、`company_report_documents`、`company_report_parses`。只读连接，不调用项目模块、采集器、迁移、缓存重建或后台服务。不导出其他公司、模型任务、凭据或用户组织信息。行业批量数据不是第一版个股财务的自动替代源。

若数据库结构不同，先检查 schema，新增显式适配器或使用 `--input <normalized.json>`；不要修改原表。通用导入格式为 `{schema_version: "equity_research_facts_v1", company: {code,name,exchange}, as_of: "YYYY-MM-DD", sources: [...], facts: [...], warnings: [...]}`。每条事实至少有 id、metric、period、value、unit、scope、status、source_id；缺失金额用 null。每条来源有 id、title、location、published_on、obtained_at。通用导入不执行 SQL，人工提供数据也需标明出处；声明模式为 `normalized-json`，不假称已验证数据库。

## 时间与版本

- 报告期与披露日同时过滤。日期缺失的财务行不用于有截止日的事实计算，登记缺口。
- 报告来源单位、币种和合并范围逐项核对；多币种或未知币种不进入 CNY 指标。
- 获得日期超过历史截至日不等于原始披露晚于截至日，但当前值可能受后续修订影响。保留警告，不声称严格历史回测。
- PDF 注册路径必须在指定根目录内；哈希不符不使用相关 parse。每份文档保留正式版本、披露日和 SHA256。
- 一个 PDF 有多份成功 parse 时选择最新注册版本，导出 parser 版本与文件哈希。解析文本包含的旧 `business_metrics` 不视为事实，重新看原页或结构化财务。
- 行情以 `raw_daily_prices.trade_date` 为交易日。国庆等非交易日的估值观察只是采集快照，不能标为新增交易日。PE/PB/市值保留观察日、来源、单位及是否与所选收盘日一致。
- 同一期来源不同且有效值冲突时留空、列候选，不自动平均或悄悄回退。正式修订是否应替代旧值需原文确认。

## 财务优先级

优先新浪 `gjzb` 的适用字段，再用同期间 `lrb/fzb/llb`。手工覆盖有明确字段及更新时间时保存覆盖来源；截至日后的覆盖不应用。`BIZTOTCOST` 虽在 gjzb 标作“营业成本”，实际是营业总成本；毛利使用 `BIZCOST`。EPS 不能用“归母利润÷期末股本”冒充披露基本 EPS；ROE 使用披露加权值，估算另命名。原始股本科目是权益金额，不当作股数。缺失借款字段不是零，缺完整债务信息不自动计算净现金。

## 分红数据优先级

三年分红及当年中报首先只读查询本地 `dividend_events`，按股票、利润归属期、截至日可知的公告日期和分红状态核对；不要仅按实施年份汇总。读取 `cash_per_ten` 时除以 10 换算每股金额，保留 `report_period`、`notice_date`、`ex_dividend_date`、`status`、`source` 与原始响应。跨来源去重，修订与冲突依据原公告判断。

已实施、已宣告待实施和拟议状态分别保留；不能把同一分配方案的预案与实施记录加总两次。自动取数器只提取已实施事实；研究时需要核对表内其他适用状态，不因自动包未包含就直接认定本地缺失。当前中报是否已披露从对应财报的披露日期确认，不能从分红事件有无反推。

本地已有有效且同口径记录时直接复用；缺年度、缺中期、金额冲突、缺状态或无法确认完整方案时，先核对本地正式财报／公告资料，再针对缺口联网检索交易所、巨潮或公司对应的利润分配、分红实施公告及年报／中报。网络补充用 add-evidence 登记，不写回日常数据库。表中没有记录不等于零分红，不能用旧期金额补当前期，也不重复抓取已完整覆盖的数据。

派息率分母优先取本地同期间 `financial_reports` 的归母利润；历史股息率用归属当年现金分红总额除以年末市值，分母优先只读 `sw_cap_facts` 对应年末最后交易日的 `total_cap`。解析 `provenance_id` 关联 `sw_cap_provenance`，兼容旧行内来源，核对单位、版本和原始响应。当前中报用六月末市值，半年未年化。只有对应市值／财务指标缺失或口径不符时才联网补来源，不以当前市值或邻近季度替代。

## 网络补充

本地包完成后列出缺口，再用可用 web/search 或 `a-stock-data` 定向补充。重大事件先查正式公告；机构研报用于研究线索和预测而非替代正式财报。先使用交易所/巨潮原文，其次行业机构、公司/同业披露，再用研报与媒体解释。

来源需保存 URL、标题、日期、作者/机构、引用片段及检索日。机构预测与自主假设分别标记。只得到摘要时标为摘要；不可声称读过全文。若接口受限，使用可访问的公开来源或明确缺失，不绕过付费/登录限制。

## 原始财务响应的体积控制

取数器将本次查询的原始响应保存为 `sources/financial-raw.json.gz`，使用紧凑JSON及gzip压缩，不删字段、空值或有效零值。`facts.json` 仍保存可阅读的事实、字段码、来源哈希及计算公式；报告HTML不依赖压缩原始数据。工具 `load(path)` 兼容普通JSON和 `.json.gz`，也可通过 Python 标准库 `gzip.open(path, "rt", encoding="utf-8")` 读取。

旧报告的未压缩文件仍可读取。历史文件转换时必须先验证解压后的JSON对象与旧文件一致，再删除旧文件；存在manifest时同步更新对应文件名与文件SHA256。只移除重复导出，不删除数据库原始记录、正式财报或行业来源响应。只留脚本而删除快照会依赖数据库当时版本，不保证后续可复现。
