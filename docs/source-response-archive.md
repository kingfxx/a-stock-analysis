# 公共响应归档

后台维护的「响应归档」按北京时间实际取得月份、提供方和数据集整理已登记的公共响应文件。原响应已逐个 gzip 压缩；打包主要减少文件数量，不承诺减少占用。个股等 `metadata_only` 记录没有响应文件，不参与打包。

手动操作先选已结束的截止月份并预览，确认后执行。后台再次检查来源记录和双哈希，将 gzip 文件原样写入带版本清单的 ZIP，验证后登记映射，再逐个复核并移除散文件。执行结果、异常数量和报告路径显示在页面；详细报告保存在 `data/verification/reports/source_archive/`。归档包按月和数据集分卷，名称带唯一标识；迟到文件生成新包。遇到冲突或校验失败时保留相关散文件，并在报告中说明。

月度计划默认关闭，启用后按指定北京时间运行，日期超过当月天数时在月末运行。保存配置不会立即执行；后台停机期间漏过的槽位合并到最近一次，首次启用从未来槽位开始。计划仅执行本地整理，不请求数据来源。后台必须运行才能执行计划。

来源记录继续保留原始路径与哈希，读取散文件缺失时从映射中的 ZIP 成员读取，并验证存储及原文哈希。页面可输入来源 ID 把单个文件恢复到原路径，不覆盖已有不同文件；恢复后的散文件在下次归档时可再次清理。早于映射表的数据库快照可通过同目录 ZIP 清单及原记录哈希读取，多个匹配、缺包或校验失败会报错。归档包中断发布时，下一次运行核验未登记包后再登记；存在冲突时停止，不删除原文件。

SQLite 备份不包含散文件、归档包或报告，归档也不是备份；备份或迁移时须同时保存数据库旁的 `collection_sources/` 目录，并校验文件哈希。恢复旧版本软件前应先使用当前版本恢复散文件；旧软件不会自动读取 ZIP。
