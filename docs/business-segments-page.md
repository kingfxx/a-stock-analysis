# 主营构成页面

入口：左侧「主营构成」，也可使用 `/?code=601919&tab=business`。保持现有股票选择及深色布局；手机导航分两行，图表与明细在各自容器内横向滚动。

## 读取与筛选

进入页面或点击「重新读取本地数据」只调用 `GET /api/business-segments`，不发起来源采集、财报下载或模型生成。现有个股更新结束后，当前主营页面重新读取本地事实；采集仍遵循[个股采集说明](stock-collection.md)。

可按产品、行业、地区选择维度；按实际存在的年报、中报、一季报、三季报选择累计口径。默认年报，无年报则采用最新已存报告类型。最近3／5／10年以所选类型最新已存年份为终点，缺少整期记录时留下空时间槽，不制造事实。无数据时说明本地暂无记录，不自动补采。

收入／成本／毛利、金额单位联动规模、结构与同比分析。项目筛选联动前四张图；超过10个跨期项目时初始展示按最近有效收入绝对值排序的前8项，可手动全选。摘要按最新所选报告期的完整维度，独立显示最大正收入项目、其来源收入占比和毛利率（单项取原值，明确地区分项汇总时按完整金额计算）；不随项目隐藏重算。

## 图表和明细

- 分项规模：正负分别堆叠，保留抵销；柱高不视为公司完整合计。切换收入、成本、毛利。
- 结构变化：对应三种来源占比，小数乘100显示百分数；无100%归一化，隐藏项目不改变分母。
- 同比：最近三个实际同类报告期各与上年相同月日、相同展示身份比较（统一名称模式）或相同来源 `item_key` 比较（原始名称模式），公式 `(本期/上年同期-1)*100`。基期非正或任一期缺失时不可比。本期为零或负、基期为正时保留实际结果。
- 毛利率：单项来源小数乘100；明确同地区多业务合并时用完整毛利合计÷收入合计，收入须为正，不取毛利率的算术平均。分类缺项、整期缺失时断线；不自行用收入与成本补齐毛利。
- 地区分布：固定地区维度，支持所选指标的金额／占比，展示最新所选报告期地区完整明细。前三块已选地区时收起重复地区图，只保留地区明细。
- 历史完整明细：保留所选维度全部项目及合计行、七项指标、修订号和实际取得时间，默认折叠，不受图表项目隐藏影响。地区表始终展示全部项目。

## 来源与边界

数据来自 `business_segment_versions` 当前版本和关联的 `business_segment_items`；API维度1为行业、2为产品、3为地区。金额以来源元值换算元／万元／亿元，比例字段按小数解释。已验收样本601919、605499按人民币元解释，其他币种须核对正式报告。

| 指标 | 本地字段 | 东财字段 |
|---|---|---|
| 收入 | revenue | MAIN_BUSINESS_INCOME |
| 成本 | cost | MAIN_BUSINESS_COST |
| 毛利（来源称主营利润） | gross_profit | MAIN_BUSINESS_RPOFIT |
| 收入占比 | revenue_share | MBI_RATIO |
| 成本占比 | cost_share | MBC_RATIO |
| 毛利占比 | profit_share | MBR_RATIO |
| 毛利率 | gross_margin | GROSS_RPOFIT_RATIO |

这些是主营分项事实，不使用新浪公司整体指标填补分项。毛利不是净利润。有效零、负值保留，缺失显示「—」；来源网页将空比例渲染为0%的情况不会复刻。API转换为JSON数值存在浮点精度限制，图表和表格显示两位小数，不作为Decimal精确复算接口。

默认按下述展示名称映射对齐跨期身份，切换「原始名称」可恢复代码＋名称的来源item_key。只有名称完全匹配「合计、总计、主营业务合计、主营收入合计、主营业务收入合计、营业收入合计、营业成本合计、主营业务成本合计」才从图表排除，明细仍保留。以“其中:”或“其中：”开头的下级明细不与主项叠加，原值及标识保留在完整表格。其他分类小计不猜测；类别变化、分类层级重叠和披露不全须核对原报告，不跨行业、产品、地区维度加总。颜色按该股已存同维度、当前名称模式的展示项目固定，收入、成本、占比和毛利率共用；同比颜色表示报告期。

不改数据库结构，不新增采集或定时任务，不增加企业经营趋势指标。

## 展示名称归并（2026-10-16）

默认「统一名称」，同一展示身份同时用于规模、占比、同比、毛利率、地区图及项目选择。归并不修改数据库、来源字段、修订和实际取得时间；API仍返回原始事实。明细始终保留原始名称和七项原值，以箭头标注统一名称。悬浮显示该点原始名称；同比显示本期、上年同期原名。新增「名称归并依据」列出映射、规则版本及同期间冲突。

通用处理：全半角与空格规范、同公司同维度的同名项目跨代码变化、业务／分部末尾标签规范（不去除「及相关业务」或未知括号限定）。地区仅精确对齐海外／国外、欧洲／美洲／亚太的名称变体，以及华东、华南、华中、华北、华西、西南、西北、东北相同地理根的区域／地区／战区／大区标签；不去掉「含北方大区」等范围限定，不推断国内、内地、境外的范围相同。来源ITEM_CODE可能复用，不能单独作为业务身份。

需要语义确认的品牌、大类和公司特定地区名称，集中维护在 `web/business-segment-aliases.js`，按股票代码、维度限定，统一由 `web/business-segment-names.js` 应用。当前包括605499能量饮料与东鹏特饮／销售东鹏特饮相关名称，601919航运、码头、抵销及中国地区／中国大陆。规则可扩展，不在各张图单独写匹配逻辑。不使用模糊相似度、金额相近或模型自动合并；美的业务重组前后的产品大类等未确认范围不强行拼接。

同一候选身份若在任一期出现多条，默认将整个历史组标为冲突并保留各自原始身份，即使数值相同也不擅自去重。唯一允许同期间相加的情况是规则显式配置的互斥业务分项：当前601919地区中，以括号明确标注航运／码头的同地区项目，按不同业务限定汇总；有未限定的地区总项、重复业务分项或其他未确认行并存时不汇总。

允许汇总时：收入、成本、毛利和三种占比各自只有全部参与项有效才相加，否则该字段留空；有效零、负值保留。毛利率仅在收入为正且全部毛利有效时按汇总毛利÷汇总收入计算，不用已有毛利率填缺；计算字段在悬浮中标明「同地区分项汇总」。不将原始缺失字段写回或补零，不跨维度汇总。

扩展规则需明确公司、维度、统一名称、完整别名清单与依据，更新规则版本；若是汇总还需明确互斥分项集合。随后运行 `node tests/business_segment_names.cjs`，并对实际样本检查同期冲突和完整金额守恒。静态资源版本在 `web/index.html` 更新，以便浏览器读取新规则。

悬浮标签采用统一深色底、浅色字、灰色边框；同比报告期放入主提示，移除颜色随系列变化的附加名称框。
