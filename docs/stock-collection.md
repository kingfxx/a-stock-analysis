## 个股主营构成

已存主营构成的前端分析入口及计算限制见[主营构成页面说明](business-segments-page.md)，页面读取本身不触发本节采集流程。

2026-10-16新增 `BusinessSegmentService`，使用东财 `RPT_F10_FN_MAINOP`，只查询单只股票。个股既有financial操作（普通到期检查／refresh／full）在财务子任务之后独立检查主营构成；财务失败仍可更新主营构成，主营构成失败不撤销财务成功。不新增全市场、定时任务、图表或跨期产品分类映射。

- 首次、显式full、180天审计按上海今天前十个日历年（闰日回退二月28日）至今天过滤REPORT_DATE；不使用PageAjax的200条截断结果。滚出窗口的已存事实仍保留。
- 增量从窗口内最近两个实际报告期的较早一期至今天，只一期则从该期；没有实际期则查十年。接受实际出现的年报、中报、一季报、三季报，不强求季度都有主营构成，不做单季差分或TTM。旧窗口之外补登／修订由full或审计发现。
- 独立 `SyncKey(dataset='business_segments', source='eastmoney:RPT_F10_FN_MAINOP')`；成功含空结果缓存24小时，失败自动抑制600秒。手动刷新不能绕过公共eastmoney冷却。checked_at表示成功检查，coverage_start/end为累计已成功查询外边界，实际报告期水位独立；各次精确查询范围在sync_runs及batch.result_json，不把边界解释为逐字段覆盖完整。
- 每页显式500条，按报告期、分类、RANK、名称、代码排序；核验总数／页数／页长、股票、日期、类型、十进制有限数值、唯一项目和跨页重复。多页后重查首页业务内容，整窗口校验完才短事务发布；批次coverage_status保持unknown，result_json记录本次范围、总数、页数、实际期和缺字段数。
- 请求使用既有routed_stock_requests、stock_fast及metadata_only：共用eastmoney锁、预算、拒绝停止和冷却。只在内存解析原始JSON；公共来源保留请求参数／状态／取得时间，原文文件／双哈希为空。
- `business_segment_versions`按公司×来源×报告期保存完整业务版本，业务相同不新增，数值修订或补行补字段新增版本并保留旧版；项目消失或已有有效值变空则整段拒绝并保留旧事实。来源排序变化不触发修订。每条明细引用其实际来源页；版本取得时间为该期参与来源页的最后取得时间。
- `business_segment_items`保留来源行业1／产品2／地区3、代码及名称；金额和比例以Decimal规范化后存TEXT。收入MAIN_BUSINESS_INCOME、成本MAIN_BUSINESS_COST、毛利MAIN_BUSINESS_RPOFIT，比例MBI_RATIO/MBC_RATIO/MBR_RATIO/GROSS_RPOFIT_RATIO按小数保留。零、负值和null原样表达，比例不限定0至1；毛利不是净利润，缺值不自行收入减成本补齐。样本601919、605499金额按人民币元解释，接口未提供统一币种字段，其他币种须另核实，不在API臆造币种。

## 巨潮公告日期元数据

个股财务同步可触发巨潮公告目录元数据检查；纯缓存读取不发公告请求。股票首次财务初始化时同步建立公告历史及身份，无需再手动刷新一次；初次建立身份须由调用方传入 `allow_initial=True`。已核验的 `szse_stock.json` 索引同时包含沪深股票，当前仅匹配唯一 `orgId`，避免每只股票额外索引请求。一次完整查询范围作为一个经完整校验的发布段，按已验证的六类目录查询年报、半年报、一季报、三季报、业绩预告和权益分派；类别集合及配置版本写入批次范围，扩大类别后重新验证完整范围。业绩预告源类也包含业绩快报；权益分派源类包含预案、实施及说明会公告，这些类只保留元数据，不参与正式报告披露日判定。代码依据官方有限探测记录 `data/verification/reports/cninfo_selected_categories_20261014.json`（source 2143、2144、2147）。分页按 `totalAnnouncement` 和实测30条页容量计算应取页数，再用 `hasMore`、每页长度、重复公告及首页复核确认。实测 `totalpages` 是向下取整值：沪电93条/3页、601919共91条/3页，实际两者都需请求4页；小于30条时也观察到2条记录而 `totalpages=0`。因此不直接以该字段当作实际页数。请求起点不早于上海当前日期前十个日历年；后续增量以数据库适用分类、已验证公告的最新实际发布日期为含当天的起点，补到上海今天，不再固定回看90日；公告元数据的来源分类集合须为当前查询分类的子集，不能用无关分类推进水位。当前分类已成功查询但无适用公告水位时，从上次成功查询终点含当天补尾。首次、全量和类别扩展查询完整范围，显式 start 保留用户指定起点，但均不早于十年下限。自动刷新成功后24小时内复用缓存，自动失败10分钟内抑制重试；显式 `refresh/full` 可请求一次更新，但仍遵守 cninfo 提供方冷却。

只保存筛选后的公告编号、标题、公告时间、附件相对路径、报告期候选、规则状态和真实来源引用。`announcementTime` 转上海日期作为公告日期；附件路径日期只用于发现冲突。请求范围和全部页通过校验后，公告元数据版本及报告期日期判断在短事务发布。重复元数据不新增版本；财务读取提供新浪原始日期、校正候选、最终日期、最终来源/状态、最近已知修订日期和规则版本。人工日期及人工 null 覆盖优先。

公告自动同步绝不下载 PDF、读取正文、缓存响应原文或正文片段；`metadata_only` 请求只在内存解析，公共来源文件路径、哈希和字节数为空。正式财报下载准备链仍独立运行，尚未统一到该公告元数据请求预算。命中原始报告只证明标题/时间元数据匹配，不能证明本地财务数值对应首次披露版本，尾部补差不能发现任意历史内部的删除、补登或元数据修订；需要显式 full 或定向 start 核验。成功查询终点 coverage_end 与实际公告 data_watermark 分开记录，不以采集时间代替公告日期。

## 元数据与证据边界

公告列表的“业绩预告/快报”筛选同时识别业绩预增、预减、预盈、预亏等标题。列表读取对旧缓存按当前标题规则派生类别，因此旧的unknown分类快照不需要重新采集就能显示；原始元数据记录仍保留。新采集使用相同标题识别规则，业绩类不参与正式财报首次披露日判断。

普通公告更新沿用最新已验证公告发布日期（含当天）的尾部增量；新增更早财务报告期不自动扩大历史查询。日期判断只处理新/变化公告涉及的报告期（含变更前后的关联）及已覆盖目录中的新报告期，其余历史结果原样复用；明确 full/start 或分类/规则身份变化时才按指定范围重新核验。十年范围外无证据的旧期不新建缺失判断，已有旧记录保留但不触发汇总警告；近十年 pending/missing 仍列明数量和具体报告期，成功同步不代表历史完整。

个股 batch scope 显式记录股票代码、sync run、数据集、实际来源接口、更新模式和 `evidence_mode=metadata_only`。每次 HTTP 请求与重试经同一个 `RequestCollector` 登记到 `collection_sources`，包含脱敏参数、请求状态、HTTP 状态、解析状态、错误类别和真实取得时间。`collection_sources.parse_status` 表示该次响应是否完成来源页级解码／解析；它不表示整个数据集的跨页完整性或业务候选验证结果。后续跨页／业务校验失败时 batch 仍标记失败，失败 run 不提交业务事实。

个股响应体只在内存交给现有解析器，不写到 `collection_sources/`，不保存正文片段、原文哈希、压缩副本或 BLOB；相关文件、哈希和字节数为空。`read_source` 与 `reusable_source` 不能重放此类请求。业务表原有 raw_json 继续保留来源拆分后的业务记录，它不是完整 HTTP 原文。旧个股事实不新增公共 source 外键，公共 batch 与旧业务事实通过既有 `sync_runs` 及行内 run_id 关联，不能声称旧表逐行精确映射到分页来源；新主营构成明细是独立设计，具有精确source/batch外键，不存raw_json。

公共批次完成状态与成功 sync run、事实发布及水位更新在同一事务提交；失败时保留来源请求记录、关闭关联批次并保留旧事实。服务重启时，将 `sync_runs:<id>` 对应的未完成 stock 批次关闭为失败。无原文缓存，未发布段恢复只能按原同步策略重新请求；已发布事实段继续复用，不代表可重放原响应。

## 提供方调度与失败处理

股票请求分别使用固定 provider `sina`、`tencent`、`eastmoney`、`baidu`。这些标识与同一数据库中的全市场／行业／指数任务共享 `collection_provider_state` 的跨进程预算和冷却；不能按股票或接口拆分。个股页面请求继续使用跨进程同源锁并逐次记入共享请求计数，但跳过公共 10 秒间隔、滚动 60 秒 5 次上限及每 20 次休息，以接近原采集速度。全市场／行业／指数请求仍按默认限速执行，并把个股请求计入共享窗口，必要时等待窗口恢复。普通连接错误、超时和 500/502/503/504 最多三次尝试，等待至少 60/120 秒加随机间隔。401/403/429、验证码、频率限制及反爬响应立即停止本轮同源请求并至少冷却一小时，服从更长的 `Retry-After`；手动刷新不能绕过冷却。

巨潮 `cninfo` 有独立的公共提供方策略：完成后间隔 2 秒、jitter 0、滚动 60 秒最多 30 次，每 20 次不额外休息；并发 1，冷却至少一小时，重复拒绝继续延长并遵守更长的 `Retry-After`。GET 和 SDK invoke 共用锁、状态和策略。该策略不会改变以上四个股票来源的 `stock_fast` 行为；旧独立巨潮 PDF／历史股本采集链仍未接入公共调度。

冷却到期后的单次恢复探测按来源结构核验：新浪检查 JSON `result.status/data`；腾讯报价检查其 `v_` 响应，腾讯行情检查 `code/data`；百度检查嵌套 `Result`；东财检查 `success/result` 或明确的 9201 无记录响应。无效探测继续冷却。本 run 的拒绝异常不会被融资历史缺口补偿、分红窗口补偿、百度窗口扩大或价格历史扩展吞掉并继续同源请求。

普通自动同步失败后十分钟内不重复自动请求，也不更新成功水位；页面显示已有缓存和失败警告。用户手动刷新可绕过该十分钟间隔，但仍受公共预算和冷却保护。页面在等待时保留缓存与更新状态，不显示空数据或伪报完成。

覆盖状态目前保持 `unknown`：执行完成不等于完整覆盖。报告期、股东披露日和交易日不是采集更新时间；维护统计分别使用 `collection_batches.started_at/finished_at`、`collection_sources.obtained_at` 及 provider state 的 `updated_at`。

## 机构盈利预测临时读取（2026-10-21）

股息率计算器D模式仅在用户选择或显式重读时访问同花顺F10盈利预测页。公共provider为`ths`，沿用保守默认限速和共享冷却，无自动到期检查。`stock.institution_forecast`批次及source仅存请求元数据、解析状态、取得时间；结果、原文、哈希及预测事实均不落盘，不创建sync事实表，批次完成不代表覆盖三年。浏览器也不保存预测值。实现口径见[股息率预测计算器](dividend-forecast.md#机构预期模式2026-10-21)。
