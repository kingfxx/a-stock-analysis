# 财务、Checklist 与公司财报开发规则

本文件是根目录 AGENTS.md 的按任务补充指令。修改财务指标、行业财务、Checklist、正式财报或研报技能前必须阅读对应章节。涉及批量采集时同时阅读 [采集规则](/docs/agent-rules/collection.md)。

## 财务指标取数优先级

- 第一个 tab「企业经营趋势」新增指标或调整既有指标时，必须同步更新 `docs/enterprise-trend-metrics.md`，包括财务对照、估值及筹码指标的含义、计算公式、实际来源表／字段、周期口径、单位、缺值处理和适用限制；文档按实际代码实现维护，不能将计划中的取数规则写成已实现行为。README 仅保留概览和该文档入口，不重复详细指标说明。

- 行业页面（公司对比、行业汇总、各级排行、趋势及已保存股票比较）统一通过 `market_financial_industry` 轻量 View 读取新东财利润表及业绩指标，不再读取或回退 `sw_financial_facts`。周期转换、可比公司汇总和覆盖门槛在 Python 统一计算；排行按需读取报告期，趋势按需读取所选行业，缓存有界并随新财务发布及成员版本失效。个股新浪优先规则不变；以下旧行业指标取数与来源规则仅适用于保留的旧工具，日常按钮已不再兼容写入旧财务表。

- 全市场三表及业绩指标新来源层统一命名 `market_financial_income/balance/cashflow/performance`，四接口均取 `columns=ALL`，来源和批次集中保存。日常财务按钮与历史回填只发布新四表，不更新旧 `sw_financial_facts` 或旧财务来源、不读取个股新浪；日常任务前分类检查保留，市值使用原独立流程。用户已授权在原 2016-09-30 至 2026-06-30 基础上向前补两年（2014-09-30 至 2016-06-30，共八期）；财务校验允许最近十二年，市值仍十年。页面报告期按实际新表覆盖生成。

### 保留旧工具的规则（不适用于日常财务按钮）

- 行业全市场轻量数据新增的营业收入、营业成本、扣非归母净利润、营业利润四字段统一取东方财富 `RPT_DMSK_FN_INCOME`，不按本地新浪优先回填；新浪仅作为核对样本。此例外仅适用于这四字段的行业批量采集，原有营收／归母净利润及个股取数优先级不变。历史补采不改写原有营收、归母利润和披露日；缺字段留空，毛利率按适用口径读取时计算。
- 行业财务来源通过 `sw_financial_provenance` 集中保存，`sw_financial_facts.provenance_id` 引用，行内 `provenance_json` 仅保留兼容占位。读取必须解析来源引用；新抓取、历史补采和缺值回退均使用统一入口，不重复嵌入路径、参数、哈希和指标定义。原始响应文件保留。仅指标金额、披露日或定义变化新增财务版本；本次字段扩展完整替代的旧行可在备份及金额／来源校验后离线清理，真实修订版本保留。

### 个股财务取数（行业新来源层除外）

- 新增或接入财务指标时，优先检查本地 `financial_reports` 表中 `report_type=gjzb` 的新浪关键指标原始 JSON；该指标在对应报告期缺少有效值时，再从 `lrb` 利润表、`fzb` 资产负债表、`llb` 现金流量表中提取或基于三表计算。
- 取数前核对指标定义、报告期、累计／单季度／年度／TTM、单位、合并／归母及加权／估算等口径。`gjzb` 有同名指标但口径不适用时，按未找到适用指标处理，不直接替代；已有指标不因取数优先级而自动改变口径。
- 有效零值应保留；缺字段、null、空字符串或无效值不能当作零。回退时按股票和报告期逐项判断，不用旧期值冒充当前期。保留实际来源、来源字段码和计算方法，区分直接取数与自行计算。
- 三表也缺少适用资料时，明确留空并标记待补，不编造数值；需要财务附注或业务明细的项目另从正式报告补充。

## Checklist 与公司财报

- 页面启用 18 项定性 checklist，每项一至两句；旧 AI 研判代码、提示词和历史保留但页面不挂载。新旧任务按 output_schema_version 区分；checklist 内部 verdict=checklist 仅为兼容旧表约束，不能展示为投资结论。
- 正式财报存放 `data/company_reports/<交易所代码>/<报告期>/v1/report.pdf`，不增加 annual 子目录。披露日、来源、修订关系登记 SQLite；逐页缓存按解析器版本保存，主题片段按提取版本保存。
- 不从 verification 目录直接提供正式业务资料；导入保留来源样本。删除 checklist 不删除原件、解析和主题缓存，日常清理不触及正式财报。
- 查看页面、历史、准备财报不自动调用模型；仅明确生成使用额度。优先复用相同哈希的缓存，常规生成仅一次模型调用。
- SQLite 备份不包含 PDF；完整资料迁移用 quarterly_dashboard.report_backup，验证哈希，恢复到不存在的新目录，不自动覆盖日常库。

财报同一期文件按 `v1、v2…` 编号，完整 SHA256 仍登记数据库和 manifest 用于去重与校验；版本编号不会因删除而重排。旧哈希目录迁移后，历史快照原路径可通过内容哈希解析到当前路径，不改写历史报告。

## 项目研报技能

- `a-share-value-research` 的维护入口是 `.agents/skills/a-share-value-research/`，技能、框架、模板、脚本及测试随 Git 管理，不修改用户目录中的旧副本。迁移说明见该技能的 `references/installation.md`。
- 默认数据配置使用项目相对路径，不写死盘符、用户名或 Python 缓存目录。新电脑先运行技能的 `doctor`；数据库及正式财报由现有备份恢复或采集流程准备，不随技能上传。
