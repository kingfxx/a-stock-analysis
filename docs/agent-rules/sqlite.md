# SQLite 存储与维护规则

本文件是根 AGENTS.md 的必读补充。新增／扩展采集存储、变更表或迁移、修改维护统计前阅读；采集和财务任务同时遵守对应规则。

- 新增或扩展采集存储时，优先通过引用复用来源和公共元数据，避免逐行重复大段 JSON 或保存无必要的数据副本。上线前用代表性数据核对每行占用、含索引总大小及写入／常用读取耗时；精简不得损失数值精度、真实来源和修订证据。
- 新增任何数据库表，须同步更新 [SQLite 存储说明](../sqlite-storage.md) 对应章节；详细设计另有文档时附链接。
- 新增表、改名或调整用途时，同步在 `stock_analysis/maintenance/maintenance.py` 的 `DESCRIPTIONS` 登记用途与分类，不能遗留「尚未登记用途」或落入默认分类。
- 真实采集／写入时间用 `TIME_COLUMNS` 识别，关联时间用 `PARENT_TIMES` 或 `table_time` 明确路径；报告期、交易日不能代替更新时间。无适用记录显示「未记录」，并在相关文档解释。
- 隔离库迁移后核对维护页／统计接口的表发现、用途、分类、记录数、大小及时间依据；特殊时间规则检查空表、缺值并同步文档。详见 [数据库维护](../database-maintenance.md)。
- SQLite 备份不包含原始响应及 PDF，资料迁移须同时处理文件并校验哈希；不得用隔离测试库覆盖日常数据库。
