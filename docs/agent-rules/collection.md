# 批量采集开发规则

本文件是根目录 AGENTS.md 的按任务补充指令。新增或改造批量采集、迁移采集元数据、历史回填及覆盖验收前必须阅读；规则是接入要求，不表示所有旧流程已完成改造。指数的实际实现见 [指数估值采集](../index-valuation-collection.md)。

## 公共集采设计与接入规则

- **以后新增或改造批量采集，统一复用 `quarterly_dashboard/collection.py` 的公共来源归档、请求调度及 `collection_batches / collection_sources / collection_provider_state`，不各自实现批次追溯和限速。** 指数接入参考 `index_collection.py`；实际机制见 `docs/index-valuation-collection.md`。既有财务／价格采集尚未全部接入，不能把本规则描述为旧流程已统一；旧历史迁移另定范围，不因新增采集自动迁移或改写旧数据。
- 职责分层：一次用户启动是一个 operation；按日期段／报告期／名单范围／行业层级划分可独立校验、提交和恢复的 batch；每次实际请求及每次重试是一个 source。operation 管启动、取消、进度、互斥及最终汇总，batch 管分段执行和覆盖，source 管参数、响应及解析证据。当前 `index_collection_operations` 是指数任务控制表；其他领域优先复用适用的现有控制层，确需统一时再设计公共 operation，不为每个接口新增一套任务表。operation 汇总可来自批次，不重复存储原始响应。
- 公共批次明确登记 `domain/dataset/source_system`、`operation_id`、范围和范围参数、频率、名单版本（适用时）、触发方式、解析及定义版本、真实开始／结束时间。幂等键和恢复判断必须包含实际业务范围及口径，不能只凭开始日期或任务名称跳过不同名单、层级、接口或定义的任务。
- 每次请求（成功、失败、拒绝、重试）集中登记来源：真实提供方、脱敏请求参数、批次、请求标识、尝试序号、HTTP／请求／解析状态、错误、实际取得时间、原始文件和哈希。原始响应在数据库旁 `collection_sources/` 原子归档，分别保存 HTTP 解码后原文 SHA256 与压缩存储文件 SHA256；先保留证据再发布事实。无响应时允许文件／哈希为空；未知参数、时间和旧历史不能编造。缓存复用保留原采集时间和复用关系，不冒充新请求。迁移／备份恢复必须同时考虑原始文件，SQLite 备份不包含它们。
- 事实通过来源及批次引用追溯，保证 source 属于同一 batch；不逐行复制路径、参数、哈希及完整口径说明。提供方、接口序列、指标定义／版本、频率及统计方法不同，保持独立身份，不悄悄拼接。仅业务指标或定义真实变化新增事实修订；重复响应仍保留来源，未变化事实不新增版本或改写原出处。有效零／负值按定义保留，缺失留空；有值变空需核实撤回原因，禁止静默覆盖。
- `collection_provider_state` 是按来源共享的运行状态，不是批次历史：保存请求预算、拒绝原因、拒绝次数及冷却截止时间，跨任务／重启延续。同一来源各接口、主机、分页、cookie获取和重试默认共享预算；接入前明确真实提供方标识及限流范围，只有来源证据支持才拆分。**旧元数据迁入公共表不会自动获得保护，旧请求代码也必须接入统一调度入口。**
- 默认保守策略：同源跨线程／跨进程并发1，请求完成至下次发送至少10秒加0—5秒随机等待，滚动60秒最多5次，每20次实际请求额外休息60—120秒。计数覆盖失败和重试，发送前预留预算，完成后持久化状态；不能通过新任务、重启或换接口重置预算。来源要求更慢时进一步收紧；调整默认值须有来源依据和验证，不为缩短回填时间擅自提速。
- 403／429、验证码、频率限制及反爬HTML等拒绝立即停止本轮全部同源请求，保留证据，持久化至少一小时冷却，并遵守更长的 `Retry-After`；反复拒绝延长冷却。后续任务到期只发一次恢复探测，有效才继续；本轮不自行反复试探。其他来源可独立继续。不得通过IP／代理轮换或验证码绕过规避限制。普通连接错误、超时、暂时500／502／503／504最多3次尝试，重试至少60／120秒加随机等待，仍受正常预算约束。
- 网络请求、限速等待、重试及原文归档期间不持有SQLite写事务；等待须可取消，剩余时长一次计算且不向休眠函数传负数。短事务发布已校验分段，取消／失败保留已提交分段和来源；恢复跳过符合相同范围且已验证完成的分段，失败／明确缺口分段定向复查。不得因继续采集丢弃历史修订或重新请求全部已完成数据。
- 分页先核实来源支持的页容量，再检查总数稳定、页长度、跨页重复、代码、日期、字段及单位；一个发布分段的所有页完整校验后才提交事实。来源截断、空页或结构变化不能按成功发布部分数据。分段大小按来源和事务负担选择，不硬性要求逐证券／逐行业请求；例如申万按月份×层级取所有行业、每页500条，不是单行业十年一次抓取。
- **执行成功与数据覆盖分开登记。** 全部分页完成不等于每个对象、日期、指标完整；分别核验交易日／报告期、名单历史有效期、逐指标有效首末日期及缺值，区分来源缺行、指标空值、请求失败和未知覆盖。名单／有效期未核实时覆盖保持未知，首条观测不当作成立日；不能用零、旧期或插值补齐，也不能把HTTP200空列表或403解释为指数不存在。常规补新数据先查本地来源／序列水位，只补尾部新增日期，已最新时跳过数据请求；修订核对另设重叠窗口，不混同补新数据。久未运行须补尾部空档，批量名单按适用层级及成功分段独立判断，避免停用对象拖回多年；无既有数据明确首次建档策略，历史内部缺口另做可控复查。页面读数据不自动启动来源采集，定时任务需独立授权。
- 使用隔离库、假时钟及模拟响应验证同源并发／跨任务预算、冷却恢复、重试、取消、分段恢复、分页截断、幂等修订和来源外键；有限真实样本验证接口及页容量，不用大量请求测试封禁阈值。历史回填完成后只读核对原文双哈希、分页总数、双向来源／事实对照、重复键、日期和逐指标缺口，保存可复核报告；不能仅凭任务complete宣称全量完整。新表继续遵守下方维护页用途／真实更新时间登记规则。

## 个股已授权例外

- 个股浏览器普通刷新保留现有到期检查；估值、融资日更需求已由用户确认。此例外不授权扩大股票范围、创建定时任务或运行历史回填。
- 个股 HTTP 读取通过同一 `RequestCollector` 及 `collection_provider_state`；共享标识固定为 `sina`、`tencent`、`eastmoney`、`baidu`，不得按股票、接口或任务拆预算。
- 个股页面请求为保持旧加载速度，持有同一个提供方跨线程／跨进程锁并逐次记录共享预算，但跳过公共请求间隔、滚动 60 秒 5 次上限和每 20 次休息；仍遵守来源冷却及拒绝后停止规则。全市场／行业／指数采集仍执行默认限速，读取同一来源的个股请求记录，必要时等窗口恢复后再发。
- 巨潮 `cninfo` 使用公共 `RequestCollector` 的提供方级授权策略：请求完成后至少间隔 2 秒，jitter 为 0，滚动 60 秒最多 30 次，每 20 次无额外休息；并发仍为 1，至少冷却一小时并继续执行重复拒绝延长及 `Retry-After`。GET 与 SDK invoke 共用此策略和同源状态。它不改变其他来源的默认下限，也不属于四个股票来源的 `stock_fast` 例外；旧独立巨潮 PDF／历史股本链不因此自动接入公共调度。
- 指数估值采集另有用户于2026-10-15明确授权的提速策略：只用于指数采集任务；跨提供方独立并行，中证和申万同源最多2个HTTP请求实际在途。用户于2026-10-16因Legu出现429将该来源降为单并发：指数Legu工作项串行，共享调度也限制同源最多1个实际请求。2026-10-17用户将指数Legu请求完成后的等待改为3—7秒，中证和申万仍为2—5秒；滚动60秒最多30次，每完成20次额外休息10秒。所有指数请求继续通过公共 `RequestCollector` 与 `collection_provider_state`，共享真实提供方预算、跨进程OS槽位、拒绝停止及冷却；不能拆来源标识。中证独立代码、申万一级/二级为并行工作单元；申万两级分别按月份倒序推进，分页在月份×层级任务内串行且完整校验后发布。普通调用仍独占提供方槽位；个股、cninfo及其他公共采集策略不变。实施及验证见[指数估值采集](../index-valuation-collection.md)。
- 行业全市场四表与季度交易快照另有用户于2026-10-15明确授权的东财策略：二者使用真实来源 `eastmoney` 和公共 `RequestCollector`，完成后等待2—5秒，滚动60秒最多30次，每完成20次额外休息15秒；拒绝、预算、冷却、恢复及个股共享规则不变。只有日常全市场财务按钮通过 `collect_public(..., parallel_interfaces=True)` 启用最多两个独立Session／接口并行，四表各接口内分页顺序执行，全部通过校验后统一事务发布。`collect_public`默认仍串行，所以手动 `market_financial_backfill` 历史财务不因本次授权自动启用接口并发；它继续使用原公共保守策略。季度 `collect_day` 快照仍单并发、分页串行，复用该入口的历史快照命令使用相同的行业快照等待策略，但不会自动启动。个股 `stock_fast` 继续跳过完成间隔、窗口及额外休息，仅等真实占用槽位并共享已发送预算／拒绝冷却；指数10秒额外休息、CNINFO和其他来源不变。实施及验证见[全市场财务来源](../data-sources/market-financial-statements.md)。
- 个股批次 scope 写明 `evidence_mode=metadata_only`。每个请求和重试登记脱敏参数、提供方、状态、HTTP 码、解析状态及取得时间；原文路径、压缩方式、哈希和字节数为空。响应只在内存交给既有解析器，不落临时文件、响应片段、BLOB 或 ZIP。此记录不能被 `read_source` 或 `reusable_source` 当成可重放缓存。
- 只有领域校验结束才将请求解析状态标记完成；解析失败、请求失败及无响应需保留各自状态。请求状态／batch 完成只描述执行，不代表全覆盖；业务事实仍沿用领域 sync run 和既有事实表。
- 页面先展示现有缓存；个股同源请求由锁串行执行，但不因公共预算间隔等待。自动失败十分钟内不重复自动请求，手动刷新可重试但不绕过来源冷却。重启恢复关闭关联 stock batch，不影响其他领域批次。
- 详细来源与频率见[个股采集说明](../stock-collection.md)。
