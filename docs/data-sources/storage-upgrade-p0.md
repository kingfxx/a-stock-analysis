验证日期：2026-09-30。执行时 Python 3.10.0，SQLite 3.35.5。

## 基线

开始实施前运行当前全部测试：**163 passed**，包含 Node.js 图表轴、悬停与后台加载回归。保留现有未提交筹码功能，不回退到 Git HEAD。

只读盘点了 6 份已有业务 JSON：601919 的财务、估值，以及 600887/601919 的融资和股东记录。记录了文件哈希、大小、结构口径及记录数。验证脚本执行前后再次比较盘点结果，确认未修改缓存。

完整观察结果和各来源代表记录保存在 [storage-upgrade-p0-samples.json](storage-upgrade-p0-samples.json)。这是公开来源的实验样本，不是生产缓存，也不会被程序自动导入数据库。

## 融资日期过滤

| 股票 | 完整历史条数 | 最后数据日前回看 30 个自然日的条数 | 窗口缺少已知日期 | 核心字段变化 |
| --- | ---: | ---: | ---: | ---: |
| 601919 | 3610 | 21 | 0 | 0 |
| 600887 | 3588 | 21 | 0 | 0 |
| 000001 | 3994 | 21 | 0 | 0 |

完整历史按每页 500 条拉取，三个窗口均为一页。过滤使用 `SCODE` 和 `DATE` 的上下界；不仅检查返回条数，也检查股票、日期范围及与完整响应的已知日期/核心字段一致性。完整记录保留包括 `RQMCL` 在内的来源额外字段。

结论：此时接口支持按日期缩小请求，可用于 P2 增量更新。不能推断 30 天之外永远没有修订；仍需周期核对。P2 还需要把范围过滤接入生产适配器，并执行历史保留、字段缺失和 UPSERT 策略。

## 前复权结束日期与重叠窗口

对三个股票分别获取 640 条前复权日价格，再以前一个窗口内较早交易日为结束日期获取另一个 640 条窗口。每个股票有 **441 个同日期重叠记录，收盘价差异均为 0**。比较使用来源收盘价规范化后的十进制表示，不比较不同日期。

结论：观察到的不同结束日期请求在这些重叠日期上保持同一价格基准，支持继续研发。当前生产日价格分页采用不重叠的向前翻页，本次实验特意制造重叠；两者不能混称为已经验证完整生产分页。

这项实验尚未证明：全部上市历史每页都使用一致基准、全部 OHLC 字段保持一致、除权发生期间源响应不会改变。P3 发布共享价格服务前，仍需实际完整分页的重叠校验、覆盖检查、除权样本与 20 个已有交易日更新场景。当前日价解析只输出日期与收盘价，P3 保存完整来源行情时还需扩展来源契约。

- 600887 和 000001 的两个来源最近统计日一致，最近人数一致；F10 同时返回 `HOLDER_TOTAL_NUM` 和 `HOLDER_A_NUM`。这只能说明该样本对应关系，不能作为所有股票的通用合并规则。
- 601919 的 F10 最近统计日为 2026-06-30，`HOLDER_TOTAL_NUM` 为 430616；明细源最近记录为 2017-05-16，`HOLDER_NUM` 为 326080。明细源不能提供该股票近期覆盖。
- 601919 样本没有足够字段证明 F10 总人数等价于 A 股人数；记录来源、统计日、公告日和未知口径，不能把明细补充记录与 F10 直接视为同一统计序列。

P3 再决定具体来源优先级和可比序列选择；本次没有改变现有图表的合并行为。

## SQLite 运行时

实际运行时 SQLite 3.35.5 不在本次认可的 WAL-reset 修复范围内。P1 自动选择 DELETE rollback journal，保持 Python 3.10 兼容；不更换系统运行时或 DLL。支持开启 WAL 的版本检查按官方修复版本及回移分支执行。[SQLite 官方说明](https://www.sqlite.org/wal.html#walreset)

WAL 的真实多线程读写和恢复验收，需要在包含修复的 SQLite 运行时另行执行。本机已经验证版本选择规则和 DELETE 模式下的事务、并发、备份及恢复，不能把规则单测写成已经做过真实 WAL 并发测试。

## 复现

在仓库根目录执行：

```powershell
python -m experiments.source_probe.storage_upgrade_probe --output data/verification/storage-upgrade-probe.json
```

脚本只发出读取请求，默认验证 601919、600887、000001，并检查已有 JSON 未变化。本次共 39 次公开来源请求。默认输出路径是跟踪的实验样本；复查时建议显式使用上面的临时输出路径，避免覆盖已记录基线。错误记录在输出中，不能把存在 `error` 的股票判定为验证通过。

离线回归读取已保存的样本，不依赖后续网络和源数据变化：

```powershell
python -m pytest tests/test_storage_source_contracts.py -q
```
