# 投资 checklist

独立联网结论表见 [经营判断说明](business-judgment.md)。两者共用 AI 设置，历史按结果版本分别读取，经营判断不启动完整研报技能。

页面现已启用 18 项定性 checklist，每项一句至两句。旧 AI 研判代码与历史数据保留，页面不启用；原使用说明见 [旧研判说明](ai-stock-assessment-legacy.md)。

## 使用

1. 在股票页面打开 Checklist。查看页面、历史与 AI 设置均不会自动调用模型。
2. 界面显示本地年报、中报的报告期、版本、解析状态和来源公告。点击“准备财报资料”：资料齐全且未落后于本地财务期时复用；未下载或报告期落后时从巨潮补齐最新完整年报和中报。新一期发布后也可主动点击“刷新财报版本”。标题支持“全文”“（全文）”和修订版，排除摘要及相关说明公告。
3. AI 设置沿用现有 ChatGPT 登录授权和模型选择；资料更新结束后，明确点击“生成 checklist”才使用额度。
4. 结论按 18 项展示，展开依据可见生成时数据、公告地址及 PDF 页码；缺失项标记待补。资料变化后可重新生成，旧版本保留。
5. 历史支持选择、批量删除和最新版本回退；删除只移除任务与无引用快照，不删除可复用财报。

## 存储及复用

- checklist 仍保存在 SQLite 的 `ai_analysis_runs` 和 `ai_analysis_snapshots`，版本 `stock_checklist_output_v1`。
- 正式原件：`data/company_reports/<交易所代码>/<报告期>/v1/report.pdf`，不增加 annual 子目录。
- 逐页文本：同版本目录 `parsed/pdfplumber_pages_v1/pages.jsonl`；主题原文、PDF 页码和提取版本索引位于三张 `company_report_*` 表。
- 财务取数 gjzb 同期同口径优先，三表补齐；加权 ROE 与既有 TTM 简化估算分别标注。估值复用十年历史分位，分红按归属年度已实施事件汇总，筹码用最近三期同口径股东和一年周度融资。
- 规则提取只整理原文，不自动进行 OCR；财报中的“其他地区”不能直接当海外，行业景气按报告期解释。模型不得用记忆补齐这些缺失。
- 正常生成仅一次模型调用；PDF 相同则复用缓存，不每次重解析。首次解析需下载和本地文本提取，刷新资料与模型生成分开触发。

## 导入已有 PDF

```powershell
python -m quarterly_dashboard.company_report_service --code 600887 --period 2025-12-31 --file <PDF路径> --url <正式来源URL> --published-on 2026-04-30
```

## 备份和恢复

既有 SQLite 日备份不包含文件系统 PDF。需要完整迁移时使用：

```powershell
python -m quarterly_dashboard.report_backup --output E:\backup\investment-full.zip
python -m quarterly_dashboard.report_backup --restore E:\backup\investment-full.zip --output E:\backup\investment-restored
```

备份仅包含数据库、已登记财报原件及必要解析文件和 SHA256 清单，不含 AI 凭据。备份文件和恢复目录必须不存在；恢复前验证路径与全部文件哈希，恢复后核验数据库。恢复资料位于新目录，接管日常库属于独立维护操作。

财报同一期文件按 `v1、v2…` 编号，完整 SHA256 仍登记数据库和 manifest 用于去重与校验；版本编号不会因删除而重排。旧哈希目录迁移后，历史快照原路径可通过内容哈希解析到当前路径，不改写历史报告。

生成完成后，页面摘要、正文和历史记录显示生成耗时，按任务 started_at 到 completed_at 计算，包含模型请求及输出核对，不包含排队和此前财报准备。已有历史记录有完整时间戳时同样显示。


### 四项数字摘要增强

当前提示词为 `stock_checklist_prompt_v11`。核心产品附收入、毛利与净利表格，地区收入保留任意原始地区名称，年报与中报分别列示。新生成的数字通过独立 `tables` 字段进入 JSON，包含标准报告期、分类、指标、单位、金额、占比、分母与来源编号，发布前验证结构及引用；程序据明确分母补算缺失占比并标注计算。旧文字记录保留兼容显示转换。生命周期与竞争格局规则保留，核实资料默认折叠。详细协议见 `docs/checklist-prompts.md`。

财报摘取升级为 `checklist_topics_v8`，复用已有PDF全文缓存；明确的分部收益和中国大陆内外对外交易收入表校验合计后缓存 `business_metrics`。不支持的表格版式继续保留原文，不猜口径或比例。仅准备资料不调用模型；历史checklist保持原样，重新生成使用新规则。


主营业务分行业/分产品表也提取收入占比与毛利贡献，保留内部抵销，数字来自本地程序校验。产品项包含最新年报收入构成；已有合并业务分部利润或主营业务毛利时，不能用可能相互包含的子公司利润替代。


分行业、分产品同时披露时优先展示分产品构成，不重复相加。没有显式合计的表，仅在两套分类的收入、成本合计分别一致时使用计算合计；分母仍为主营业务合计。产品列表不完整或两套分类不一致时不猜占比，保留原文供核对。


核心产品项的数字摘要在页面按期间显示为表格（产品/业务、收入或毛利金额、占比/说明），定性正文保留在上方。现有“期间＋产品 — 金额 — 占比”历史文字仅在显示层转换，保存的报告不改写、不调用AI；不能识别的格式保留原文。单位、口径和限制保留，窄屏表格可横向滚动，核实资料仍默认折叠。


分部净利润表有明确列名和正合计时，按完整金额核对并计算贡献占比，保留亏损和抵销；区分分部净利润与归母净利润。表中未重复币种但报告明确声明“本财务报表以人民币列示”时，使用该声明并记录页码；显式美元等表不沿用人民币声明。展示兼容“2026年1-6月”和“金额（占比）”格式，历史报告数字仍保留原结果，新生成采用校验后的比例。


历史数字表格匹配到生成时快照的同期间 `business_metrics` 时，优先使用该快照的校验金额、占比和口径，补入对应证据编号；金额按数量级显示亿元/万元/元，小额抵销不以亿元四舍五入丢失。缺失占比但已有适用金额和分母时可在显示层计算并标注，不需要重新调用模型；缺失金额不使用当前数据回填历史。新生成的独立表字段按原单位展示，缺值保留null。


中国电信等正文收入构成：仅在明确组成项定义、人民币金额及合计校验成立时计算主营收入占比。保留取整近似及原披露比例差异；天翼云等另口径规模在说明中列示，不加入闭合收入构成。收入表头依据收入口径，不明确时显示金额；已有收入、成本则计算毛利，不能混称净利润。


估值项按本次生成快照由本地程序生成，分位单位明确为百分数（0–100）：0.8 表示 0.8%，不乘以100。高低位分档与企业经营趋势页一致，PE/PB 分别显示实际观测日；缺少适用正值或样本时留待补充，稀疏样本标记资料有限。已有 checklist 读取时也按其原快照修正估值项展示，不使用最新数据替代、不改写保存的输入及结果、不调用模型。历史位置不代表内在价值。

产品收入表可摘录同表成本及毛利率；按收入减成本计算毛利，只有毛利率时标为估算。分类金额齐全而原比例缺失时，按所列产品各指标的合计补算占比并注明范围。历史展示只使用原快照的证据，不改保存结果、不调用模型。
