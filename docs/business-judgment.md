# 经营判断

股票页的「经营判断」是独立轻量模块，共用 AI 设置的 ChatGPT 登录、额度授权和所选模型。它不启动完整研报技能，也不要求先生成 Checklist 或准备财报。

## 输出

先展示三张前置分析表：PESTEL 六项（政策、经济、社会需求、技术、环境、法律），波特五力五项，以及按公司业务选取的内部资源与公司能力 5–7 项。每行包含分类、明确判断、依据与分析、对公司的影响及来源。随后展示 5–7 个核心问题的最终结论表「核心问题 / 明确判断 / 权衡理由 / 对整体判断的影响」，附主判断、2–3 个改变条件、缺口和来源。结论行通过 framework_refs 关联前置分析项，可点击回看。主判断要求说明决定性证据，不机械平衡正反；证据不足明确标记，不产生评分、目标价或买卖建议。

经营判断抽屉采用浅绿背景、深色正文、蓝色来源链接，样式只作用于该抽屉。前三表按参考格式组织为「维度 / 可核查的依据 / 分析判断 / 风险或反证验证点」；内部能力第三列为「优势如何转化为经营结果」。来源链接直接显示在依据列，同时保留可读详情展开。prompt_v4 将 analysis 限定为事实依据，judgment 为主判断、impact 为作用机制，新增必需 risk_verification 字段描述风险、限制、反证及可观察验证点。旧报告可直接使用当前样式和列顺序；未保存的反证/验证点明确提示，不编造，需显式重新生成补齐。

当前v15每次生成分为一次联网检索请求和一次严格结构化分析请求，完成后统一保存全部表格。旧v14及以前为单次模型请求。business_judgment_v1保存协议不变，旧历史保留原样。新校验要求固定维度完整、能力项不重复、所有表来源有效、结论引用的前置项存在。格式校验不能保证事实与推论正确。

本地依据展开使用中文指标名、金额自动换算为万元/亿元、百分比、报告期、来源及口径说明；同比单独注明比较基期，零值保留，缺值显示资料缺失。财报片段展示页码与原文，不直接展示 raw JSON。此渲染也适用于旧历史，不调用模型或改写存储。

## 生成与联网

prompt_v6保留PESTEL按外部因素的原因归类：经济E分析全球/区域增长、贸易、库存、通胀、利率、汇率等宏观因素如何传导到公司；公司营收/利润仅是影响结果的佐证。社会S分析人口、生活方式、消费习惯与服务需求的结构性变化如何影响行业，不以运输总需求预测、补库存或运价替代社会因素。跨境购物、可靠交付等只是待来源核实的分析方向，不能自动认定增长事实。两者可交叉但按主要驱动归类；无适用社会证据明确标缺口，不强行凑表。

- 查看当前结果、历史、AI 设置不会自动生成。只有「生成经营判断 / 重新生成」发起检索、分析两次模型请求；服务端不自动重试或因格式错误追加修复请求。Checklist单次模型流程不变。
- 使用 Responses `web_search`，要求执行工具，并请求 `web_search_call.action.sources`。ChatGPT 计划是否支持由模型、账号和工作区策略决定；不支持或没有完成检索时失败，不回退为模型记忆。官方限制见 [ChatGPT plan preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。
- 必须返回至少 3 个不同来源；结果的 URL 必须出现在本次实际检索返回的来源或 URL citation 中。优先官方资料，同时允许机构研究、行业资料和可靠新闻。过滤本地/私有地址，不把网址真实性等同于事实真实性。日期未知留空，不允许晚于资料截止日期。
- v15检索完成后，后台从实际工具来源、引用注释及输入中的不可变财报生成冻结source_catalog。模型sources只输出id和excerpt，Schema枚举限定编号；后台绑定URL、标题与已知日期。没有真实标题时显示“未返回原文标题”和网站/文件名，不让分析模型编标题；未知日期为null。旧版URL校验规则继续保留，不迁移或改写旧报告。
- 分析阶段采用Responses text.format=json_schema、strict=true，所有对象禁止额外字段；引用编号、代码、日期、维度和长度受Schema约束，后台再次检查同一合同及事实来源。结论关联前置表用分组+行号指针，后台转换为可点击分类名。事实摘要仍由模型提取，未逐字独立核验。严格模式失败不退回自由输出，不添加修复调用。官方参数见[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)。
- 行业地位每行必须采用单一指标、时期和主体。若模型返回重复排名，后台将该行排名、份额及集中度全部标为未取得，并显示口径冲突提示；原始数字保留在“查看原输出排行（未采用）”中供核对，不作为有效行业排行。其余结构和来源合格的报告可保存，相关文字判断仍明确待核实。
- 本地只读取股票身份和最近一次成功 Checklist 输入中有限的经营证据（最多 24 项、约 1.6 万字符），不重新计算全部指标，不复用历史 AI 结论作为事实。本地资料可能陈旧，提示模型联网核对。没有 Checklist 仍可联网生成。
- 两阶段各自总超时480秒，单次网络读取超时60秒；不承诺固定耗时。页面展示完整生成时间。全局仍最多一个运行任务和一个等待任务，同一股票不能同时生成不同类型分析。
- 生成过程每秒读秒；排队以创建时间显示等待秒数，生成/校验以开始时间显示已用秒数。关闭或查看历史停止前端计时，再打开根据保存时间续计，不增加请求额度；完成展示总耗时。

## 保存与历史

复用 `ai_analysis_runs` 和 `ai_analysis_snapshots`，无新增表或迁移。`output_schema_version=business_judgment_v1` 与 Checklist 独立筛选；输入 `business_judgment_input_v1`、采集规则 `business_judgment_capture_v2`、提示词 `business_judgment_prompt_v15` 分别记录版本。历史的 prompt_v1/v2/v3/v4/v5 保留原样。

输入快照保存股票、本地证据、资料截止日期和引用 Checklist 的快照哈希。结果保存结论表、条件、缺口、来源标题/URL/发布日期/事实摘要以及真实检索 URL 清单和接收时间；任务保存生成时间、模型及用量。v15另保存冻结来源清单、严格合同哈希、两阶段响应编号及各阶段用量；不保存完整网页或另下载PDF，已有完整资料备份包含这些SQLite记录。

同日、相同证据、模型、提示词的普通生成可复用成功任务；「重新生成」明确强制联网并新增历史。跨日提示资料日期已变化，即使本地证据相同也不会冒充新检索。查看历史只读取保存内容，失败不覆盖上次成功结果。删除只删除该类型的所选任务与无引用输入快照，不删除 Checklist、正式财报或解析缓存。

接口为 `/api/business-judgment`、`/history`、`/runs/<id>`，以及显式 POST 生成、取消和 `/history/delete`。写操作沿用 Host、Origin、本地会话防护。账号断开取消两种任务；队列按已保存类型选择正确校验器。

自动回归使用隔离数据库和模拟模型。真实验收仅在用户授权后使用日常8765后台及所选模型；每家公司记录真实任务编号、来源绑定、严格Schema参数和页面检查。工具为data/verification/tools/business_batch_acceptance.py，已完成公司默认不重新调用，显式--retry-failed才重新测试失败公司并保存prior_attempts；不作为业务自动重试机制。
