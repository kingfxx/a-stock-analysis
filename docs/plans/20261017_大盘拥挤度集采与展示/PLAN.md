# 大盘拥挤度集采与指数页展示

状态：2026-10-17已实现并上线主机8765，schema v36；已完成初次导入并启用每日18:00 HTML检查。实现说明见docs/market-congestion-collection.md，验收记录见本目录PROGRESS.md。

## 1. 用户确认的流程

首次同时获取API历史与HTML近期表格并写入数据库；初始化完成后，手动更新和系统每日检查都只获取HTML，解析整个表格、补存缺少日期。API不再进入日常更新或自动补缺队列。中间20个日期的缺口暂时保留，等待用户另行处理。按用户最新要求，首次历史初始化保留来源响应归档，后续HTML更新采用metadata_only，不保存响应文件。

不采集全市场行情自行计算、不自动登录或购买会员、不绕过权限。保留Windows主机执行和共享Legu限速。定时检查由项目后台承担，不依赖Codex聊天唤醒。

## 3. 首次初始化

1. 用户点击“获取／恢复历史”，同时建立API历史、HTML近期两项工作单元。复用已归档且双哈希、解析通过的样本可完成历史回放，必须保留原取得时间及reused_source_id，不冒充新请求。HTML不够新时再执行当日一次HTML更新。
2. 无可复用来源时，先通过HTML获得Session Cookie/CSRF并解析表格，再调用一次API；复用同一Session，token按Asia/Shanghai日期生成。API没有已证实的范围参数，只请求一份完整响应，不逐年/月/日重复取数。
3. 网页与API各自建立公共batch，独立校验和发布；网页成功、API失败可保留网页数据，初始化状态仍提示历史步骤待恢复。只有首次API成功校验入库后才认定历史初始化完成；后续普通更新不暗中重试未完成初始化。
4. 保存API全部返回日期，有值则为有效观测，仅date则为来源缺值观测NULL；保留HTML表格全部实际行。不能把API中没有值的日期记作有效覆盖。
5. 结构、字段和整段校验通过后短事务发布；解析失败不发布局部事实，保留原文供修复后回放。恢复仅重做未完成步骤，跳过相同范围/定义且已验证的步骤；已初始化后不反复调用API。将来重新获取API或补那20日需另行明确启动，不属于日常更新。

## 4. 日常更新：只取HTML

### 一次检查的行为

- 请求HTML一次，解析表格内所有返回日期，不能只取第一行或只看最大日期。一次检查可以补上窗口内多日缺失。
- 日期与值在本地已有且相同则不重复写事实、不增加版本、不改原事实出处；仍保留本次请求元数据和检查时间，不保存响应文件。
- 本地无该通道记录则新增；已有NULL变有效值则补入；同通道同日期数值改变则保留旧版本并新增修订。整张近期表格很小，每次检查全部行，内部修订不要求额外网络核对。
- API占位行不改写为HTML来源值。按日期查看时允许知道该日已存在HTML有效观察，不能把它统计成API成功。
- 来源删行、窗口缩短或有值变空不删除原有效历史；记录异常，未核实撤回前不覆盖成NULL。表格缺列、日期重复冲突、数值无效或摘要矛盾则保留原有数据并显示校验错误。
- 表格正常但没有新日期表示“检查成功、无新增”，不是失败；分别记录最近检查时间、来源最新日期及有效值日期。
- 表格失败时JSON-LD只能说明最新摘要仍可读，不能把一个摘要当作整个表格已更新或补出其余日期。首版不新增摘要事实序列。
- 未采集日期仍在表格窗口内时自动补回；停用超过窗口的缺口保留，绝不回退到API或自算。中间已有20日缺口单独标记“暂待补充”，不触发反复请求。

### 每日调度（已获用户授权的设计）

默认北京时间每天18:00进行一次后台检查；这是收盘后的实现默认值，不宣称Legu固定于该时间更新。到时只获取HTML，不调用API或额外交易日历接口。页面浏览和普通网页刷新仍只读数据库。

- 调度器在8765宿主机后台运行，使用Asia/Shanghai，不依赖浏览器打开。后台未运行时不保证准点执行；当日18:00后启动且当日尚无定时检查记录，补执行一次。次日启动只做当前到期检查，读取近期表格补窗口内日期，不为错过的每天各发一次请求。
- 采用当前后台生命周期内的轻量调度循环；不得凭搜索到的函数名假定已有每日调度器可用。退出、恢复数据库及服务关闭时停止调度，不能持有失效数据库连接。
- 每自然日最多一次定时检查，周末/节假日也可运行一次，来源无新增就正常结束。用户手动更新独立记为manual，仍受同源预算；当日已有成功的手动HTML检查覆盖本次调度候选日时可复用该结果，避免重复请求。
- 日运行身份含dataset、北京时间日期、trigger=scheduled和解析/定义版本，使用数据库短事务及现有operation互斥/OS锁原子核对与登记，跨进程/重启防重复，不能只靠内存last_run。
- 沿用index_collection_operations；scope保存scheduled_date，batch/source保存实际时间与trigger。运行前如已有指数operation运行，调度等待当天下一次空闲检查点，不抢占、不创建第二个并发operation；这不算已经请求过来源。当日实际启动过的定时任务即使失败/拒绝/中断也不自动重复运行，次日再检查；可由用户手动处理。
- 冷却中到期则登记“本日因来源冷却跳过”，不访问来源、不在冷却结束时自动反复探测。普通失败本轮仅一次尝试，保护每天一次检查意图；下一日或用户手动更新可再次尝试。403/429等按公共规则停止并登记冷却。
- 配置支持开启/暂停和每日时间，初次初始化完成后启用本指标的每日检查；这是本次用户授权的范围，不扩大到其他指数/来源。初始化未完成时提示先完成历史初始化，不由调度器隐式请求API。
- 日程配置与当日执行标记须持久化。优先复用经核实适用的现有配置表；如没有可用结构，新增一张小型`collection_schedules`表（见存储章节），不拿provider预算表或篡改旧事实充当配置。

## 5. 任务与公共采集接入

复用index_collection_operations、collection_batches、collection_sources、collection_provider_state和RequestCollector，不建立拥挤度专用operation/原文体系。

现有POST入口增加datasets=[market_congestion]、providers=[legu]的明确选择；省略datasets的原指数按钮行为不变。首版每个operation只执行原估值集合或拥挤度集合，不接受任意混合组合。

模式：full表示首次历史获取/恢复；incremental表示只取HTML的日常检查；review如保留也只能重读HTML近期表格，不调用API。拥挤度分发先于原估值日期计划，不套十年裁剪、月频、强制排除今日、联网日历或估值分位算法。定时触发同一增量入口并登记trigger=scheduled。

提供方始终legu；HTML、首次API、Cookie及重试共用预算。默认并发1，完成后间隔10—15秒，60秒最多5次，每20次休息60—120秒。不继承仅对指数估值授权的3—7秒例外。日常HTML检查使用max_attempts=1；首次初始化的恢复/重试遵循公共规则。真实403/429立即停源冷却至少一小时；恢复验证继续使用公共探测机制。

所有联网执行在Windows主机端。网络请求、限速等待和初始化原文归档不持有SQLite写事务。初始化先归档双哈希原文再发布校验事实；后续HTML更新按用户授权使用下面的metadata_only策略。沙箱网络错误不能被当成来源拒绝。

### 后续HTML更新不落响应文件（用户授权例外）

- 适用初始化完成后的每日定时、手动“立即更新”及HTML近期核对；首次API/HTML初始化仍保留归档。已存在的正式来源文件不删除，不将此例外扩大到指数估值或其他采集器。
- RequestCollector显式传入`evidence_mode='metadata_only'`，batch.scope记录相同证据策略。提供方仍为legu，预算、锁、拒绝停止、冷却、请求和重试记录全部继续执行，不因为不落文件而绕过公共采集。
- 每次实际请求登记脱敏URL/参数、batch、提供方、请求/解析状态、HTTP码、真实取得时间及简短错误。原文路径、压缩方式、哈希、原文/存储字节数为空，不虚构空文件哈希。
- HTML仅在内存中解析；禁止改存为临时HTML、压缩文件、截图、响应片段日志、数据库BLOB或结果JSON中的整页原文。不为每次日更另存一份独立报告文件，检查结果/计数保存在既有operation和batch结果中；例行日志只记简短状态，不复制正文。若既有operation结束自动写报告文件，须按本任务与evidence_mode定向跳过，不能影响其他采集报告。
- 校验完成才标记解析成功并发布结构化观察及修订，source_id/batch_id外键继续有效。解析失败记录错误并保留旧事实，不能以metadata_only为由跳过校验。
- 明确能力边界：后续来源只有请求元数据及已入库结构化值，无法从日更记录离线重放/重新解析原HTML，也不能执行原文双哈希核对。界面详情/原文入口识别无文件状态，显示“仅请求记录，无响应文件”；缓存复用、历史回放不能把它当可重放来源。

## 6. 存储与追溯

拟新增一张市场指标观察表，不建立`market_indicator_series`，不使用series_id。另按实际配置结构决定是否需要一张调度配置表；实施时使用最新schema迁移版本。

| 表 | 用途与主要字段 |
|---|---|
| market_indicator_observations | id；indicator_key、scope_key、provider、channel、frequency、definition_version；observation_date；value可空、value_status=observed/source_missing、precision_digits；close、top5_amount_yi、total_amount_yi均可空；version/is_latest/content_hash；source_id/batch_id、obtained_at/updated_at、withdrawal_reason；身份直接保存在观察行，来源/batch复合外键 |
| collection_schedules（仅无可复用配置表时） | task_key唯一、enabled、timezone、local_time、updated_at；仅保存调度配置，执行历史仍用已有operation/batch，禁止再造run表 |

序列身份由`indicator_key + scope_key + provider + channel + frequency + definition_version`组成，字段均非空，避免NULL绕过唯一约束。本期取`ashares_congestion / all_a / legu / api_history或html_recent_table / daily / v1`。按身份加observation_date和version建立版本唯一约束；按身份加observation_date建立is_latest=1的部分唯一索引，保证同日只存在一个当前版本。查询、修订和幂等判断均包含完整身份，不能只按日期或指标名更新。provider必须与source真实提供方一致，source与batch配对受复合外键约束。

本期value=0有效，observed要求有限0—1；缺值为NULL。API与HTML的来源和修订独立，精度保留；同日期冲突同时保留并提示，不静默覆盖。图表可以在同一时间轴看两条序列，但不冒充单一API连续历史。

公式、单位、有效范围、统计对象、来源字段和缺值规则放在随Git管理的代码定义注册表与指标文档，不建立数据库定义/序列表，也不在每个观察行重复存definition_json。解析/发布必须查到明确的身份及定义版本；未知定义拒绝发布。现有版本含义不可原地修改，定义变化新增版本，事实hash纳入定义身份及版本。未来新增创业板、行业或其他拥挤度指标时，注册新的indicator_key/scope_key及相应定义即可共用此表；不同公式、频率或单位不混读，不把本期0—1校验硬编码为全表所有未来指标的约束，按定义执行校验与显示格式。此设计只预留扩展字段，不在本期采集其他指标。

按用户确认，收盘价、前5%成交额及全A成交额与拥挤度同一观察行结构化入库，不再仅留原文：

| 字段 | 单位 | API映射 | HTML映射 |
|---|---|---|---|
| close | 指数点数 | close | 收盘价 |
| top5_amount_yi | 亿元 | top5AmountYi | 成交额排名前5%的个股的成交额（亿元） |
| total_amount_yi | 亿元 | totalAmountYi | 全部A股成交额（亿元） |

这些字段沿用该行相同日期、通道、来源证据和修订版本；不从其他通道或邻日填充。字段缺失保持NULL，包括API只有date的受限行；不能为金额缺失补0。金额有效0保留，有限非负；close有值时要求有限正数。字段存在但无效则校验失败，不静默转NULL。金额比例只做允许来源四舍五入误差的核对，total_amount_yi为0或有金额缺值时不作除法，仍以来源拥挤度作为value，不自行重算替换。

内容hash包含value、close、两类金额及状态/定义身份等业务字段；任一已存字段真实改变或从NULL补为有效值均产生该观察行新版本，重复返回不改原出处。任一已发布有效字段变空，保留原值并记录来源异常，核实撤回前不覆盖。value_status及有效日期计数只描述拥挤度；另按这三个字段统计有效数/缺值，不能以金额或close有值冒充拥挤度有值。

收盘价对应的基准指数身份在定义中明确登记；当前页面标题只写收盘价，未核实前标识来源未明确，不自动认定它就是某个宽基指数，也不据此填充图中所选点位。未来扩展指标若不提供这些字段则留NULL；不同含义/排名阈值不能硬套top5_amount_yi，须另行登记适用定义。本期不新增点位表或金额表，单张观察表保存这些配套字段。

事实真实取得时间沿用source，回放不改；发布/修订时间另记updated_at。初始化事实可追溯已归档原文；后续metadata_only事实仅追溯请求元数据与业务修订，不宣称原始响应可重放。检查时间和执行状态来自公共batch/source，配置更新时间不能替代数据更新时间。

同步SQLite说明、维护页DESCRIPTIONS用途/分类与TIME_COLUMNS/PARENT_TIMES依据；新表空值/空表不显示虚构时间。指标表分类“市场指标”，调度配置归“运行与配置”。新设计细节写入docs/market-congestion-collection.md，指数文档提供链接。迁移与备份同时处理collection_sources文件及哈希。

以上来源文件迁移/双哈希规则仅对实际归档的初始化及既有文件适用；metadata_only记录无文件为正常状态，不误报文件丢失。实现时在采集说明及SQLite文档同步登记本指标后续更新的用户授权例外。

### 宽基指数点位叠加（用户新增要求）

- 拥挤度和指数点位始终在同一图表、同一日期横轴展示。左轴为拥挤度百分数，右轴为所选指数的实际收盘点位；不做归一化收益率替代点位。指数线与两个拥挤度通道有清楚的图例和配色。
- 新增“叠加指数”下拉框，默认上证指数（当前稳定身份`cn:000001`）。列表取本地指数目录中全部宽基指数（index_type=broad），不能只列当前已有点位的指数；不包含行业或策略指数。选项按稳定index_code去重，重名时附代码，不把不同来源作为重复指数。
- 与上方估值区块的指数选择保持独立。切换下拉框只更换右轴点位线，不改变大盘拥挤度本身，不重置所选时间范围，也不请求外部来源。
- 时间范围仅保留“5年／10年／全部”，默认5年。以北京时间当前日期向前滚动5/10年，日历周年计算并正确处理闰日；全部显示本地拥挤度最早已记录日期至今日。两条指标和所选点位使用相同日期窗口，不按两个来源日期交集裁掉拥挤度历史。可用数据不足5/10年时显示实际有值区间，不补齐。
