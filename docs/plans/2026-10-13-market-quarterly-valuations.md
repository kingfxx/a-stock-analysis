# 全市场交易日快照全字段采集方案（当前采集季度末）

状态：已实施并执行2015Q1—2026Q3共47期核验。2018Q1—2026Q3的35期有数据，2015—2017的12期明确为空；实际数据覆盖为partial。结果及行为以来源说明和验收报告为准。接口字段依据本次 `RPT_VALUEANALYSIS_DET`、`columns=ALL`、2025-12-31、第一页三行实测；成功返回22列，不代表已验证所有历史期间的字段覆盖。

2026-10-14 补充：2015—2017 的12期已按独立多源合成口径发布35,987条历史快照，详见 [历史快照缓存与补齐计划](2026-10-14-market-trade-snapshot-composite-backfill.md)。五项估值留空，后续按完整版本单独补字段；下文东财来源身份及原空期证据继续保留，合成发布不冒充东财原值。

## 1. 范围与命名

新增一张业务表 **`market_trade_snapshot`**，用途说明为：**全市场交易日快照，保存未复权收盘价、涨跌幅、总股本、A股流通股本、总市值、流通市值及估值指标；当前仅采集季度末最后交易日，支持以后扩展全部交易日。** 沿用全市场来源层 `market_` 前缀，按用户指定使用单数 `snapshot`。不在表名或事实身份中固定季度频率；来源数据不只服务申万行业，也不能按当前沪深行业名单裁掉来源层记录。

表中每行表示一家公司在一个实际交易日的来源快照。季度末是当前的日期选择策略，不是不同的数据定义。以后扩展日频沿用同一表、字段字典、数据集和修订规则；同日记录不因采集策略不同而重复保存。该接口当前实测没有开高低、成交量和成交额，不将快照描述成完整日线行情。

全字段指该报表实际返回的全部字段，不是东方财富所有数据或财报完整明细。接口名称仍为 `RPT_VALUEANALYSIS_DET`。

新增数据库表仅此一张。**不新增 `market_valuation_batches/sources/operations` 等控制表**，不复制旧 `market_financial_batches/sources` 的模式。公共采集规则优先于尚未统一的旧财务、价格流程。

## 2. 共用控制设施

| 职责 | 复用位置 | 接入方式 |
|---|---|---|
| 启动、互斥、进度、最终结果 | `sw_update_runs`、行业服务现有任务入口 | 保留 `cap_quarter` 日常动作；历史任务复用其控制层，使用明确的新动作值及范围结果，不建新任务表 |
| 日期分段、执行与覆盖状态 | `collection_batches` | 当前每个季度末目标交易日一个batch；`domain=market`、`dataset=market.trade_snapshot`、`source_system=eastmoney`、`frequency=daily`表示源事实的交易日粒度；`scope_json.sampling=quarter_end`表示本次采样策略 |
| 每次请求、失败、重试、缓存复用 | `collection_sources` | 每页/每次尝试一个source；事实同时引用source与batch |
| 限速、同源锁、拒绝及冷却 | `collection_provider_state`、`collection.RequestCollector` | 提供方统一为 `eastmoney`，分页、各主机和接入的其他东财接口共用预算 |
| 原始响应 | `collection.archive_source` | 数据库旁 `collection_sources/eastmoney/market.trade_snapshot/`，gzip原文、双哈希、项目相对路径 |

`operation_id` 使用有命名空间的稳定字符串，例如 `sw_update_runs:<id>`，避免与指数操作ID冲突。批次范围同时登记季度自然末日、实际交易日、市场范围、`columns=ALL`、定义/解析版本；行业名单版本仅用于下游行业覆盖，来源层另声明来源市场范围。

现有 `sw_update_runs` 没有取消字段且状态只有running/complete/failed。若需要页面停止功能，给现有控制层增加 `cancel_requested` 和必要状态支持；如果保持现有状态约束，则取消在其结果中明确标记，公共batch登记cancelled。实现时统一选择一种表达，不隐含已有取消能力。历史命令与日常按钮共用任务互斥，后台重启只标记中断，不自动联网恢复。

公共模块需小幅通用化：

1. `begin_batch` 允许显式传入domain、解析版本、定义版本、名单版本；保留指数调用默认兼容，不能让新数据写成 `index-v2`。
2. `RequestCollector.get` 的冷却恢复目前验证 `payload.data`，须增加可注入的响应健康检查，东财验证 `success/code/result.data`。正常空结果与有效恢复分开处理；恢复仍只允许一次探测，不能为适配接口放宽拒绝保护。
3. 行业市值两个调用点统一改用新的全字段适配器，不继续走 `industry_bulk.RequestPacer`。其他旧东财采集尚未接入，不能宣称它们已共享预算；本次只改造市值路径，后续其他接口应逐步接入公共调度。

## 3. 新数据表字段

所有源字段按小写列名保存，代码全部TEXT以保留前导零。字段字典建议放 `quarterly_dashboard/resources/market_trade_snapshot_fields.json`，登记源名、列名、类型、单位、定义核实状态和空值规则。

| 实测源字段 | 类型 | 保存口径 |
|---|---|---|
| SECURITY_CODE / SECUCODE | TEXT | 六位代码及带交易所后缀代码 |
| SECURITY_NAME_ABBR / ORG_CODE | TEXT | 名称、机构代码 |
| TRADE_MARKET | TEXT | 来源市场代码，未经核实不据此推断交易所 |
| BOARD_CODE / BOARD_NAME / ORIG_BOARD_CODE | TEXT | 来源板块标识、名称及原板块标识，语义未核实则只保存 |
| TOTAL_MARKET_CAP | REAL | 来源总市值，元 |
| NOTLIMITED_MARKETCAP_A | REAL | 来源A股流通市值字段，准确股本范围需补定义证据 |
| CLOSE_PRICE | REAL | 未复权收盘价，元/股；本次已与本地raw/qfq及市值乘积交叉核对 |
| CHANGE_RATE | REAL | 来源涨跌幅；百分数口径在有限样本中核实后登记 |
| TOTAL_SHARES / FREE_SHARES_A | INTEGER | 总股本、来源A股流通股本，股；严格核对单位及整数，非整数或超SQLite整数范围阻止该分段发布，不四舍五入 |
| PE_TTM / PE_LAR / PB_MRQ | REAL | 原值保存；具体利润/净资产期间按来源定义登记 |
| PCF_OCF_LAR / PCF_OCF_TTM / PS_TTM / PEG_CAR | REAL | 原值保存；PEG增长期间及辅助估值定义待核实，不直接挂业务计算 |
| TRADE_DATE | TEXT | 源原始文本放 `source_trade_date`；另存标准化 `trade_date` |

附加本地字段：`id`、`exchange`、标准化 `trade_date`、`version`、`is_latest`、`definition_version`、`batch_id`、`source_id`、`content_hash`、`obtained_at`、`updated_at`。事实不强制保存 `quarter_end`；季度自然末日和目标交易日映射保存在公共批次范围/现有季度名单中，季度读取按映射匹配精确 `trade_date`，不能从稀疏快照最大日期猜季度末。

`exchange` 从经验证的SECUCODE映射sh/sz/bj；未知后缀阻止发布。保留全部已验证A股来源行，包括来源可返回的北交所；本报表没有实测到 `SECURITY_TYPE_CODE`，不能照搬财务接口的A股过滤条件。接入前须用来源目录/证券身份证据确认市场范围，未核实部分明确标记覆盖未知。

历史唯一键建议 `(security_code,exchange,trade_date,definition_version,version)`；同键 `is_latest=1` 部分唯一索引保证一个最新版本。日期查询建立 `(trade_date,is_latest,exchange,security_code)` 索引，逐股历史依靠唯一键索引，不给全部22列建索引。该表来源层限定东财此接口；以后接入其他提供方时需明确独立来源身份，不能把另一提供方作为同系列修订直接覆盖。

`FOREIGN KEY(source_id,batch_id) REFERENCES collection_sources(id,batch_id)` 确保来源属于同一批次，同时外键引用 `collection_batches`。不用行内原始JSON、路径、请求参数、字段清单重复占空间。

有效零/负估值倍数保留，缺失为NULL；不把负PE/PCF丢掉。NaN/Infinity、非法字符串、代码日期错误失败。数值约束按定义，不给全部数值统一加正值约束。来源新增字段先归档、停止发布并提示扩展字典和schema，不静默丢字段；历史缺少已登记列留空并记录结构差异，不冒充全字段覆盖。

同公司、同交易日的指标或定义变化新增修订；无变化事实保持原出处，新请求仍登记公共来源。不同交易日是独立事实，不是同季度事实修订；季度目标交易日纠错须核实映射及旧记录有效性，不自动覆盖日期。名称/板块描述变化不新增指标修订，可更新最新记录描述及真实写入时间，原始历史响应仍可追溯；需保留文本历史时从归档读取。本方案不将描述字段补齐当成来源市场覆盖完整。

## 4. 请求与分段

请求地址：`https://datacenter-web.eastmoney.com/api/data/v1/get`。

```text
reportName=RPT_VALUEANALYSIS_DET
columns=ALL
filter=(TRADE_DATE='目标实际交易日')
sortColumns=SECURITY_CODE
sortTypes=1
pageSize=500
pageNumber=1,2,...
source=WEB
client=WEB
```

按一个日期取全市场分页，一个季度完整页集对应一个提交分段；已授权47期逐期执行，不逐股票请求十年数据。现有5字段请求已使用500行容量；改ALL后仍须有限真实样本核对500行、总数和字段，不仅凭本次3行探测认定完整分页已验证。

以后采全部交易日时使用 `scope_json.sampling=all_trading_days`，仍可按交易日完整分页、逐日校验发布，不需要新建数据表或控制表。任务进度可按月汇总日分段；若来源支持更高效的日期范围查询，另做有限验证后再调整请求方式，不能预设支持。季度完成只能证明那些目标交易日已采，不能证明中间交易日完成；日频恢复按完整交易日集合与成功批次逐日检查，补齐内部缺口，不能只从原季度水位追加尾部。

跨季度/日频任务的批次幂等键包含采样策略和范围，事实去重键不包含采样策略。季度末已有同日完整、同口径、同字段版本的公共来源与已验证页集可复用，必须验证范围和证据并记录复用关系；来源复用时登记当前batch所属source引用，保证组合外键，不把旧batch的source直接挂到新batch事实。未变化事实仍保留原batch/source。同日重新核对发现变化才新增修订。

季度自然末日使用上海日期的已结束季度；实际交易日优先复用经核实的本地日历及已有季度冻结日期。不能用来源第一条观测推断交易日，不把季度末下一交易日或15日内近似行情替代。与现有市值名单日期冲突时停止并报告。2026-10-13运行时，已授权47个已结束季度的范围为2015Q1—2026Q3，最终由明确参数固定，不在恢复中随运行日期移动范围。

每页先归档再解析；验证返回总数/总页数稳定、页长度、跨页证券身份不重复、日期匹配、字段和值合法。所有页通过后短事务发布本季度。`TOTAL_MARKET_CAP ≈ TOTAL_SHARES × CLOSE_PRICE` 沿用现有容差 `max(1元,市值×1e-6)`；字段缺失时标记不可核验，不凭计算补源值。跨市场股本/币种定义尚不适用的对象明确失败或待核对，不能强套公式。流通股本/流通市值乘积关系另验证，未确认不作硬性约束。

默认同源并发1，完成后10秒加0—5秒，60秒最多5次，每20次额外60—120秒。403/429/验证码停止本轮全部东财请求、冷却至少一小时。普通暂时错误最多3次，60/120秒加随机退避。网络和等待不持SQLite写事务。

按近期每期约11—12页估算，47期上限约564次请求（早期公司较少或空期会减少请求）；按当前公共限速理想情况约2—3小时，未包括日历/名单请求、重试和拒绝冷却，仅用于进度预算。

## 5. 增量、恢复和覆盖

支持手动单季、尾部补新、十年首次建档/恢复、指定季度修订复查。常规更新只补已完成水位后新增季度；已最新跳过接口。历史内部缺口显式复查，不能被最新日期掩盖。恢复键包括固定区间、季度、真实交易日、来源市场范围、ALL字段策略、解析/定义版本及下游名单版本。

完整且同口径的成功batch才能跳过；旧 `sw_cap_facts` 有总市值不等于ALL已完成。部分/失败页集保留证据，重新使用缓存时核对请求、双哈希、字段版本与分页总数。不能混合不同采集快照页造成伪完整；总数变化失效整个未发布季度页集，完成季度不重采。来源复用保留原取得时间和关联，不能把复用当新HTTP请求。

`collection_batches.result_json` 登记请求总数、页数、来源行数、验证行数、逐字段有效/NULL数、代码缺口、适用名单和未知范围、已提交及跳过数。执行状态与覆盖状态分开：分页齐不保证各股票/各字段齐，历史名单有效期未核实时覆盖unknown。行业覆盖仍按季度固定名单计算；全市场来源覆盖单独表示，不以当前申万成员数为全市场分母。

## 6. 旧数据和读链路

旧5字段缓存可离线盘点出 `TOTAL_SHARES/CLOSE_PRICE`，但不能补齐其余17列；旧响应不当ALL完成。方案不自动迁移旧公共元数据、不重写旧文件/事实。离线利用旧缓存须独立明确授权和范围，登记真实旧时间或未知、来源复用关系及字段覆盖。

新表发布后，行业读取按季度名单映射的精确交易日，优先使用新表该日最新 `total_market_cap`；没有适用新记录时，可显式使用旧 `sw_cap_facts` 同日期市值并带旧来源标记。以后加入日频数据不改变季度页面日期选择，不将最新日价代替历史季末价。新请求不再重复写旧市值事实、旧市值来源或新的私有batch表。行业汇总可复用既有计算/缓存设施，查询层按新事实批次和旧导入版本共同失效，避免展示未刷新的总额。不能从新表空值静默覆盖旧有效值。

新 `close_price` 为东财来源，与BigQuant `market_quarterly_prices.close` 独立保留。建议后续行业价格入口在东财价格覆盖通过后读新表同日价格，从而减少同季度额外价格请求；不得悄悄覆盖BigQuant历史或合并来源。PB现有“股价/BPS”计算与源 `pb_mrq` 是不同口径，不直接互换；PE/股息率等展示的取数变化另列实施范围并同步指标文档。

旧 `industry_bulk.collect` 混合采集入口已停用并提示新快照/独立财务入口；保留旧解析及离线导入工具，不继续运行旧限速市值请求。既有财务采集控制层保持原入口。日常分类检查和价格补采中未接入公共调度的请求明确登记现状，不能声称全任务所有网络都已改造完成。

## 7. 实施、文档与验收

建议分为公共模块适配→新表/字段字典/独立解析发布→单季度入口→历史恢复→行业读取衔接。本次已授权并启动2015Q1—2026Q3的47期历史回填，未设置自动调度。

新增表迁移先正式SQLite备份，再在隔离库核对schema及维护接口。同步更新 `docs/sqlite-storage.md`、`docs/industry-data-schema.md`、来源说明；在 `maintenance.DESCRIPTIONS` 登记行业数据分类，并使用第1节的交易日快照用途说明，`TIME_COLUMNS` 登记真实 `obtained_at/updated_at`，空表或无时间显示未记录。文档明确当前仅季末采集、其他交易日尚未覆盖，只更新已实现行为。

必要验证：共享调度的东财冷却恢复、跨任务/进程预算；22列类型、零/负值及NULL；来源/batch组合外键；分页缺页/重复/总数变化拒绝；字段漂移；单季事务回滚、取消和恢复；无变化幂等、指标修订；季度/日频同日不重复、季度数据不能冒充完整日频、未来日频不影响精确季末选择；旧市值/价格来源衔接；维护页记录数/分类/时间。使用隔离库和模拟响应，有限在线样本核对真实ALL字段和500页容量，不做大规模探测。

历史执行完成后另出覆盖验收，检查每季页数、双哈希、来源/事实双向对照、逐字段覆盖、真实股本日期和市值乘积；不能只看任务complete。报告存 `data/verification/reports/`，来源正式归档使用公共目录，清理临时库和一次性产物。单独SQLite备份不包括原始响应，迁移需同时复制 `collection_sources/` 并核对双哈希。

存储预算沿用讨论中的粗估：十年约16万—22万行，22列结构化数据相较5列约增加30—50MB；版本、公共来源元数据、索引和归档文件另计。原始来源只集中压缩保存，不额外生成全量合并JSON或每股副本。已实测2015Q1来源明确为空，实际数据覆盖以执行及字段验收报告为准。
