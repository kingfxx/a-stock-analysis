# 全市场财务补缺模式

日期：2026-10-31。状态：已实现并完成定向验收，未启动真实补缺。单代理。

## 目标与范围

采集管理的全市场财务任务新增手动「补缺」模式，针对选定报告期，按公司＋交易所＋接口缺整行计算缺口，只下载缺失公司的ALL字段；已有行不请求、不更新，不补合法字段空值，也不替代修订核对。普通／修订模式保持原行为；定时仍仅允许增量，不自动启用补缺。该期四表均未初始化则提示先普通采集，避免首次补缺变相全量。

## 当前架构与具体归属

- collection/collection_management.py负责注册／参数校验及传递missing标志；IndustryService仅转发标志，行业更新编排在industry_updates.py选择缺口流程。
- 新增domains/market/market_financial_missing.py：已知公司范围／逐接口缺口查询、按至多200代码一段构建来源请求、校验、复用、统一事务只插缺行及结果汇总。继续使用market_financial的字段定义、normalized、编码／哈希，不改全量publish的80%骤减保护或四接口校验。
- 范围复用当前沪深成员、该季已存交易快照（含北交所）及该期四表已存公司并集；记录成员版本与快照参考，不声称发现了不在任何本地名单／快照／当期事实中的新公司。没有北交所期末名单时覆盖范围明确受限，不自动采集另一份名单。
- 请求／证据／同源预算／拒绝冷却沿用公共RequestCollector，ALL字段归档可复算。按接口分段身份记录报告期、代码范围、定义、名单参考；不新建表、缓存、锁或调度器。沿用日常财务profile，不另加提速。
- 前端仅维护页注册模式名称、范围提示及确认文案。server和HTTP协议、鉴权及恢复门禁保持；新模式仍从既有采集管理入口启动。

## 校验和续跑

- 来源filter明确报告期和证券代码，验证ALL字段、唯一证券／交易所、返回集合必须属于请求集合、总数与页数／行数一致。200代码不超过来源已核实的每页500容量，单段只有一页；来源缺行可有效返回空／部分，但记录剩余缺口，不冒充完整。
- 已完整命中全部请求公司的分段，可在同范围重试时通过归档双哈希和相同请求／定义复用，保持原取得时间；空／部分响应不缓存复用，下一次手动补缺重新查询。失败后不丢证据，不重新请求可证明完整的成功段。
- 所有实际需要的接口／分段验证成功后，在同一事务只插仍缺失的行；任一段失败不发布本轮事实。入库前重查缺口，期间已有行则跳过，不覆盖既有值或来源。原全量保护不放宽。
- 发布后按已知范围重新统计各接口缺口；公共batch标unknown（仅证明本次范围执行），不因补了几个公司就让调度器认定整期全市场完整。报告与页面区分本轮补入、跳过、仍缺及已知范围。

## 最小充分验证

隔离库和模拟响应验证：模式仅财务可用／不可定时；按接口仅请求缺行、ALL／证券过滤及来源外键、既有行完全不动、字段空值不补、首次未初始化阻止；零缺口无请求；空／部分响应仍缺统计；同范围成功段复用、失败不发布及重试；异常范围／字段／日期／重复拒绝；并发已补行跳过。运行新增测试及受影响的采集管理／全市场财务必要回归、前端语法／相关HTTP边界子集。
