# 指数采集进度显示计划

用户要求在指数页按钮下的进度位置显示当前采集说明和已采集/总数。延续用户已授权的Sol规划、Luna执行、Sol审查协作。

## 范围与验收
- 复用现有operation.result_json保存结构化总进度与分来源进度，不新增表或迁移，不触发额外来源请求。
- 按独立工作单元计数：中证指数历史各一项、看板一项、XLS一项；乐咕指数PE/PB各一项；申万月份×层级各一项，完整分页完成才算成功。日历、cookie、分页与重试不重复计入工作总数。
- 采集前仅用本地状态和任务范围统计，尽量在发送估值请求前确定总数。必须区分成功采集、已最新/已完成跳过、失败、取消/待处理。不得把失败、跳过或在途当作已采集，不把任务完成冒充数据覆盖。
- 页面直观展示总体分数及各来源当前说明/分数。允许“已处理X/Y（采集S、跳过K、失败F）”作为总进度并同时明确成功数，不能假造旧任务总数；旧记录显示进度未记录与已有状态。
- 停止/失败后保留最终分数，不输出cancelled等英文状态和原始JSON错误。0项、尚在统计、全已最新、恢复全量及单源拒绝需语义明确。
- 更新静态旧限速说明为实际已授权指数策略。
- 用隔离库/模拟任务验证总数、并行递增不丢失、跳过/失败/取消/恢复、最终状态保留及旧记录兼容；完成后Sol审查，检查当前任务是否在运行，宿主核对进程身份后重启8765并验证页面，不自动发起采集。

## 用户追加要求
- 采集按钮旁增加“查看进度”按钮，默认收起，用户手动展开/收起；展开区显示结构化总体与来源进度、当前采集说明，轮询更新不自动展开、不重置用户开关状态。保留简洁顶层运行/完成/停止状态，旧任务的未知总数不编造。
