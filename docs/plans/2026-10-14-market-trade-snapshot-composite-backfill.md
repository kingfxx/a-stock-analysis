- 固定范围2015Q1—2017Q4，共12期，只取已核实的季末实际交易日；2016Q4为2016-12-30，2017Q3为2017-09-29，2017Q4为2017-12-29。

## 2. SDK样本验证依据

详见 [BigQuant样本测试](../data-sources/bigquant-snapshot-probe.md)。8家样本覆盖12个目标日及2018-03-30核对日：

- `cn_stock_real_bar1d` 与 `cn_stock_shares` 各98行，`cn_stock_capital` 289条事件；缺少的六个组合属于江苏银行上市前期间。
- 95个有效未复权价格与本地同日价格一致；95个可计算市值中68个有旧有效市值对照，全部通过现有乘积容差，其中8个同时对照东财原始快照。
- `change_ratio` 为小数比例，映射 `change_rate` 时乘100；2018年样本支持转换。
- 日频总股本与最近事件股本有1处差异，流通A股有2处差异。因此日频表优先，事件表仅核对及缺口候选回退。
- 万科三个停牌季末的 `close` 为空，虽有昨收及零涨跌幅，市值仍不可计算。

样本成功不证明全市场覆盖、返回容量或股本映射全部正确。现有探测仅按SDK操作使用公共锁和预算，未追踪SDK内部各认证/Flight细分请求，正式批采接入必须补齐该限制。

## 3. 字段决策

采用独立合成 `definition_version`（拟为 `historical-composite-v1`），与 `em-valueanalysis-v1` 分开存储。字段定义、公式及继承方式存集中定义清单；公式尚未验证的字段登记为pending，不把待核验公式写成已实现行为。

| 目标字段 | 第一版来源／计算 | 校验及缺值规则 |
|---|---|---|
| `security_code`、`secucode`、本地 `exchange` | 经验证的BigQuant `instrument` 与已有证券身份映射 | 六位代码保留前导零，核对交易所和有效期 |
| `security_name_abbr` | 行情同日 `name` 优先；缺少时可按用户意图继承已有记录 | 回溯名称必须标记后期继承，不冒充同期名称 |
| `org_code` | 沿用已有记录的明确身份映射 | 冲突或无法确认对应关系留空，记录被引用行 |
| `trade_market`、`board_code`、`board_name`、`orig_board_code` | 沿用已有记录 | 用统一、确定的继承选择规则，保存参照记录日期及版本，标记后期回溯；不推断历史状态 |
| `source_trade_date`、本地 `trade_date` | 真实目标交易日 | 合成日期按标准日期保存，不伪造东财原始日期格式 |
| `close_price` | 本地同日raw价格优先，BigQuant `cn_stock_real_bar1d.close` 补缺与核对 | 不使用复权价；两个有效来源冲突时隔离 |
| `change_rate` | 同日 `cn_stock_real_bar1d.change_ratio × 100` | 零值保留；缺失留空；有有效价和昨收时核对日收益，不计算季度涨跌幅 |
| `total_shares` | 同日 `cn_stock_shares.total_shares` 优先 | 样本单位股；严格INTEGER，不四舍五入；缺项才检查事件表 |
| `free_shares_a` | 同日 `cn_stock_shares.a_float_shares` 候选映射 | 扩大东财重叠样本确认后发布，不用自由流通股 `free_float_shares` 替代 |
| `total_market_cap` | `sw_cap_facts` 同日最新有效值优先，缺项用 `close_price × total_shares` | 元；排除失败／拒绝来源；有效旧值冲突隔离，不直接覆盖 |
| `notlimited_marketcap_a` | `close_price × free_shares_a` | 元；股本范围与东财定义通过核对后才发布 |
| `pe_ttm` | 总市值 ÷ 同报告期TTM归母净利润 | 复用行业计算，分子或分母非正、必要输入缺失时NULL |
| `pb_mrq` | 同日未复权价 ÷ 同报告期BPS | 采用行业页PB公式，独立合成口径；价格或BPS非正／缺失时NULL |
| `pe_lar`、`pcf_ocf_lar`、`pcf_ocf_ttm`、`ps_ttm`、`peg_car` | **第一版全部NULL** | 用户已确认；不为提高覆盖率临时套用未经核验的公式 |

`cn_stock_capital` 回退按 `change_date <= trade_date` 的最近适用事件选择；保存 `change_date`、`publish_date`、原因、股份结构与来源引用。同最近变动日冲突、精度不符或缺少适用性证据时留空，不能只按公告日选股本，也不能无条件以财报股本替代。日频及事件表同时有值但不同，进入差异清单核实；不以“同一提供方”认定两表必然一致。

PE/PB财务通过 `market_financial_industry` 读取新东财行业来源，不回退旧行业财务或个股新浪。非年末TTM归母利润＝本期累计＋上年全年－上年同期累计；年末直接取全年。BPS不差分、不累计。保留输入的原表、行ID、版本、报告期、披露日和更新时间；使用最新财务修订的历史估值不宣称无前视偏差。东财原始零／负PE保留规则与合成行业公式的非正分母留空规则分别适用。

## 4. 来源缓存与追溯

1. 盘点12期日历、证券适用名单、已有来源和缺口，冻结范围及名单版本；记录本地输入版本和导出哈希。
2. 正式SDK适配复用 `collection.py`、`collection_batches/sources/provider_state` 及现有行业任务互斥，不新增专用控制表。提供方统一bigquant，认证、schema、查询、分页、重试共享预算；细分传输不可计数时不得仅凭SDK调用数宣称符合实际请求预算，应先完成可验证适配。
3. **一次启动准备全部所需来源，优先宽范围查询，不预设按季度或每800只证券拆请求。** 日频表分别查询2015—2017全部12个目标日及2018-03-30重叠核对日的沪深A股来源记录，SQL用明确 `date IN (...)`，分区filters覆盖这些日期的最小／最大值。保留来源返回的历史有效证券，不以当前行业名单过滤；仅取所需列，不下载三年全部日线。优先每张表一次范围查询，只有已验证的容量、额度、超时或内存约束需要时才按年度或稳定证券范围分块。缓存仍可离线拆成季度候选；季度分段校验不要求逐季度联网。
4. 接入前验证容量、分页／截断机制、重复键和范围；使用已归档缓存复用真实取得时间及来源关系。保留SDK返回证据；物化JSON/Arrow证据使用真实哈希依据，不冒充HTTP原文。
5. 原始来源先集中归档至数据库旁 `collection_sources/`；字段计算证据集中保存每行的本地输入记录引用、外部来源引用、公式及继承标记。合成事实的 `source_id` 指向本批次计算证据，输入来源作为依赖引用，满足 `(source_id,batch_id)` 外键；不逐行复制完整原文和路径。

调度遵守同源并发1、完成后10—15秒、60秒最多5次、每20次额外60—120秒；拒绝立即停止本轮同源请求并冷却至少一小时，暂时错误最多3次且60/120秒退避。网络、归档和等待不持SQLite写事务。

候选按季度保存Parquet；manifest包含证券范围、实际交易日、定义/解析/公式版本、来源依赖、真实取得时间、生成时间、文件哈希、逐字段覆盖及缺失原因。避免生成额外全量合并JSON或逐股原文副本。

### 宽范围查询及完整性验收

| 数据集 | 一次任务需要的范围 | 缓存列与用途 |
|---|---|---|
| `cn_stock_real_bar1d` | 12个历史季末＋2018-03-30，来源层沪深A股 | `date/instrument/name/close/pre_close/change_ratio`，保留空价行情行，用于价格、名称、日涨跌幅与重叠核对 |
| `cn_stock_shares` | 同一日期集合及来源市场范围 | `date/instrument/total_shares/a_float_shares/free_float_shares/total_float_shares`，用于总股本、流通A股及股份结构核对 |
| `cn_stock_capital` | 日频缺项／差异证券及必要核对样本；首个目标日前的基期事件＋之后至2018-03-30的事件 | 变动日、公告日、原因和股份结构；基期保留最近有效变动日的所有冲突候选，不能用任意一条ROW_NUMBER结果掩盖同日冲突 |

事件表优先由云端筛出基期及窗口事件，以减少传输；若当前SDK／SQL不支持经验证的基期筛选，按稳定证券范围下载足够前史再本地匹配。无需全市场从1990年开始的全部事件；如日频无缺项且核对通过，只取事件核对样本。后续独立补充五项估值的财务计算主要使用本地财务，不为尚未确定的公式无限扩大BigQuant下载范围。

这里的“一次取齐”是一次任务准备全部需求；三表保持各自来源证据，不强行一次SQL内连接，以免丢掉缺行、空价格或股本冲突。正式运行前检查账号剩余额度及当前SDK返回机制；官方的大结果转换或流式接口不等于账号没有限制，不能凭默认batch_size推断最大允许行数。

每个日频表同范围单独取得按日期的总行数、去重证券数及关键列非空数，与下载缓存对照；核对范围外记录、重复键、证券身份及字段类型。计数查询和数据查询分开时登记各自实际取得时间；若源修订导致计数不一致，保留两份证据并定向复核，不自动放行。返回成功或恰好达到某个行数上限不证明完整。若使用分块，manifest记录所有块的范围、哈希、应有／实得计数，检查分块合并无重叠遗漏并支持定向恢复。

这些来源缓存先完整归档，再合成季度候选并执行第5节的一次性业务入库。宽范围取数不会改变公共请求预算、拒绝保护、季度覆盖判据和独立来源身份。

## 7. 读链路与文档接入

当前 `market_cap_latest` 及行业快照价格查询固定筛选 `em-valueanalysis-v1`，现有发布器也绑定东财定义。因此新增合成记录不能直接调用原发布函数，也不会自动被页面读取；本次实现需显式支持定义身份、合成证据和未来稀疏补丁合并。
