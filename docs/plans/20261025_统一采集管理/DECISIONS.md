# 决策

- 任务独立于航运预测，使用本目录管理计划和后续修复；当前用户只要求准备计划，新窗口实施。
- 用户确认统一采集管理方向，且明确“采集管理放第一个、默认打开”，原因是数据库预览扫描较慢。默认视图必须避免任何预览扫描，包括隐式初始化、公共刷新按钮、后台事件和轮询。
- 建设在现有“后台维护”内部，不加左侧一级导航、不新开服务。tab顺序：采集管理、数据库预览、未关注股票管理；不恢复上次数据库tab而覆盖默认选择。
- 统一管理与执行接口，保留领域采集器；原页面保留快捷入口并共享任务状态/互斥，不建立两套独立执行流程。
- 任务范围首批为已有全市场财务、季度交易快照、指数、拥挤度；航运预留注册能力，真实采集及事实存储在航运计划实现。
- 调度配置优先兼容现有collection_schedules，拥挤度已授权设置保留。新任务默认关闭；不因管理页开发自动授权定时、历史回填或额外股票范围。
- 不设计自由脚本/任意URL/任意cron文本执行平台。支持可验证的日/周/月规则和发布窗口，参数由任务定义白名单约束。
- 任务级互斥与提供方级预算不同，二者都需要；来源锁/预算/冷却保持公共层，不能用任务分组拆预算。
- 配置、任务执行、数据覆盖分别表达，现有领域记录优先引用；新增公共表仅在证明必要时设计，不为每个采集器新增一套管理表。
- 航运研究表research_shipping_*前缀约定归航运计划；本任务的公共表沿用collection_*体系，不加research_。
- 正式可见状态和覆盖来自轻量业务摘要/现有水位，不调用数据库全表统计实现任务页。
