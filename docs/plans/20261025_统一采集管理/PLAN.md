## 目标与范围

在“后台维护”中集中管理现有采集任务、手动操作、进度/覆盖及定时设置，并提供未来行业采集的接入方式。复用现有采集器与公共采集层，不另建后台或任意脚本调度平台。

用户明确要求：**采集管理是第一个且默认选中的tab**。建议顺序为“采集管理 / 数据库预览 / 未关注股票管理”。数据库统计及缓存扫描只在用户进入数据库预览或明确刷新该预览时调用。默认进入维护页、刷新采集列表、轮询任务、隐藏页收到业务事件均不得触发数据库扫描；隐藏页标脏，进入时再读取。

首版纳入现有全市场财务、季度交易快照、指数采集及拥挤度任务。原业务页仅保留只读状态和前往采集管理的导航，批量执行入口统一在管理页。盘点其他可执行入口，适合的接入，不适合的标注范围；个股页面到期更新及正式财报/模型生成不自动扩大成全市场定时任务。

与航运任务分工：本任务提供任务注册、参数/能力描述、运行/状态适配、调度及管理UI；航运任务实现SSE/MOT采集器、解析、行业事实存储、预测页及真实业务校验。未实现的航运任务可仅列“待接入”说明，禁止可执行假按钮、伪成功或启动占位定时任务。本任务验收不依赖航运完成。

- 详情：适用参数、支持操作、当前进度、运行历史、错误与来源冷却、覆盖诊断/来源证据链接。任务计数、请求数、数据行数分别标注。
- 操作按能力提供：增量更新、指定范围/报告期、修订核对、历史回填、请求停止及失败分段恢复；不支持的操作不显示为可执行。取消能力不能假称已支持。

- 键盘tab/方向键、aria-selected、面板隐藏行为正确；轮询仅在可见且有需要时进行，离开停止或暂停。刷新按钮只作用当前面板，数据库预览有独立明确的刷新语义。

## 调度规则

- 统一执行器在原8765宿主机后台生命周期内运行，兼容恢复/压缩等活动门禁和安全停机；不引入Windows计划任务、额外常驻服务或Codex自动化。
- 迁移拥挤度已授权启停、北京时间、初始化要求、来源/evidence_mode及运行语义，保持原状态；切换后只有一个执行器生效，旧调度不能继续重复执行。
- 除已有授权定时外，所有新增任务默认关闭；实现可配置能力不等于允许在原库启用真实定时。回填也不自动开始。用户在新页面明确保存启用视为对应任务与范围授权。
- 日/周/月规则按Asia/Shanghai计算；服务停机不伪记执行成功。恢复时合并为至多一次必要的增量检查，不按错过的每个时间槽集中重放。记录已领取/进行中/待恢复，避免崩溃后永久锁死或无界重复。
- 月度公告类允许在发布窗口内反复检查缺失目标月份，取得完整目标后停止该目标的重复检查；不假定每月1日一定有数据。不预先启用未实现的来源。
- 失败重试遵守公共来源状态；拒绝立即停止该轮同源请求并持久冷却。无新数据、来源未发布、来源字段缺失、失败、部分成功和完整覆盖分开表达。
- 调度执行不调用研究模型，页面请求也不自动调度；任务请求仅接受登记的task_key、可验证参数和能力范围。

### 执行、调度与边界

- 新业务编排归domains/stocks/的具体模块，不继续扩充server或把新流程堆入data_service；纯参数和结果解析独立。HTTP routes只做协议与校验，application.py组装依赖及生命周期，collection_management适配注册能力，复用原Scheduler。
- 后端统一编排首次、页面手动、管理页手动及分组定时；复用现有领域更新与验证，不通过请求自身HTTP接口实现后台采集。整理财务/分红/估值及价格版本依赖，保留有效缓存与原业务口径。
- 整次operation引用必要的股票/数据项工作状态、sync run与公共batch；不改写旧sync_runs:<id>身份。设计关联时支持一个工作项对应多个来源sync run，并记录真实触发方式及父运行。新任务无需网络或被复用时也有可解释状态。
- 在短事务中固定本次分组成员快照及数据项、领取运行/槽位，事务提交后联网。组成员变动只作用未来运行；按稳定ID关联，重命名不失效，删除组使其未来日程失效，空组记录明确跳过，取消关注不进入新运行。
- 同股同数据项跨页面、多个组、手动和定时共享持久互斥与合并判断。定时只复用满足本槽位有效检查条件的成功结果，不能用任意旧成功或“当日运行过”跳过；后续显式手动刷新仍可请求新检查。不同数据项或不同全量范围不能误合并。
- 定时沿用公共最近到期槽位、漏跑合并、跨进程唯一领取及有界恢复。槽位身份需包含规则实例，支持多条规则，不把动态组名当任务身份；兼容现有单任务日程及原开关，不重新授权或重放旧任务。
- 停止在安全请求/分页边界生效，不中断事实短事务；已提交部分保留，不再启动待执行项。重启关闭失联子run/batch并恢复可恢复的父运行关系；默认不凭重启重跑手动或首次任务，定时按公共有界恢复规则处理。
- 来源拒绝立即停止该轮后续同源请求，其他来源可继续；单股票/数据项失败不能吞成总成功。执行完成、部分失败、停止及覆盖未知分别表达，coverage unknown不能被提升为complete。
- 数据库恢复、压缩、限速保存门禁及安全停机必须覆盖新的个股operation和来源请求；活动判断不能只识别旧注册任务。

## 2026-10-27 采集控制元数据整合（已实施并部署）

### 目标与边界

用户确认 operation 是一次启动的整体记录，batch 是其中可独立校验、提交和恢复的数据分段，source 是实际请求及重试；定时到点实际启动也生成 operation。本任务先编写计划，随后用户明确授权执行；保持单代理，实际实施、迁移及验收见PROGRESS最新记录。

本节覆盖此前为兼容而保留独立 operation 表及五列 schedules 合同的长期设计。目标是替换重复控制结构、统一关联和维护展示，不是在旧表上再加永久双写的公共账本。公共请求层、事实表、来源证据和既有用户授权保持原语义。

### 目标模型及表的去向

| 对象 | 整合后的职责与处理 |
|---|---|
| collection_operations | 一次实际启动的唯一控制记录；管理任务身份、范围/成员快照、模式、触发方式、停止、真实开始结束时间、整体状态及必要紧凑摘要 |
| index_collection_operations | 当前指数、国债、拥挤度、航运等实际使用方全部切换公共 operation，历史迁移并核对后删除旧物理表 |
| stock_collection_operations | 整体控制迁入公共 operation；保留首次幂等、范围、触发和取消语义，核对后删除旧物理表 |
| stock_collection_items | 不新增公共 collection_items；现有排序、互斥、模式、复用和失败恢复能力由 operation/batch 及领域执行承接，历史核对迁移后删除旧物理表 |
| collection_batches | 统一承接真实数据分段的待执行清单、顺序、领取、执行/覆盖状态及发布计数；直接关联 operation，保留既有 batch/source ID 和幂等身份，不另套父子 batch |
| collection_sources / collection_provider_state | 请求证据与真实提供方共享运行状态；不重置预算、锁、冷却或改变原文策略 |
| sync_runs / sync_state | 保留业务同步、事实出处、覆盖水位、修订及有效价格版本职责；不强行合入 operation 或 batch |
| collection_schedules | 合并开关、时区、时间、rule_json、params_json及真实更新时间，保留稳定规则身份和多主题规则 |
| collection_schedule_rules | 数据合入 schedules，改完全部读写方后删除旧物理表 |
| collection_schedule_slots | 保留定时槽位领取、唯一性、恢复次数和执行引用；关联真实 operation，与配置分开 |
| sw_update_runs | 必须纳入盘点：注册任务的整体控制归公共 operation；其中业务结果及被引用身份单独评估保留，禁止仅为状态展示新增整份结果副本，也不盲删领域业务记录 |

目标关系统一为 schedule → slot → operation → batch → source，不设置公共 item 层。业务 sync run 与 batch 保持可追溯关联，不把 sync run 当成另一次用户启动。手动与首次初始化没有定时槽位；保存日程不创建 operation，未实际启动的到期检查也不伪造运行。

“股票×财务”等界面工作单位按 batch 的股票、数据集、来源和范围分组汇总，不为展示分组另存一条 item。一次财务工作可以包含多个来源/报表类型的真实分段；分页、重试和解析步骤不另建 operation 或空壳父 batch。整体进度按明确的业务工作单位汇总，不能拿 HTTP 数或数据行数充当完成工作数。

### batch 承接工作清单（已实施）

- 排序本身不要求独立 item。指数目前由执行顺序及 work_progress.tasks 跟踪工作状态；整合时将适合持久化的真实分段状态落在 batch，operation 只保留紧凑进度摘要，不把全量待办继续塞入大JSON。
- 已确定范围的真实分段可提前登记 pending；领取后变为 running，started_at 记录实际开始时间。计划创建时间单独表达，pending 的 started_at/finished_at 为空，取消未开始分段不伪造执行时间。现表只能创建 running，需通过新迁移及公共创建/领取接口扩展，不直接沿用现 begin_batch 假装支持。
- 明确顺序/优先级、稳定工作键、实际模式和必要依赖；在短事务中原子领取并进行冲突检查，提交后联网。动态发现范围的任务先执行真实发现分段，再按确定范围增补真实 batch；不为凑齐总数建立无范围、无来源的占位父 batch。计划未展开时标明规划中/总数待定。
- 支持明确的复用/跳过结果及被复用分段引用，不生成虚假 source，不复制旧写入计数；本轮零写入不等于来源返回空。覆盖状态仍独立，执行/复用结束不能自动提升为覆盖完整。
- batch 稳定键及冲突约束覆盖股票、数据集、来源、范围和口径，不能只按排序号判断重复。旧同股同数据项互斥粒度可能比单batch更宽，须由公共operation占位/数据库事务和领域规则共同保持，不能拆成来源batch后放开原本冲突的两个运行；实施前给出并发竞争用例及约束方案。
- 停止不再领取待执行分段，保留已提交事实和证据；继续失败保留原增量/全量模式，复用范围/口径匹配的完成分段，处理未开始和失败部分。首次初始化唯一性由公共operation承接，不依赖是否已产生batch。
- 旧 item 与 batch 并非一对一。迁移逐项核对原模式、状态、时间、错误、复用及已有分段引用；有真实分段则关联已有batch，只有真实待执行范围时才登记计划分段。无法证明来源/分段的旧汇总信息须保留可追溯历史说明并明确未知，不推造成功batch或请求；历史承接方案在字段对照中定稿后再删除旧表。
- 默认方案不新增 collection_items，也不把旧item改名为父batch再套子batch。若实施发现无法由此模型合理承接的具体职责，先记录反例和替代方案再调整计划，不自行恢复四层结构。

### 字段与迁移设计要求

1. 实施前在本目录补充字段/状态/索引及旧新引用对照，覆盖所有注册任务、旧入口、恢复与维护判断。版本号按届时实际 schema 确定，不改历史迁移文件/校验和。公共 operation 字段至少覆盖稳定 ID、task_key、mode、trigger_type、scope、status、cancel_requested、started_at、finished_at、error；结果仅保留不能从分段低成本还原的必要摘要及真实历史资料。
2. operation ID 优先保留现有稳定值；命名冲突以确定性命名空间处理，保留旧引用的可核对映射。旧 API operation_ref、前端详情、历史链接及 slot 引用保持可解析；不保留永久双套控制写入或动态兼容代理。
3. 重点处理个股：当前 batch.operation_id 是 sync_runs:<id>，scope 中另有 parent_operation/parent_item。新执行显式携带公共 operation 和真实 sync run 关联，不新增 item 引用，不能继续靠字符串前缀猜父级。旧 parent_item 仅作历史映射证据。批次重建/加列方案须先核对组合外键、来源、事实引用、幂等索引和行业 manifest 对 operation_id 的校验，定稿后再实施。
4. 仅迁移可证明的历史父子关系。缺父级的旧 batch、未注册 CLI 或独立历史 sync run 保留真实旧引用和未知父级，不按时间邻近拼接、不为每条旧 batch 编造一次启动。历史无法归属的表示方式及约束须在字段设计中写清；新受管任务必须具备有效关联。
5. schedule 合并保留原 task_key、enabled、timezone、local_time、规则、参数和分别可证的真实修改时间。无 rules 行的旧拥挤度日程使用其真实旧 daily 语义；不得把已删除个股规则留下的 disabled 父身份重新解释成有效规则。用明确删除标志或等价设计保留槽位外键与删除语义，字段定稿时给出判定矩阵。
6. 日程身份与任务类型分开：stocks:<group_id>:<uuid> 仍为规则身份，业务 task_key 为 stocks。同组多主题不覆盖，编辑保留身份；删除阻止未来启动、关闭待恢复槽位，保留历史和已运行任务。规则删除/关闭不等于用户取消当前 operation。
7. 同一槽位一次恢复若实际产生新执行，可关联新 operation；既有 attempts 上限和最近到期漏跑合并规则不扩大。保留已记录旧执行线索，不额外新建无必要的执行历史副本；具体恢复引用方式在字段对照中定稿。
8. 活动互斥、首次初始化唯一性、同股同数据项部分唯一索引、定时槽位唯一领取必须在数据库层延续。合并表不把既有全局串行擅改为并行，也不扩大原不支持的取消能力。运行成功、部分失败、停止、复用和覆盖未知继续分别表达。
9. 迁移在无活动任务时进行，联网和限速等待不在写事务内。先备份，再事务迁移、核对、切换及清理；在迁移事务内发现冲突应回滚，不留下半迁移库。上线回退须恢复匹配版本代码与迁移前备份，不以隔离库覆盖日常库；切换后如已有新写入，禁止直接恢复旧快照丢弃新记录，须先保全并制定回退步骤。
10. 本轮不搬动来源文件/PDF；SQLite 备份不包含这些文件，保持引用及双哈希不变。若实施发现必须移动文件，应先补文件清单和哈希校验方案，不能仅以库备份声称资料已备份。

- 历史精简先做字段对照和可重建性核验。已有batch/source/正式验收报告可完整承接的重复内容才删除；独有覆盖或异常证据先明确合理归属并无损迁移，未知计数仍未知。不能仅截断字符串、压缩BLOB或删results宣称完成，也不能为旧历史联网重采。
- 迁移前备份保留原始旧记录，迁移后核对历史整体状态、可证计数、诊断、详情可追溯及报告引用。新增验收包括JSON逻辑字节、表及索引物理页、空闲页、列表/详情耗时和运行进度更新写入开销；给出精简前后最大/平均值与总量，不只报告列表SQL已投影。
- SQLite删除/缩短字段或DROP旧表不保证数据库文件立即变小；本任务不在有任务运行时自动VACUUM。实际需要压缩时沿用维护门禁和备份恢复规则，区分可复用空闲页与已释放文件空间。
