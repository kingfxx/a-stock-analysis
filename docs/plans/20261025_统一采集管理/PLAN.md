# 统一采集管理

状态：已实施并完成相关回归、隔离库验收及8765原库页面验收。本任务独立于20261024_ccfi海控利润预测。

## 目标与范围

在“后台维护”中集中管理现有采集任务、手动操作、进度/覆盖及定时设置，并提供未来行业采集的接入方式。复用现有采集器与公共采集层，不另建后台或任意脚本调度平台。

用户明确要求：**采集管理是第一个且默认选中的tab**。建议顺序为“采集管理 / 数据库预览 / 未关注股票管理”。数据库统计及缓存扫描只在用户进入数据库预览或明确刷新该预览时调用。默认进入维护页、刷新采集列表、轮询任务、隐藏页收到业务事件均不得触发数据库扫描；隐藏页标脏，进入时再读取。

首版纳入现有全市场财务、季度交易快照、指数采集及拥挤度任务。原业务页仅保留只读状态和前往采集管理的导航，批量执行入口统一在管理页。盘点其他可执行入口，适合的接入，不适合的标注范围；个股页面到期更新及正式财报/模型生成不自动扩大成全市场定时任务。

与航运任务分工：本任务提供任务注册、参数/能力描述、运行/状态适配、调度及管理UI；航运任务实现SSE/MOT采集器、解析、行业事实存储、预测页及真实业务校验。未实现的航运任务可仅列“待接入”说明，禁止可执行假按钮、伪成功或启动占位定时任务。本任务验收不依赖航运完成。

## 页面和交互

- 默认任务列表：任务名称/分组、来源、数据覆盖截至/缺口/未知、运行状态、最近检查/最近成功、自动开关/规则/下次检查、操作。各时间清楚区分，不用数据日期替代采集时间。
- 详情：适用参数、支持操作、当前进度、运行历史、错误与来源冷却、覆盖诊断/来源证据链接。任务计数、请求数、数据行数分别标注。
- 操作按能力提供：增量更新、指定范围/报告期、修订核对、历史回填、请求停止及失败分段恢复；不支持的操作不显示为可执行。取消能力不能假称已支持。
- 历史回填/大范围运行显示范围与模式，保留原业务所需确认；不得将默认“立即运行”变成全量回填或收费/模型生成。
- 自动检查可配置启停、北京时间、日/周/月检查规则和必要的发布窗口。页面上解释检查频率不等于数据频率。管理页刷新只读本地状态，定时配置保存不立即采集。
- 键盘tab/方向键、aria-selected、面板隐藏行为正确；轮询仅在可见且有需要时进行，离开停止或暂停。刷新按钮只作用当前面板，数据库预览有独立明确的刷新语义。

## 公共执行与存储设计

1. 先盘点每个现有入口的启动参数、互斥键、状态来源、取消/恢复能力、授权策略、覆盖口径及运行证据，形成TASK_CATALOG.md。任务按业务能力登记，实际HTTP提供方仍由公共层独立控制。
2. 用显式任务注册表和小型适配接口描述task_key、名称、参数约束、支持模式、run/status/cancel/coverage/schedule能力；不允许前端提交任意Python函数、URL或shell命令。
3. 复用collection.py的请求锁、预算、拒绝冷却、批次及来源归档。已有旧业务记录通过引用展示，不批量重写旧历史，也不使未改造流程冒称已受公共保护。调整入口不能改变既有来源速度和证据策略。
4. 现有index_collection_operations等领域任务控制继续作为真实执行/进度依据。优先适配，确需跨类型执行账本时最多设计必要的公共轻量运行记录，引用领域operation与公共batch，不复制响应、整份进度或事实。
5. collection_schedules已有日更字段，先核对真实结构再设计兼容扩展，不能直接覆盖成不兼容表或复用拥挤度开关运行其他任务。配置保存启停、时区、规则、参数及真实更新时间；运行实例/租约与配置分开。明确调度槽位唯一键，支持重启/跨进程互斥，数据库短事务领取后执行网络。
6. 任务级互斥必须覆盖新页面、旧页面、手动和定时；范围不同但可能写同数据时按领域冲突规则处理。互斥不得靠两个页面各自的JS按钮disabled实现。
7. 新表/扩展同步docs/sqlite-storage.md、维护DESCRIPTIONS/TIME_COLUMNS/PARENT_TIMES和相关设计文档。隔离库核对用途/分类/记录数/占用/时间；代表性数据测量行大小、索引和写入/常用读取耗时。具体新增表清单待代码盘点定稿，不先承诺固定数量。

## 调度规则

- 统一执行器在原8765宿主机后台生命周期内运行，兼容恢复/压缩等活动门禁和安全停机；不引入Windows计划任务、额外常驻服务或Codex自动化。
- 迁移拥挤度已授权启停、北京时间、初始化要求、来源/evidence_mode及运行语义，保持原状态；切换后只有一个执行器生效，旧调度不能继续重复执行。
- 除已有授权定时外，所有新增任务默认关闭；实现可配置能力不等于允许在原库启用真实定时。回填也不自动开始。用户在新页面明确保存启用视为对应任务与范围授权。
- 日/周/月规则按Asia/Shanghai计算；服务停机不伪记执行成功。恢复时合并为至多一次必要的增量检查，不按错过的每个时间槽集中重放。记录已领取/进行中/待恢复，避免崩溃后永久锁死或无界重复。
- 月度公告类允许在发布窗口内反复检查缺失目标月份，取得完整目标后停止该目标的重复检查；不假定每月1日一定有数据。不预先启用未实现的来源。
- 失败重试遵守公共来源状态；拒绝立即停止该轮同源请求并持久冷却。无新数据、来源未发布、来源字段缺失、失败、部分成功和完整覆盖分开表达。
- 调度执行不调用研究模型，页面请求也不自动调度；任务请求仅接受登记的task_key、可验证参数和能力范围。

## 验收重点

- 默认进入后台维护选中采集管理；storage统计接口及底层扫描调用为零，任务刷新/轮询/隐藏页事件同样为零。点击数据库预览才读取，重复切换按现有缓存策略复用，不每次强制重扫。
- 已有采集入口和新入口启动同一任务时不重复执行，适用的参数、取消和恢复行为一致。
- 执行成功与覆盖完整分开；无法取得的覆盖/时间显示未知或未记录，不扫描整库来补造任务覆盖。
- 隔离库+假时钟测试每日/周/月、月末/跨年、重启漏跑合并、重复tick/跨进程领取、手动冲突、关闭运行中任务和崩溃恢复。关闭自动开关阻止新调度，不强杀已运行请求；停止用独立操作。
- 拥挤度迁移保持初始化/授权/metadata_only行为，旧新调度不并存；新schedule默认关闭。
- 公共冷却、失败分段恢复、数据库恢复/压缩门禁及停机回归通过，不用大量真实请求验收限流。
- 相关后端和前端测试通过，实际页面验证tab顺序/懒加载/参数/状态；正式运行用原8765，自动测试用临时隔离库和显式空闲端口，清理测试资料。
