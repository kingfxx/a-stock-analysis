# 港股个股分析与采集

## 交付范围

- 在「我的股票」中新增、搜索、切换、分组、排序、取消关注和恢复港股，支持 A 股和港股同组。以「中远海控 · 601919 · A 股」和「中远海控 · 01919 · 港股」验收同名证券，再用一只仅在港交所上市的普通股验证通用数据链。
- 港股打开同一套「企业经营趋势」「主营构成」「财务分析」，按实际可用报告期、指标和币种显示。已有证券的页面 GET 只读本地，首次未建档沿用明确进入完整个股页后的幂等初始化 POST。单股手动刷新、全量刷新沿用现有入口。
- 「后台维护 → 采集管理 → 个股采集」接受 `601919 01919` 或混合分组，提供增量、全量、续跑、停止、进度和分组日程。一次触发对应一个 `stocks` operation。
- 本计划交付个股数据及三个分析页面。账户持仓纳入、组合汇率及人民币盈亏由[个人持仓与复盘](../20261125_个人持仓与复盘/PLAN.md)处理。个股以外的研究、行业对比、Checklist、模型和正式财报准备沿用各自授权与入口。

## 实施顺序与模块边界

| 阶段 | 现有入口与改造归属 |
| --- | --- |
| 1. 证券身份与存储 | 先核对 `infrastructure/storage.py` 的启动迁移、`instruments` 的外键、视图、索引和触发器，以及按股票代码查询的调用方。证券身份解析放 `domains/stocks/` 的小型纯模块，接受市场与文本代码，现有 A 股专用校验保留给专用路径。SQLite 负责迁移和约束，证券库负责搜索、分组及关注状态。 |
| 2. 来源验证与分段 | `domains/stocks/` 承担腾讯行情、分红和披露易元数据的港股适配，`domains/financials/` 承担港股三表与主营来源及映射，`domains/valuation/` 承担百度港股估值。来源模块负责请求与分页、纯解析负责字段、日期及币种校验，业务服务负责短事务发布与水位。先按下表验证实际响应，再接入对应主题。 |
| 3. 统一采集 | `collection_operations.py` 负责范围和生命周期，`collection_plan.py` 负责生成每只证券真实来源分段，`group_execution.py` 与 `group_requests.py` 复用运行内执行及提供方通道，`collection_schedules.py` 处理规则和恢复。港股执行委派给所属领域适配，现有 `domains/stocks/data_service.py` 仅对接它已有的读取和页面数据组装职责。 |
| 4. 三页与股票选择器 | 首页／个股 API 由 `http/routes/pages.py`、`http/routes/stocks.py` 及现有相关路由继续承接。路由解析和校验输入后调用领域，`http/rendering.py` 负责安全页面注入。`web/shared/stock-picker.js` 与三个现有页面脚本消费证券身份、币种、报告期和适用项，由领域提供相同语义的数据契约。 |
| 5. 验收与上线 | 按下方检查顺序先完成离线和隔离库验证，再有限联网核验。实现完成后更新架构导航、个股采集、采集管理、企业经营趋势指标、主营构成和 SQLite 文档。需要应用代码生效时核对宿主 8765 活动任务与进程，安全重启、核验启动日志和页面，保持后台运行。 |

依赖方向沿用 `HTTP → 领域编排／读取 → 来源适配与纯解析／存储`。`application.py` 仅按既有模式组装实例。公共采集层负责锁、预算、冷却、归档、运行和槽位状态，业务分段仍由个股领域管理。行情分页、事件版本、拼音生成和现有图表契约在语义吻合时复用。实施前对照最新工作树复核真实入口及进行中的改动，若边界或范围变化，先更新本目录。

## 来源、展示口径与存储

优先共用按 `instrument_id` 和来源区分的事实表。现有约束和字段边界见[设计决策](DECISIONS.md)。行情报价币种、财报列报币种、宣派与支付币种按各自口径表达。

| 主题 | 计划与验收要求 |
| --- | --- |
| 行情 | 腾讯 `hk01919` 未复权与港股专用前复权接口，新浪独立核对。复用未复权及前复权版本存储，确认交易日、OHLC、成交量单位、复权口径和分页重叠。缺日区分停牌、未上市、已知缺口及未知覆盖。 |
| 财务报表 | 东财港股三表，采用真实字段码和元数据，有限样本对照披露易财报或业绩。年度、中期按实际期显示，部分发行人有季度披露时逐项验证累计／单季及合并范围。仅在所需期间和字段齐备、口径一致时计算单季度与 TTM。保留报告期、原始字段码、实际出处、列报币种、单位及可核实披露日。 |
| 主营构成 | 同花顺港股经营分析作为结构化候选，披露易年报分部附注作核验。先验证 01919 年度及中期样本、再验证纯港股样本及历史分页。对齐分部、业务或地区、期间、币种、抵销和收入分母。只能证明营业利润时按营业利润语义处理，毛利和成本无适用数据时留空。验收须有两期可比较的分部数据或明确展示仅有的一期及缺口。 |
| 公告元数据 | 港交所披露易。先验证发行人识别、目录接口、日期范围、公告修订及至少一个实际财报披露日。保留公告取得时间与实际披露时间。个股目录采集沿用 `metadata_only`，正式 PDF 仍由独立明确业务入口处理。 |
| 估值 | 百度港股 PE(TTM)、PB、总市值作为观测来源，保留实际观测日与采样定义。图表区分港元股价、列报币种财务指标和估值单位。证券级市值需有同类流通市场对应的已发行股数及其日期，发行人总市值需要独立核实定义及币种，未验证口径的市值留空。 |
| 分红 | 东财和同花顺候选，披露易派息公告核对关键事件。保留宣派币种及金额、适用支付币种及每股金额、除净日、登记日、派付日、事件状态及修订。证券公开派息与券商账户入账分属不同领域。 |
| A 股专用主题 | 港股的股东人数和融资融券按当前可用数据标「不适用」，在三个页面按市场能力展示。公开卖空、港股通持仓和 CCASS 以后可按各自口径另行接入。 |

## 混合运行契约

- 手动输入兼容裸六位 A 股和裸五位港股代码，保留 `01919` 的前导零。规范证券身份贯通去重、手动输入、分组成员、最近查看、页面状态、缓存、任务互斥、首次初始化、续跑及恢复。旧 A 股 URL 和 API 参数可继续使用。先核对归一后的代码与提供方真实证券身份再写入事实。
- 运行时先由领域按「证券 × 所选数据项」判定适用性，确定确切接口再创建分段。混合任务逐证券展示不适用项，既无可执行项的显式请求返回原因。同源批量合并须满足实际接口、市场、字段定义及范围兼容，并具有完整分页和逐成员证据，港股首版按单证券来源窗口验证。组内依赖仅影响本证券及该来源的相关数据项。
- 一次启动或一个槽位冻结实际成员及所选范围。增量补尾并校验重叠，全量按各数据集已定义历史窗口重查。续跑按同一规范证券、实际来源、口径及原分段范围恢复，已完成且匹配的分段可复用。旧 A 股运行按可证明的原身份解析，无法确认的历史保持原有证据；恢复时不按当前分组重新扩张原运行。
- 同一真实提供方跨 A 股、港股和其他模块共用 `RequestCollector`、持久预算、锁和冷却。港股新增接口使用公共保守策略，已有批量配置仍按授权范围适用。每次真实请求及重试单独记来源，发布前核验，拒绝立即停止本轮同源请求并遵守既有冷却和 `Retry-After`。按公共批次区分执行状态、覆盖缺口和不适用。
- 混合分组日程由用户明确启用，默认关闭，保存不触发请求，定时仅增量。已有规则在保持原 A 股授权范围的前提下继续运行，可显式编辑以纳入港股。槽位检查的提供方从本轮匹配的证券及实际分段得出，续跑复用该槽位冻结范围。

## 验收

1. **启动迁移与身份。** 在隔离库覆盖空库、已有 A 股库、重复启动和失败回滚。核对 `integrity_check`、`foreign_key_check`、证券 ID、分组、最近查看、行情版本、公告及事实行关联。验证旧 URL/API、前导零、同名 A/H 股独立搜索和移组，以及 A 股专用入口继续拒绝港股。以 `test_storage_startup.py`、`test_storage_source_contracts.py`、`test_stock_library.py` 和选择器回归为基础。
2. **来源与分析计算。** 用离线样本验证代码、分页、截断、币种、复权、修订、缺失与有效零／负值。以 `test_statements.py`、`test_business_segments.py`、`test_financial_storage.py` 和 `trend_view.cjs` 等相关测试为基础。联网验收用 01919 和一只纯港股各做有限抽样。01919 核对 2026-05-28 未复权收盘 14.06 港元、每股派息 0.50414 港元及 2026-06-26 派付，核对 2025 年报归母溢利和至少一个主营分部。说明每个窗口观察到的缺口。
3. **混合运行与恢复。** 用隔离库、模拟 HTTP 和假时钟走手动混合输入、仅选不适用项、同组选取、显式启用日程、分组变化后恢复、停止与重启、同源拒绝以及成功分段复用。核对首次初始化并发幂等、已有证券和只读 GET 无网络、A/H 同源预算共享，核对来源记录与事实一起短事务发布。按影响选 `test_stock_collection_management.py`、`test_stock_group_refresh.py`、`test_collection_rate_limits.py`、`test_collection_provider_pacing.py` 与 `test_http_source_boundaries.py` 的有关用例。
4. **页面和维护。** 浏览器切换 A/H 股，核对三个页面的币种、有效报告期、空值、不适用项和日期悬浮提示；核对采集运行详情、SQLite 维护页分类、记录数、空间和真实更新时间。隔离库验证新事实的存储成本及常用读取耗时。验收结果与来源覆盖记入 `data/verification/reports/`，生产个股响应沿用既有 `metadata_only`。测试库、一次性脚本与临时页面产物按项目规则清理。

验证范围以受影响调用者及新迁移风险为限。仅在实际影响无法界定时说明理由后扩大。文档阶段仅检查文件、链接和差异。
