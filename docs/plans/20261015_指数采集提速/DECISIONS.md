# 决策记录

- 用户本轮明确授权覆盖旧指数限速下限；不把该例外应用于其他领域。
- 并发2指真实在途HTTP最多2个，预算与冷却仍按真实提供方共享，不能用拆来源标识实现。
- 完成后设置来源级下一次发送最早时间2秒+0—3秒随机；两个已在途请求不因另一请求完成而中断，后续发送遵守最新共享ready_at及窗口。第20次完成加10秒，后续完成不得覆盖缩短已有休息。
- 应使用短持锁预算预留/完成更新与跨进程在途槽位，而非全程来源独占锁，否则不能达到并发2。跨不同策略也不能丢失预算和拒绝状态；实现细节由Luna记录，Sol审查。
- 实际在途硬上限由每提供方两个OS文件锁槽位保证；普通HTTP和SDK占用两个槽位，指数HTTP占一个槽位。槽位随进程退出由操作系统释放；SQLite公共状态保留请求预算、完成计数、ready时间和诊断用inflight记录。计时不依赖可能过期的租约。
- 20次额外休息按完成请求数记录；多个在途请求完成时合并最晚ready时间。首次在途指数请求后允许第二槽并发填充；完成后新请求按最新ready时间等待。
- 不修改或覆盖工作区既有DCF相关修改；本任务无需提交或推送。

## Sol中途审查记录
- Windows默认pytest临时路径过长且隔离环境文件锁受限；正式回归在宿主提升环境使用仓库内短basetemp，测试仍只用隔离库及模拟响应。
- 真实并发上限不能仅依赖固定时长租约；requests读超时不是请求总时限，需有OS槽位锁或等效可靠占用机制。
- 放行槽位前须登记拒绝，防止默认单并发排队请求在403/429后漏发；恢复探测不能在检查所有权前计入实际请求数。
- 新策略不得取消stock_fast跳过窗口/间隔的既有授权；新旧策略混用须遵守在途独占标记。
- 失败与取消工作单元也必须纳入最终请求数、重试数及停止状态汇总。
- 兼容旧预算JSON时，以旧count作为completed的懒迁移基数，避免发布后每20次休息计数重置；SDK transport也沿用共享completed/ready状态。
- 申万按一级、二级各自使用独立worker，并在层级内按月份倒序串行；这样可并行两个层级，同时保证每个层级最新月份先完成并建立目录名称。
- 并行工作单元在全部任务结束后汇总统计并关闭自有Session；注入的外部collector不由工作单元代为关闭。
