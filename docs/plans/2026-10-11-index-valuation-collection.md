# 指数估值与公共集采元数据方案

状态：2026-10-11 已实施并上线，十年采集分段已完成，来源覆盖核验发现历史缺口。本文保留设计及最初来源证据；实际实现、未知信息处理和手动采集入口原见指数估值采集说明，现已合并至[统一指数采集说明](../index-data-collection.md)。日常库已升级 v24，前期核验的30,564条宽基／策略估值已导入；申万历史逐行业／逐指标完整覆盖、正式目录有效期及二级父级映射仍待补齐或核实，不能将分段完成视为十年数据完整。旧采集历史不迁移，主题指数不采集。

## 1. 目标与边界

- 覆盖最近十年可取得的宽基指数及申万一级、二级行业指数估值。
- 本次不加入主题指数采集，不安排主题指数目录请求、历史回填或日常增量；`theme` 仅作为存储结构的扩展能力保留，未来另行确定采集范围。
- 每种来源按其实际最细粒度采集；不把月频数据插值成日频/周频。
- 初次采集历史全量，之后按交易日增量，并重叠检查近期日期以发现历史修订。
- 本期创建 `collection_batches`、`collection_sources`，指数采集使用新公共表；业务数据仍保存在自己的事实表。公共表面向后续各采集域复用，但旧财务、价格采集继续使用原表及读写流程。
- 本期只评估公共表能否表达旧采集的历史数据，并用隔离样例验证字段映射；旧批次、来源及事实外键迁移另立后续计划，不作为指数采集上线前置条件。
- 本阶段只存估值与指数目录；“指数成分股历史、营收、市值汇总”是独立的数据域，需另做历史口径和成分权重验证。
- 宽基指数和行业指数共用一张 `index_valuation_observations` 估值事实表，PE、PB、股息率等为指标列；类别、分类体系、行业层级和父级关系放在 `index_catalog`，不在每条估值中重复存储。
- 行业指数与公司申万行业分类不是同一对象。当前 `sw_industries` / `sw_memberships` 不能代替指数目录。

## 3. 数据覆盖结论

- **申万行业指数**：已验证一级、二级均能取日频 PE、PB、股息率，且 PE/PB 有远超十年的历史探测结果。适合作为本次十年日频的主要覆盖范围；全区间、全行业和股息率完整率尚待全量盘点。
- **宽基指数**：优先采集第 2.1 节已确认九指数的中证十年日频滚动 PE；乐咕十二候选作为独立月频 PE/PB 来源。中证每日板块接口可采最新静态PE/滚动PE/PB/股息率快照，尚未确认历史能力。其他中证候选仍待复查，不能将403解释为来源不支持。当前没有验证到宽基十年日频静态PE/PB/股息率；中证近期估值文件不能承担十年历史。按指数/指标分别报告起始日与实际粒度，不合并不同来源口径。
- **动态 PE**：当前验证到乐咕静态及滚动/TTM相关列，中证 PE1/PE2 的区别为股本口径；尚未验证到可明确作为一致口径“预测动态 PE”的全指数十年序列。字段未核准前不把 rolling、TTM、PE1/PE2互相映射。
- **行业总市值**：申万日报还返回流通市值、平均流通市值（来源单位亿元），但不是已验证的指数总市值。市值是否纳入本次业务指标需单独确认口径。
- **截图中的营收与总市值趋势**：以上估值来源不足以直接生成。需额外取得历史成分、历史权重、成分股历史财务和市值，并定义当时成分或当前成分回溯口径。

## 4. 公共采集元数据设计

### 4.1 `collection_batches`

一行代表同一数据集、来源和范围的一次采集生命周期。多数据集/多来源的同一用户操作以 `operation_id` 关联多个批次。

| 字段 | 设计 |
|---|---|
| `id` | 主键 |
| `operation_id` | 同一用户操作、调度或编排任务的关联 ID |
| `idempotency_key` | 可空的业务去重键；按数据域、数据集、来源限定作用域，保留旧价格批次内容哈希的去重能力，不对所有运行全局唯一 |
| `domain`, `dataset`, `source_system` | 数据域、数据集、预期来源；如 `market`, `index_valuation`, `sws` |
| `scope_start`, `scope_end`, `scope_json` | 日期范围与指数/行业/报告期等精确范围；名单引用固定为 `universe_ref={type, id}`，如 `{type: "sw_imports", id: 123}`，保留引用类型和原 ID |
| `frequency`, `universe_version` | 目标粒度、指数/成分名单或分类版本 |
| `trigger_type` | `full`, `incremental`, `backfill`, `retry`, `manual` 等 |
| `status` | `running`, `complete`, `failed`, `cancelled` |
| `coverage_status` | `complete`, `partial`, `empty`, `unknown`，与执行状态分开 |
| `started_at`, `finished_at` | 实际批次起止时间 |
| `parser_version`, `definition_version` | 解析与来源口径映射版本 |
| `result_json`, `error` | 覆盖/计数/缺口详情及批次级错误 |

建议给日期范围、数据集、来源和状态建立查询索引。`complete + partial` 表示请求完成但数据覆盖有缺口；权限错误为 `failed + unknown`。

`idempotency_key` 的生成规则需按业务登记；有来源修订检查需求的增量任务不能仅凭请求范围相同跳过。重复导入只复用已完成且校验通过的结果，失败批次允许新尝试。名单引用在对应适配器中校验目标存在；`universe_version` 是版本标识，不能代替引用类型及 ID。

### 4.2 `collection_sources`

一行表示一次请求尝试及其响应文件；失败请求也留痕。

| 字段 | 设计 |
|---|---|
| `id`, `batch_id` | 主键、批次外键 |
| `source_system` | 本次请求的实际提供方，不能仅依赖批次的预期来源；混合提供方采集按来源拆批次，以 `operation_id` 关联 |
| `dataset`, `request_key`, `attempt_no` | 子数据集、页码/指数代码/请求范围标识、重试序号 |
| `request_json` | 固定结构包含 `transport`、HTTP `method/url` 或 SDK `method_name`、`params`、分页标识；脱敏后保存，不含凭据 |
| `request_status`, `parse_status`, `http_status`, `error` | 请求状态与解析状态分开；HTTP 状态不适用或旧数据未记录时可空，失败信息区分网络、业务响应及解析错误 |
| `file_path`, `content_type`, `compression` | 相对数据库目录的来源文件路径、原始内容媒体类型及落盘压缩方式；无响应文件时可空 |
| `raw_sha256`, `stored_sha256`, `hash_basis` | 解压原文和实际落盘文件哈希及明确的哈希对象；旧记录缺失的哈希可空，不将不同对象的哈希相互冒充 |
| `raw_bytes`, `stored_bytes`, `fields_json` | 字节数及响应字段清单 |
| `obtained_at` | 实际请求/采集时间 |

路径统一相对于数据库目录，建议归档在 `collection_sources/<source_system>/<dataset>/...`。财务原始文件、季度股价日历和指数估值之后统一登记来源，但允许不同业务域采用自己的分段、缓存和发布策略。

请求尝试采用 `UNIQUE(batch_id, dataset, request_key, attempt_no)`，新请求重试序号从 1 开始。`request_key` 由稳定的接口标识、脱敏业务参数及分页范围生成，不包含会变化的凭据。旧来源仅能映射为一条已记录尝试，不声称其历史上没有重试。状态取值应允许 `unknown`；旧数据没有的 HTTP 状态、失败次数、字段清单、字节数及哈希可空。

请求过程中逐次持久化来源记录，不能等事实发布成功后才登记；失败批次仍保留成功响应和失败尝试。来源文件先原子落盘并校验哈希，再登记可复核路径。缓存复用保持原始 `obtained_at`，在当前批次请求记录中注明复用及原来源引用，不冒充新网络请求。事实表通过组合外键或触发器验证 `source_id` 属于其 `batch_id`，拒绝跨批次误关联。

### 4.3 旧采集历史数据兼容性评估（本期不迁移）

当前财务使用 `market_financial_batches/sources`，季度股价使用 `market_price_batches/sources`。本期以现有 schema 和读写实现为依据，验证以下信息能完整表达；不改写旧表、旧外键、旧来源文件或日常任务。

| 旧信息或行为 | 公共表表达及后续迁移约束 |
|---|---|
| 财务一个批次包含三表及业绩指标 | 未来按数据集拆为四个公共批次，以同一 `operation_id` 关联；旧批次到新批次映射支持一对多，现有财务四表共同发布要求保持不变 |
| 财务 `report_date`、批次状态、时间、结果及错误 | 报告期写入精确范围，原状态、时间和结果保留；未记录的覆盖状态为 `unknown`，不能从执行成功推定完整 |
| 财务来源 `dataset/page_number/url/params_json` | 映射到数据集、固定请求结构及稳定请求键，保留分页标识 |
| 财务来源 `content_hash` | 当前发布代码存的是解压原文哈希，映射到 `raw_sha256`；落盘 gzip 哈希仅在原文件可校验时补充 |
| 价格批次 `content_hash` | 映射到相应业务作用域的 `idempotency_key`，保留已完成结果复用语义；不是来源文件哈希 |
| 价格批次 `member_import_id/start_period/end_period` | 名单用 `scope_json.universe_ref` 保留 `sw_imports` 引用，日期范围保留原季度末含义，频率为季度采样 |
| 价格来源 `source/dataset/params_json` | 保留逐来源提供方和接口/SDK 数据集；日历等辅助数据集按自身来源及粒度拆批次，用同一操作关联 |
| 价格来源 `content_hash` | 当前代码对实际落盘文件计算哈希，映射到 `stored_sha256`；不能直接作为原文哈希 |
| 财务和价格原始文件路径 | 旧财务相对采集根目录、旧价格相对项目根目录；后续根据原根解析，再转为数据库目录相对引用，可含上级路径，不要求移动原件；读取须限制在明确登记的来源目录内 |
| 两套 ID 可能重号及批次拆分 | 后续用 `(legacy_table, legacy_id, dataset)` 映射批次，用 `(legacy_table, legacy_id)` 映射来源，保留原身份信息，禁止按数值 ID 直接合并 |
| 旧数据未记录的请求尝试与元信息 | 保留已知记录；其他信息为空或 `unknown`，不编造历史失败次数、HTTP 状态或采集时间 |

项目现有 schema 为 v22；预计拆成 v23 公共采集表、v24 指数目录/估值表，实施时以实际最新版本顺延。本期同步登记新表在 `maintenance.py` 的用途、分类、真实更新时间依据，并更新存储和数据源文档。旧数据迁移、事实表重建及财务/价格读写器改造后续单独实施。`sw_update_runs` 保留页面进度与任务互斥职责；新指数操作可用 `operation_id` 关联公共批次，它不是来源追溯表。

## 5. 指数业务表

### 5.1 指数目录 `index_catalog`

保存 canonical `index_code`、名称、指数类别、分类体系、行业层级、父级指数代码、有效起止日及提供方原始代码。提供方代码与名称可能变化，需保留历史有效期与目录来源引用。早期申万行业数少于当前行业数是历史事实，不补造不存在的指数。

类别、体系、层级分别建字段，不合成 `sw_l1/sw_l2` 等组合枚举，避免展示层拆解字符串，并支持后续接入其他行业体系。

| 字段 | 设计与缺值规则 |
|---|---|
| `index_code` | 含发布体系命名空间的稳定指数标识，供统一估值事实关联 |
| `name` | 该目录历史版本的名称，不将当前名称自动覆盖到所有历史日期 |
| `index_type` | 非空类别，`broad` 为宽基（包括纳入的综合市场指数）、`industry` 为行业、`strategy` 为红利／低波等策略指数、`theme` 为半导体／人工智能等主题指数；类别按正式编制定义核准，不因共用估值表而归为行业 |
| `classification_system` | 行业分类体系，如 `sw`；宽基及无正式行业分类属性的策略／主题指数为 `NULL`。提供方不等于分类体系：乐咕可以提供申万行业估值 |
| `industry_level` | 行业层级整数，已核准时为1、2等；非行业指数为 `NULL`，不使用0。行业层级未知时留空并标记待核对，不冒充一级 |
| `parent_index_code` | 同分类体系内直接上级行业指数的 canonical 标识；一级行业、宽基及不适用的策略／主题指数为 `NULL`，二级行业关联对应一级；父级未知时留空并标记待补，不用行业父级字段表达主题标签或策略派生关系 |
| `valid_from`, `valid_to` | 该名称及分类／父级关系版本的有效区间；未知有效期单独标记，不能从观测缺口推断 |
| 提供方原始代码、目录来源引用 | 保留提供方代码映射和可追溯来源，不能只用页面名称匹配指数 |

例如沪深300为 `broad/NULL/NULL`，申万一级行业为 `industry/sw/1`，申万二级行业为 `industry/sw/2`；三个值分别对应类别、分类体系、层级。二级行业的 `parent_index_code` 指向其一级行业指数，不指向公司分类表 `sw_industries`。

红利策略指数为 `strategy/NULL/NULL`，经核准的半导体主题指数为 `theme/NULL/NULL`；若某半导体指数属于正式行业分类体系，则为 `industry` 并登记对应体系与层级，不能仅凭“半导体”名称判断。存储结构支持后续新增主题／策略指数；本次明确不采集主题指数，`theme` 只用于扩展设计及合成样例验证。本期其他采集目录仍以已验证来源为准，不承诺未来候选的历史估值覆盖。正式申万行业体系中的半导体行业指数不因名称相同而排除。

canonical 代码需包含发布体系命名空间，避免不同体系代码碰撞。目录历史以独立版本行或历史映射表表达，不能仅以 `index_code` 为唯一主键覆盖名称、层级和父级变化。同一提供方原始代码的有效区间不得重叠；正式有效期与最早/最晚观测日期分别保存，不能因某段数据缺失推断指数当时不存在。有效期无法核实时明确标记未知。

父级关系需验证父级存在、体系一致、层级相邻、有效期相容，禁止自指和环；未核准的映射保持待补。查询可分别筛选宽基、全部行业、申万一级、申万二级，并通过父级关系生成行业树。历史分类展示按观察日期匹配目录有效版本；当前目录导航使用当前版本，两种查询口径明确区分。为类别／体系／层级筛选及父级查询建立适用索引。

### 5.2 估值宽表 `index_valuation_observations`

宽基、各行业层级及已纳入的策略／主题指数统一存于此表，不按类别或层级另建估值事实表。事实只关联稳定 `index_code`；`index_type`、`classification_system`、`industry_level`、`parent_index_code` 从目录解析，避免重复存储后产生不一致。日频与月频、不同提供方和口径仍分别保存为独立记录。

采用一行一个**指数 × 观察日期 × 提供方 × 稳定序列键 × 频率 × 定义版本**，同一响应中且同一统计口径的多个估值指标放在列中。来源接口或统计口径不同，保留为不同记录，不能合并成貌似同口径的一行。

建议列：

```text
id, index_code, provider, series_key, observation_date, frequency,
pe_source, pe_dynamic, pe_static, pe_ttm, pe_rolling,
pb, ps, ps_ttm, dividend_yield,
definition_version, content_hash, version, is_latest,
batch_id, source_id, obtained_at, updated_at
```

建议唯一键：`(index_code, provider, series_key, observation_date, frequency, definition_version, version)`；另用部分唯一索引保证每个不含 `version` 的对应组合只有一个 `is_latest=1`。唯一键维度均非空，`version>0`，`is_latest` 为 0/1。行内各指标可空。PE 允许有效负值，不应对估值指标统一施加正数约束。建表前根据来源实际字段决定是否保留 `pe_rolling`、`pe_ttm` 独立列；未经证实二者相同前应分开。

`series_key` 表示稳定的接口数据集及统计口径，例如乐咕 PE 普通、PE 等权、PE 中位数和 PB 普通是不同序列。不能用每次变化的 `source_id` 充当序列键。同一响应中的普通、等权、中位数或不同股本口径分行，可共享来源引用；PE/PB 分属不同接口时各写一行，用不同序列键避免同提供方唯一键冲突，再由查询层按明确规则组合。查询展示需保留每个指标的序列及来源，不能隐式混合口径。

### 5.3 指标定义与版本规则

在随版本管理的配置中登记 `(provider, series_key, definition_version)`，每个事实记录必须能解析到对应定义；将来可迁入定义表。本期定义至少包括接口/数据集、原始字段、目标列、指标含义、统计方法、利润期间、股本口径、原始单位与存储单位、转换公式、有效零负值及特殊值处理规则、依据和已确认/待核对状态。不能只保存一个无法还原映射的版本字符串。

- 乐咕普通、等权、中位数分开登记；中证 PE1/PE2 及股息率1/2按各自股本口径分序列，不能映射为静态/动态差别。
- 申万 `pe` 在利润期间未核准时存 `pe_source`，展示为“来源披露 PE”，不强行填入静态、TTM或滚动列。
- PE/PB 等倍数保持来源倍数；股息率统一存百分数（如 2.5 表示 2.5%），仅在原始单位核准后转换，待核准值保留在原始响应中，业务列留空。
- 月频样本若带有尚未结束月份的最新观察点，保留真实日期，并在序列定义中标明更新行为，不能把该观察点伪称为已结束月末。
- `content_hash` 根据规范化指标值及定义计算，不包含请求时间、来源 ID、压缩文件或其他运行元信息。相同值及定义再次获取不增加事实版本，公共来源记录仍保留；事实保留原发布来源引用。
- 已知定义内的真实修订新增版本，保留旧版本。定义版本变化形成独立组合，查询必须明确选择定义，不能因多个定义各有 `is_latest=1` 而混用。
- 来源明确、合法地撤回值时以空值新增版本并保留原因；字段缺失、结构变化或解析异常视为失败，不静默覆盖有效事实，也不以前值冒充此次观测。

## 6. 初始全量和增量流程

### 初始全量

1. 先完成公共字段兼容映射、稳定序列键和指标定义，再以小范围真实来源样本完成隔离演练，随后启动十年采集。
2. 按每个候选来源获取指数目录，记录指数代码、名称、类别、层级、已核实有效期、实际粒度及指标字段；未知信息单独标记。
3. 日期窗口采用滚动十年：以上海时区运行日期减十年为起点，包含起止日，截止到来源已发布的最近完整交易日；闰年 2 月 29 日减年后取目标年 2 月最后一天。以 2026-10-11 为例，范围为 2016-10-11 至 2026-10-09，不使用当年 1 月 1 日作为窗口起点。实际任务重新核对交易日历和来源发布时间。
4. 以第 2.1 节九个中证日频指数和十二个乐咕月频候选为首批已确认集合；运行时复核实际窗口与字段，并继续验证尚遇403的中证候选。本次不将 `theme` 指数加入目录请求、历史回填或增量队列。目录名称、基日、发布日期不能代替可取得估值范围，来源回溯历史需与发布后数据区分。
5. 分来源、数据集及实际粒度建批次。日频请求按日或月分段，接口返回全历史时保存完整响应后按窗口筛选；分段边界及恢复进度写入范围和结果中。
6. 使用薄采集适配层统一实现超时、限速、重试、原始响应及逐页留痕。AKShare DataFrame 仅可作字段映射参考或核对结果，不能重新序列化后称作原始响应；底层 HTTP/SDK 请求须捕获实际响应/返回对象，并在 `hash_basis` 区分网络原文与 SDK 返回对象的规范化序列化内容。
7. 校验代码、日期、交易日历、边界占位、重复项、分页总数/页数/实际行数一致性、字段、单位及数值。原始响应中的休市日/占位记录留在异常报告，不发布为交易日事实。403/429时停止当前来源的批量请求并冷却，不连续重试或判定无数据。每段先完成校验，再在短事务中发布事实和完成该批次，不能等十年数据全部采完才一次发布；财务域现有四表共同发布规则不在本期改变。
8. 汇总各段的指数/序列/指标起止日、返回行数、缺观察日、缺指标数和分类变化，失败请求及覆盖缺口照常保留。完成执行不等于全区间完整。

### 请求间隔、限速与反爬响应处理

本期指数采集须在统一请求入口执行以下保护，适用于初始全量、日常增量、历史抽查、目录、分页、重试及获取 cookie 等实际网络请求，不能只在外层指数循环加等待。以下为保守的初始配置，不是提供方承诺的安全阈值；遇到拒绝访问即停止，不保证仅靠间隔就不会被限流。

- **同源串行**：同一提供方默认并发为1。其不同接口、批次、分页及重试共享请求预算；同源不同主机的公开文件下载也不另开并发队列。防止多个采集任务分别限速却合计形成突发请求。
- **明确间隔**：每次请求完成后，下一次同源请求至少等待10秒，再增加0—5秒随机延迟；同时限制任意滚动60秒内最多5次请求。分来源可配置，遇到更严格的官方要求按更严格规则执行，不因一次成功自动提速。
- **分段休息**：同源每完成20次实际请求额外休息60—120秒；长时间全量采集保留分段进度，允许停止及后续恢复，不为赶进度缩短间隔。有效缓存复用不发请求、不消耗网络预算；失效缓存重取仍经过统一限速。
- **有限重试**：普通超时、连接失败和明确的临时服务器错误，每个请求最多3次尝试（含首次），两次重试至少分别等待60秒、120秒并增加少量随机延迟，再经过正常限速。结构变化、业务参数错误不盲目重试。
- **拒绝访问即停止**：HTTP 403、429，或HTTP 200但返回验证码／访问频率提示／反爬HTML时，立即停止该来源本轮所有后续请求，取消其排队重试，保留状态、原始响应及恢复进度。不得继续轮询其他指数、接口或主机来规避限制；不使用代理轮换、IP轮换或验证码绕过。
- **冷却跨任务生效**：记录来源、原因和 `cooldown_until`，新批次及重启后同源任务也遵守该截止时间。默认至少冷却1小时；服务器提供 `Retry-After` 时按秒数或HTTP日期解析，并取不早于服务器要求的时间。冷却到期不自动重跑全量；后续任务只发一次正常验证请求，仍被拒绝则停止并延长冷却，恢复有效响应后才按保守速率续采。
- **记录与展示**：批次 `result_json` 登记有效限速配置、已请求／重试次数、停止原因和冷却截止时间，来源记录保留每次尝试。因限流停止按失败及已确认的覆盖状态记录，待采分段明确列出，不标记为指数不存在或完整覆盖；其他来源可独立继续。等待和冷却支持取消，不持有SQLite写事务。

实施时用可替换的时钟及模拟响应验证间隔、预算和冷却，不通过大量真实请求测试封禁阈值。未来旧采集统一改造时复用此机制，本期不因此扩大旧采集迁移范围。

### 覆盖率判定

- 覆盖分母为窗口与已核实指数有效期交集内，该来源/序列应有的观察日期。日频依据交易日历，月频依据来源已确认的观察规则，不按所有交易日计算月频缺口。
- 有效期或来源观察规则未知时，预期数量与覆盖率为未知；只报告已观察范围、行数和已确认缺口，不通过首末观测推断有效期或完整率。
- 分开统计“指数尚不存在”“来源不支持该指标”“请求失败”“来源明确返回缺值”“结构/解析异常”“待核对”。未支持指标不计为请求失败；某段没有返回记录也不能直接判断指数不存在。
- 指标覆盖率按序列和指标分别计算；只在明确分母且全部应有观测通过校验时标记 `complete`。返回空数据需结合适用范围说明，不能标记完整。

### 日常增量

- 日频来源每个交易日检查发布情况并增量采集，重叠检查最近 5—10 个交易日（可配置）；来源尚未发布时记录待发布并允许重试，不将缺值补零。
- 月频来源按实际发布节奏复查当前月及最近三个已结束月份（可配置），全历史接口取回后比较相应观察点；不套用日频重叠窗口，也不制造日频事实。
- 近期重叠只覆盖近期修订；默认每月轮换抽查较早月份，季度复核覆盖汇总，发现差异后扩大对应序列的复查范围。频率和请求量按来源限制配置。
- 值未变化时不重复增加事实版本；修订、撤回及解析失败按第 5.3 节规则区分处理；重跑及缓存恢复保持幂等。
- 周线按日线每周最后交易日派生，不重复存储。来源为月频的宽基只按月频展示，不制造日频数据。
- 一次操作可产生多个公共批次，批次间可独立成功/失败，操作总状态由页面编排层汇总。

## 7. 验收标准与非目标

- 初始盘点能列出全部已纳入指数、来源、粒度、指标、起止日和覆盖率；未覆盖指数不能被标记为完整。
- 宽基、申万一级／二级及策略／主题指数的存储结构可共存于统一估值事实表；目录类别／体系／层级分别存储，非行业层级为NULL。隔离样例验证分类筛选、父级树、无自指／环，以及分类变更后按观察日期匹配历史目录，不能用当前层级改写历史展示；主题指数只用合成样例验证扩展性，不实际请求或采集。主题半导体与正式行业半导体可按定义区分。
- 来源覆盖清单区分中证十年滚动PE、乐咕月频PB及中证近期／最新快照，不将旧 FundDB 示例或未验证的历史PB／股息率接口标为本期可用来源。
- 每条估值事实都能通过 `source_id → collection_sources → collection_batches` 回溯，原始响应哈希可复核。
- 同一指数、日期、提供方、稳定序列键、粒度、定义版本不会出现重复“最新值”；同提供方的 PE/PB 分接口可并存，普通/等权/中位数及不同股本口径可并存，不同来源/口径不覆盖。
- 每个事实能解析指标定义、原始字段及单位；未经核准的申万 PE 不映射为静态/TTM/滚动，股息率百分数转换有可复算样例。
- 请求成功而解析失败、重试、空响应、失败批次内成功来源均可追溯；错误的事实来源/批次组合被拒绝，原始响应和落盘文件按各自哈希对象复核。
- 隔离演练验证分段中断恢复、重复采集不增加事实版本、真实修订/合法撤回保留版本，以及分页异常不发布候选事实。
- 覆盖中证实测的 2018-06-18 休市行及历史请求边界占位：原文保留、异常可查、交易日事实排除；403/429不被误判为不存在指数或空覆盖。
- 模拟请求验证同源并发1、至少10秒加随机延迟、滚动60秒最多5次及分段休息；分页／辅助请求／重试不绕过统一预算。模拟403、429、验证码HTML后不得继续发送同源请求；`Retry-After`、跨任务／重启冷却、单次恢复验证和可取消等待均符合上述规则，不用实测封禁阈值验收。
- 维护页能自动发现新表，显示用途、分类、记录数、大小及真实采集时间依据；空数据不以交易日/观察日推算更新时间。
- 公共表兼容性验收使用隔离样例验证旧字段完整表达、财务批次一对多映射、同号 ID 区分、价格批次去重键/名单引用、逐来源信息、路径基准转换、哈希对象及未知元信息；不要求实际迁移历史数据或修改旧采集流程。
- 维护页更新时间依据只使用真实记录；缺失时间明确显示“未记录”。验证资料归档至 `data/verification/samples/`、`reports/`、`tools/` 等相应目录，完成测试后清理临时数据库及一次性资料，保留来源样本和验收报告。
- 本期不迁移旧批次/来源/事实外键，不开发旧采集读写器改造；旧采集迁移作为后续独立任务。
- 本期不采集主题指数；保留 `theme` 类别及通用存储支持，不将主题数据获取列入本期验收。
- 本期不计算指数营收，不回推历史成分，也不把申万行业流通市值当成指数总市值。
