# 决策记录

## 2026-11-07：第一版范围

- 用户选择无黑窗启动、托盘常驻、默认浏览器打开现有页面，本轮要求写计划。
- 本轮只创建计划资料，不实施、不安装依赖、不重启后台。默认单代理，未授权协作开发。
- 第一版使用项目 Python 环境的 pythonw.exe 与快捷方式，不做独立网页窗口或 EXE 打包。这样先完成日常使用入口，同时控制依赖、常驻进程与实施范围。
- 托盘采用 pystray/Pillow，桌面依赖独立于普通 CLI 安装；实际版本在实施时验证并固定。

## 2026-11-07：状态与实例归属

- 后台和托盘在同一进程；runtime 唯一拥有 HTTP、Scheduler、恢复循环和生命周期状态，托盘只通过显式控制契约操作。
- 保留原数据库文件锁；额外的 Windows 桌面互斥量/激活事件只负责跨重复启动的桌面实例身份与唤起，完整桌面生命周期内持有，不替代原数据锁。
- 第二次桌面启动通知原实例打开页面并退出；遇到旧 CLI 后台或未知端口占用明确报错，不自动终止进程、不未经身份确认接管。
- 关闭浏览器仅关闭页面。用户显式从托盘退出才请求结束后台。

## 2026-11-07：退出与可观察性

- 第一版有活动任务时拒绝退出，提示用户通过原业务入口完成/停止；不新增托盘强制退出或采集控制。
- 空闲检查与关闭任务准入必须协调，复用原门禁和服务实例。恢复中不允许中途终止发布；初始化/恢复时的停止竞态必须定向验证。
- 无控制台日志在业务导入前建立，保存原 print/HTTP 错误及未处理线程异常；日志按大小轮转，失败用原生错误提示兜底。
- pythonw 改变 sys.executable，必须验证已有拼音短命子进程；只在证据表明需要时修改解释器选择。

## 2026-11-07：内存与验收

- 不将此前的内存量级估计写成项目实测结果。用同环境、同负载顺序比较 Working Set 与 Private Bytes，并将浏览器单独列出。
- 空闲 Private Bytes 增量约 30 MiB 为初步调查线，超出需要解释；不是已测保证。控制目标是避免第二个常驻 Python 和网页引擎，保留原空闲回收行为。
- 自动测试隔离数据和端口；最终人工验收在宿主机 8765 与原数据库完成。首次切换先核对原进程和活动任务，验收结束保持托盘后台运行。

## 2026-11-07：实施与验证补充

- 用户已明确要求执行，授权必要代码、依赖安装、快捷方式创建及安全切换；本任务继续单代理。
- RuntimeControl 单独位于 runtime_control.py，通过标准 server.service_actions 确认循环已实际运行；停止请求只置状态，shutdown 线程从运行循环中创建，避免初始化期间 shutdown 死锁。
- 退出 SQL 放 maintenance/runtime_activity.py，application 只组装现有内存工作线程与该查询。原 RequestGate 覆盖请求、维护关键区、调度和归档线程；冻结后再检查脱离 HTTP 的业务工作。
- ExitStack 确保单个清理异常不跳过其余资源释放。清理异常记录到控制对象，托盘保留失败现场并拒绝宣称安全退出；调度恢复在工作线程启动前失败时避免 join 未启动线程掩盖原异常。
- pythonw 下中文拼音 JSON 管道测试通过，无需修改 stock_search.py。pystray 0.19.5 与现有 Pillow 12.1.1 已实际验证。
- 已通过真实桌面快捷方式启动 pythonw，HTTP 和实际重复启动验证通过。图形 UI 自动化因无法可靠确认当前浏览器 URL 被安全机制停止，未绕过限制；实际托盘右键/点击及关闭浏览器操作未完成现场验收，离线菜单/退出控制与真实进程安全停止已有测试。
- 实测启动空闲额外工作集约 8.28 MiB、Private Bytes 约 4.74 MiB；相同 HTTP 读取后额外约 7.48/2.01 MiB。未实测一小时后的回收，也未完成浏览器进程内存对比，不扩大结论。

## 2026-11-07：追加重启后台

- 用户明确要求增加托盘重启；采用完整 Python 进程交接，确保加载磁盘新代码，不在旧进程内 reload 或仅重启 HTTP 线程。
- 重启复用安全退出门禁；有业务任务、维护/恢复或清理异常时不自动重启。并发退出/重启以首次成功接受的操作为准。
- 桌面入口在旧资源清理后启动等待旧 PID 结束的同环境 pythonw 替代进程，保留端口且不再打开新浏览器标签。替代进程在等待完成前不打开业务数据库或日志，不持有桌面实例锁。
- 进程等待/启动归 desktop/restart.py，菜单意图归 tray.py，命令行参数及交接归 desktop_app.pyw；runtime 与领域状态所有者不变。

- 开发用命令复用 Windows 同会话命名事件机制，统一经托盘安全重启。命令不启动实例，接收方保留任务忙时的拒绝逻辑。

## 2026-11-07：精简 HTTP 日志

- 按用户要求，在 HTTP Handler.log_request 使用实际响应状态过滤小于400的正常/重定向请求，不在桌面日志流中用文本规则猜测状态。
- 失败状态、log_error、线程异常、启动/任务/重启日志仍保留；认证回调路径继续全面屏蔽；轮转容量与已有历史不变。
- 轮转测试必须mock原生错误框，并断言错误列表为空；模拟写入失败的专项用例也只收集提示，不操作用户桌面。Windows沙箱改名限制导致的环境失败仅在项目短路径隔离目录重跑。
