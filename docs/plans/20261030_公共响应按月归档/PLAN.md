# 公共响应按月归档计划

状态：已实施并部署至宿主机 8765；计划默认关闭，尚未执行真实文件归档。测试基线及验收详情见 PROGRESS.md。

## 目标和范围

减少 `data/collection_sources/` 下公共来源响应的散文件数量，保留每次来源记录、原始证据与可追溯性。后台维护新增「响应归档」tab，提供手动归档和默认关闭的月度计划。已有 `.raw.gz` 已压缩；本功能以减少文件数量为目标，不承诺明显节省字节数，也不改变采集策略。

仅处理登记在公共 `collection_sources` 且存在原始响应文件的证据；不迁移其他旧流程、PDF、备份或未登记文件。`metadata_only`、无响应和未知取得时间分别统计，不能误当成丢失或编造月份。先只读盘点真实路径、引用、时间格式、文件及缺失情况；未登记或异常文件列为待核对，不自动删除。

## 页面与操作

- 在「后台维护」现有标签后新增「响应归档」，不改变「采集管理」默认选中及数据库预览的按需加载。打开页面、预览和刷新均只读本地，不启动归档或来源请求。
- 手动选择截止月份，默认截至北京时间上一个自然月；预览按来源、数据集、月份展示候选文件数、字节数、包数及异常，再明确执行。服务端重新校验范围与候选，禁止归档当前或未来月份；展示执行进度、结果和错误。重复执行只处理未完成部分。
- 计划设置启用开关、每月日期和北京时间，默认关闭；保存配置不启动任务。启用后归档上月及更早的合格散文件。日期与月末处理须在表单中明确，采用现有月度规则并验证其实际语义。
- 后台停机错过计划时，启动后合并漏跑为至多一次必要执行，记录原计划槽位和实际时间；首次启用或修改设置不追补保存之前的槽位。已完成的月份仍允许迟到文件生成新分卷。关闭计划不取消正在运行的任务。
- 显示最近运行、手动／计划来源、状态、处理数、跳过与异常、归档包列表及实际时间；执行成功与文件覆盖分别展示，不因零候选或局部失败虚报完整。支持键盘和无障碍标签，运行时禁用冲突操作并由服务端保证互斥。

## 存储和读取设计

1. 根据来源实际 `obtained_at` 转换到 `Asia/Shanghai` 后取月，不能用业务日期或文件修改时间。解析不了、缺少时区或存在冲突的历史时间先报告，实施前根据真实数据确认可证明的解析规则，不推测。相同文件被多条来源引用时归档一次，并保留全部引用；引用时间冲突须报告而非任意归月。
2. 按 provider／dataset／月份分组，使用带唯一标识的不可变 ZIP 分卷，例如 `eastmoney/bond_zh_us_rate/2026-10-<标识>.zip`。包内保持原始 gzip 文件字节，使用 ZIP 存储模式避免二次压缩开销；每包最多 1000 个文件。后续增量另建分卷，不覆盖旧包。包内清单记录格式版本、原相对路径、成员名、大小及哈希；不能使用不安全路径或重复成员名。
3. 新增一张 SQLite 映射表，暂命名 `collection_source_archive_members`，每行对应一个已归档的原始物理文件。建议字段：原始相对路径、压缩包相对路径、包内成员路径、gzip 文件 SHA-256、gzip 文件字节数和真实归档时间；对原始相对路径设置唯一约束，并约束同一包内成员路径唯一。读取时以 `collection_sources.file_path` 查询映射：多条来源记录复用同一文件时共享同一映射，不为每次请求重复存档；相同内容但路径不同的文件仍分别映射。保留原 `collection_sources.file_path`、`raw_sha256`、`stored_sha256`、取得时间和复用关系，不改事实来源。
   压缩包的格式版本、包哈希、状态及真实发布时间等必要元数据也存入这张映射表，不另建压缩包表；同包多行信息须一致，具体字段与约束在实施盘点后定稿。映射和状态的设计须保证一个路径只有一个有效归档位置，并能识别孤儿包和中断状态。包内清单须能独立核验；不能只靠哈希区分不同请求。
4. 扩展公共来源读取：检查受控路径，读取散文件或映射中的 ZIP 成员，校验 gzip 存储哈希、解压后原文哈希；对缺包、缺成员、重复成员或哈希错误明确失败。需要导出／恢复时只提取指定成员到受控位置，验证后原子写入，不覆盖不同内容。读取不依赖先解压整包。
5. 全仓盘点直接使用公共 `file_path` 的读取、核对、复制、导出及备份调用，适配实际受影响入口（包括国债核对和市场快照相关路径），避免仅修改 `read_source` 后其他流程失效；区分公共文件和旧流程自身路径。复用来源及重新解析保留原取得时间和双哈希。归档、读取、备份和恢复期间须消除删除散文件与并发读取之间的竞态。

## 发布、并发与恢复

- 手动、计划及跨进程执行共享互斥，和数据库恢复／维护门禁、关机生命周期协调。复用现有唯一后台调度器的生命周期和槽位能力，先明确非采集维护任务的适配边界，不伪造来源请求、采集 batch 或新建常驻服务；长时间工作不得持有 SQLite 写事务或阻塞其他采集调度。定时授权仅覆盖本地归档，不扩大网络采集。
- 以分卷为独立提交单元：确定候选并检查路径、引用、大小及原文／gzip 双哈希；写同目录临时包并完整回读核验清单、每个成员及包哈希；安全发布不可变包，短事务登记映射；确认可通过正式读取路径校验后，才逐个删除仍与预览一致的散文件。涉及数据库与文件系统的操作不能假定跨系统原子事务。
- 持久记录必要阶段，使包发布前后、映射提交前后、清理过程中任何中断都可幂等恢复：散文件仍在时优先保证可读；未登记的包不直接删除或覆盖，核验后登记或报告；已登记但文件尚存可安全续清理；发现冲突、损坏或状态不明停止相应分卷并保留证据。运行中新增的来源或复用引用不得丢失；删除前再次验证文件身份与状态。
- 归档包不是备份。SQLite 单独备份不包含响应或 ZIP；明确数据库与源文件／归档包共同备份、迁移、恢复及哈希核对的流程。旧数据库快照可能只认识散文件：实施时设计并验证与旧快照组合的恢复方案，不能默认为 SQLite 恢复后映射仍然存在；无法证明一致时阻止清理或明确提示并提供可验证恢复方法。

## 验收

- 隔离数据库和目录覆盖不同来源／月份、跨北京时间月界、重复路径与复用、相同内容不同请求、失败响应、`metadata_only`、无时间、缺文件及时间冲突；归档前后双哈希、来源 ID、引用及事实一致。
- 覆盖重复运行、跨进程互斥、并发读取和新增复用、临时包／发布／数据库提交／逐文件清理各阶段中断，验证重启恢复、包或成员损坏、路径越界、重复成员、目标冲突和空间不足；所有故障均不丢失唯一有效证据。
- 验证公共读取、受影响的核对／导出／回放、单文件恢复及备份迁移；覆盖归档前旧 SQLite 快照与归档后文件组合，核验可恢复性。对映射、包和散文件做双向盘点。
- 假时钟验证月末、跨年、启用／保存、停机漏跑合并、防重复及手动与计划冲突。页面验证只读加载、预览与执行、默认关闭、状态、异常和无障碍；HTTP／来源边界及相关回归通过。
- 在隔离环境测量大量小文件打包数量、空间、运行时间和随机读取性能；保留验收报告于 `data/verification/reports/`，清理一次性测试资料，不触碰日常库和正式备份。完成后记录实际结果及限制。
