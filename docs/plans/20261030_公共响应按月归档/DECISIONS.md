# 决策

- 2026-10-30：用户明确目标是减少存储文件数量，而非节省存储空间；保留已经单独 gzip 压缩的响应字节及原文／存储双哈希。
- 归档入口放在「后台维护」新增 tab，提供手动和计划操作；手动先预览，计划默认关闭，保存配置不运行。
- 按真实取得时间的北京时间月份、来源和数据集分包，已结束月份可归档；迟到文件使用新分卷。缺失或不能可靠解释的时间不猜测。
- 延续公共来源记录和路径身份，通过映射定位包内文件，读取时校验；归档不等于备份。先验证再清理散文件，必须保证中断恢复和并发安全。
- 明确只新增一张 `collection_source_archive_members` 映射表（暂定名），按原始物理文件路径一行记录压缩包、包内成员和必要包元数据；多条来源记录可共享一个映射。不另建压缩包表，同包重复信息须一致。
- 分卷名使用月份加随机唯一标识，避免中断后覆盖未登记包；每包最多 1000 个成员。计划及运行槽位复用现有表，完整执行报告保存在验证报告目录。
- 计划编写时用户只要求规划；随后于 2026-10-30 授权实施。具体分卷大小、表结构及调度适配方式在只读盘点和隔离验证后确定；不自动启用计划或对真实文件执行历史归档。
