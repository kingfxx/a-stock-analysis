# 全市场三表全字段采集设计

状态：已实施；运行及字段说明见 [全市场三表采集](../data-sources/market-financial-statements.md)。下文保留设计依据，具体行为以实现及运行说明为准。已有表不迁移、不改名；历史区间补采提供独立离线命令，不自动执行。

## 目标与边界

- 在现有行业对比的“更新全市场财务”按钮内，一次采集所选报告期的业绩指标、利润表、资产负债表、现金流量表。
- 三表使用东方财富摘要接口 `columns=ALL`，保存全部返回字段；不将“全字段”表述为财报完整明细。后续接入完整明细接口时另行核对定义，不混写本数据集。
- 现有 `sw_financial_facts`、来源表和页面读取暂不迁移、不改名；新增三表先作为独立来源层保存。
- 不改变个股新浪取数优先级，不把东财原始字段自动覆盖到个股三表。现有行业指标的四字段例外继续遵守项目规定。
- 不生成 baseline JSON，不重复保存合并后的整套数据文件；SQLite 用于查询，原始响应用于核验与重建。

## 接口与覆盖范围

| 数据集 | 接口 | 参数 | 当前样本字段数 |
|---|---|---|---:|
| 利润表 | `RPT_DMSK_FN_INCOME` | `columns=ALL` | 46 |
| 资产负债表 | `RPT_DMSK_FN_BALANCE` | `columns=ALL` | 57 |
| 现金流量表 | `RPT_DMSK_FN_CASHFLOW` | `columns=ALL` | 48 |
| 业绩指标（保留现有流程） | `RPT_LICO_FN_CPD` | 暂沿用现有字段选择 | 已有字段 |

三表统一按 `REPORT_DATE` 查询，业绩指标按 `REPORTDATE` 查询；期末日期只允许季度末。
新三表层统一采集全部 A 股，包括北交所，过滤 `SECURITY_TYPE_CODE="058001001"`。
行业展示继续使用现有沪深名单与申万分类，未分类和北交所记录可入来源层，不因此进入行业合计。
历史补采只代表接口当前可返回的历史报告期，不声称覆盖当年全部上市、退市公司，也不声称是当时已知的财报版本。

## 命名规则

新增全市场财务表统一采用 `market_financial_` 前缀，业务字段统一英文小写下划线。
`sw_` 后续只用于申万分类、成员和行业汇总；已有表改名放到后续独立迁移。

| 建议表名 | 用途 |
|---|---|
| `market_financial_income` | 全市场利润表全字段记录及真实修订版本 |
| `market_financial_balance` | 全市场资产负债表全字段记录及真实修订版本 |
| `market_financial_cashflow` | 全市场现金流量表全字段记录及真实修订版本 |
| `market_financial_batches` | 所选报告期的一次三表采集批次、状态、覆盖统计和时间 |
| `market_financial_sources` | 分页请求参数、原始响应路径、哈希、采集时间及所属批次 |

未来迁移业绩指标时统一命名 `market_financial_performance`，本次不提前建空表。
现有 `sw_update_runs` 继续负责按钮任务与状态查询，通过 `result_json` 引用新批次 ID，不再另造一套任务系统。

三张业务表采用相同结构规则：

- 主键采用独立 `id`；证券身份统一为 `security_code`、`exchange`，保留接口 `secucode`；报告期统一 `report_date`。
- 源字段原则上直接转小写列名，例如 `TOTAL_ASSETS → total_assets`，以实际返回字段为准；建立字段字典记录源代码、名称、类型、单位和适用行业，不凭名称推断枚举或财务定义。
- 财务金额/比例作为可空数值列，代码和日期作为文本列；保留有效零值。未知定义字段照存原值，暂不参与计算。
- 公共管理列使用 `version`、`is_latest`、`batch_id`、`source_id`、`content_hash`、`definition_version`、`obtained_at`、`updated_at`。如与源字段重名，源列加 `source_` 并登记映射。
- 唯一约束为证券身份、报告期、版本；对证券身份、报告期设置唯一的最新记录约束，并增加报告期查询索引。
- `notice_date` 是来源公告日期，`obtained_at` 是实际采集时间，二者不能互相代替。记录首次/最近观察时间也不能冒充首次披露时间。
- `source_id` 引用共享分页来源，不在每条记录重复嵌入请求参数、路径和文件哈希，不另存整行重复 JSON。

具体 DDL 在实施时根据已保存样本和字段类型核对后确定；这一步不创建表。

## 按钮与一次任务的流程

继续使用现有按钮及 `/api/industry/refresh` 的 `action=financial_period`，报告期选择方式不变。
按钮文案保持“更新全市场财务”，确认说明明确列出“业绩指标＋三表全部返回字段”，并分别说明全 A 股采集范围和沪深行业展示范围。
季度市值按钮保持独立，不把市值或个股刷新绑进本任务。

1. 验证报告期、互斥任务锁、数据库可写和磁盘空间；建立运行目录、固定本次沪深分类名单快照。
2. 沿用现有每日最多一次的公司名单/分类检查。检查失败可沿用旧分类并警示，不影响按全 A 股接口采集来源层。
3. 串行采集同一报告期：利润表 ALL → 资产负债表 ALL → 现金流量表 ALL → 现有业绩指标。
4. 利润表 ALL 结果直接供现有行业指标转换使用，不再为相同报告期另发一次利润表部分字段请求。本地新浪仅用于现有允许的指标选择，不覆盖新三表层的东财原值。
5. 保存每页原始响应并校验；完成全部分页后进行记录校验、字段映射和版本比较。
6. 全部必要数据集校验通过后，在同一个 SQLite 事务中发布新三表记录、来源引用和现有行业指标更新，并将批次标为完成；需要拆分现有 `import_bundle` 的事务入口，禁止内部先提交旧表、外部再提交三表。
7. 返回每张表的记录数、缺报公司数、新增/修订/未变化数、原始文件大小和耗时，刷新页面。

进度示例：`资产负债表 5/12 页 · 已获取 2500 家`；完成说明分别列出三表和业绩指标结果。
接口正常完成但部分公司未披露属于缺报，不等同于网络分页失败；记录覆盖情况，不用旧期冒充本期。
某一个接口失败、分页不完整或字段结构未支持时，整个批次不发布，页面继续读原有数据；已验证的原始页保留供重试。

## 限频、重试与缓存

- 复用现有限频：串行、每次间隔 2.5—3.5 秒、每 20 次请求休息 30 秒，失败按现有 60/120 秒退避；不并发请求四个接口。
- 每页 500 条，以证券代码及必要的稳定补充键排序；处理过程中验证页数和总数稳定，并检查重复及缺页。
- 同一运行被中断后允许续跑；缓存键包含接口、字段选择、报告期、范围、排序、页码及解析版本。
- 缓存续跑受有效期限制；默认仅同日同一运行可复用，跨日或来源总数变化时重新采集该接口，避免拼接不同时间的分页。
- 用户新点击“更新”属于重新核对来源，不能永久命中旧缓存而漏掉修订。
- 后台重启后沿用现有失败状态恢复，再由用户重新触发重试；重试可复用有效缓存，不静默自动采集。

## 校验与缺值

- 检查请求/返回报告期、A 股范围、证券唯一性、分页总数、字段集合及单位；新增未知字段先完整保留原始页，再明确报告映射待更新，不静默丢弃。
- 允许 null、有效零和适用的负值；金额解析失败不得转零。
- 三表各自统计可返回公司数和缺报名单，不要求三表公司集合机械相等；明显异常下降阻止发布，阈值按同口径历史覆盖与披露阶段确定，不照搬当前沪深名单的固定比例。
- 资产=负债+权益等关系在适用且字段有效时作为核对警示，考虑精度与行业差异，不把所有关系差异当成接口失败。
- 三表不同 `notice_date` 不强行统一；公告日期不自动解释成首次披露日期。
- 单季、TTM、毛利率等在读取/计算层派生，新表保存源报告期原值；资产负债表为期末余额，利润表与现金流量表通常为本年累计，按字段定义核对。

## 去重、字段扩展与修订

- 无变化：不新增业务版本；更新最近观察时间/来源，并在批次保存已核对记录统计。原始响应按内容哈希去重，保留各次请求和采集时间。
- 字段扩展：已有非空财务值、日期和定义均未变，仅增加之前未采集的字段时，补全当前记录，不制造一套缺字段的历史业务版本；补全字段的实际来源在集中来源结构中留有映射。
- 真实修订：已有财务值、公告日期或定义变化时新增版本，旧版保留。有效值变成 null 也不能当作“补字段”吞掉，先辨别是否结构/解析异常；确认属于来源变化时保存修订，不盲目沿用旧值。
- 公司名称/行业名称等描述变化不当作财务修订；所有源字段均保存，但业务版本哈希与整行源内容哈希分开。
- 删除一条源记录、字段补全或修订不能通过哈希单独判断；补全判断逐字段比较，0 与 null 明确不同。
- 不保存“完全一样但每次点击新增一版”的财务行；不自动清理真实修订或原始来源。

## 原始文件组织

建议位置：`data/market_financial_sources/<report_date>/<dataset>/responses/<sha256>.json.gz`。
数据集目录固定 `income`、`balance`、`cashflow`、`performance`，不再按临时试采名字散落。
共享来源表记录相对路径、原始解压内容 SHA256、请求参数、采集时间、编码及压缩方式。相同内容仅落盘一次，SQLite 保留请求与批次关系。
gzip 保存接口解压后的响应原文，不重新格式化、不再落一份未压缩副本。写临时文件后校验哈希，再原子改名。
运行中的检查点/请求索引只负责续跑，不保存重复的全量合并结果；完成后清理不再需要的临时文件。正式来源和验收报告保留。
本次容量测试的样本目录不自动搬迁、不作为正式业务读取入口；已有来源路径也留到后续迁移统一处理。

## 历史补采与已有表后续迁移

日常按钮仍只更新所选一期，不在一次点击中悄悄补十年。
历史补采使用相同采集、校验、存储入口，提供显式报告期区间的命令行操作，逐期提交、断点续跑；不采市值、不重写分类。
优先从已有可验证原始响应补录字段和历史期；已保存的部分字段响应不能冒充 ALL，缺少完整响应的报告期才联网补采。
已有 `sw_financial_facts` 与来源引用的重构单列后续计划：字段对照、数值及来源核验、备份、页面切换、旧结构清理。此次不与新三表采集一起重构。
未来统一业绩指标来源时仍保留 CPD 采集，三表摘要不能替代 ROE、每股指标等全部需求。

## 实施及验收顺序

1. 固定字段字典、命名、版本判定与样本；新增迁移和统一三表采集器。
2. 在隔离数据库验证三表写入、来源、索引和更新规则；同步登记维护页 `DESCRIPTIONS`、`TIME_COLUMNS`/`PARENT_TIMES`，更新时间使用真实采集/写入时间。
3. 接入现有任务与按钮，保持页面取数及旧表结构不变；完成同一事务发布和失败回滚。
4. 验证分页异常、重试、字段新增、null/0、真实修订、纯字段补全不留冗余旧版、来源去重、并发点击互斥及重启恢复。
5. 验证三表同一报告期全字段可读、记录数与原始响应一致，ROE等旧页面结果及取数优先级不变，维护页用途/分类/数量/大小/更新时间和空表状态正确。
6. 通过相关测试后自动重启并检查日常 8765 后台；用户人工验收仍用日常后台。清理临时数据库、一次性脚本及预览缓存，保留来源、报告和后台日志。
