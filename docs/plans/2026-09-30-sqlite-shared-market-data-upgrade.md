# SQLite 与共享行情数据改造计划（初稿）

日期：2026-09-30

状态：P0/P1 已实施；P2–P5 待实施，具体结果见第 13 节

范围：本地单用户 A 股分析工具的数据存储、更新和复用

## 1. 目标与边界

将按股票、按模块保存的 JSON 缓存逐步迁移到一个 SQLite 数据库。融资数据按日保存并增量更新；股东人数独立更新；所有需要股价的图表通过同一个价格服务取得数据。筹码评估两个图表默认使用前复权价格，并可切换不复权价格。

改造必须保留现有财务、分红、估值计算口径和异步加载体验。一个数据源失败时，其他已取得的数据仍可保存和展示；已有有效数据不能被失败响应覆盖。

初版不做全市场批量采集、分钟行情、交易功能、云数据库、完整历史时点回测或通用指标平台。不引入 ORM；优先使用 Python 标准库 `sqlite3`。旧计划中“不保存完整日行情”的约束，由本计划针对共享价格与融资历史的新需求替代。

## 3. 总体结构

```text
HTTP / 页面接口
    ↓
应用服务：财务、筹码、估值、刷新协调
    ├── 共享价格服务：范围读取、交易日匹配、复权版本
    ├── 更新服务：增量范围、校验、去重、失败恢复
    └── 现有纯计算函数：季度、TTM、估值、图表拼装
             ↓
存储层：业务查询、事务、迁移、备份
             ↓
data/stock_analysis.sqlite3

来源适配器 → 获取候选数据 → 校验 → 更新服务提交
```

建议先增加 `storage.py`、`price_service.py` 和一个更新服务模块；业务复杂后再按领域拆分，不提前建立大量抽象类。来源适配器不直接写数据库，图表接口不自行访问价格源。

数据库是迁移完成模块的唯一持久化事实来源。前端响应 JSON 继续保留；它是接口格式，不再是存储格式。

## 4. 数据模型

### 4.1 通用约定

- 股票代码保存为文本，不能丢失 `000001` 的前导零；股票身份同时包含交易所。
- 交易日期使用 `YYYY-MM-DD`，业务交易日按上海时区解释；获取、检查和运行时间保存为 UTC 时间。
- 金额保存来源原始单位，通常为元；展示时才转换为亿元。整数人数使用整数。缺失值与零严格区分，融资净买入允许负数。
- 常用字段独立建列，来源额外字段保存在逐记录 `raw_json`。不建立“一只股票一张表”，也不把所有业务指标压入通用键值表。
- 来源、解析器版本、计算口径版本、数据库结构版本、前复权版本分别管理，不能用一个全局版本号替代。
- 价格比较按来源精度规范化，明确舍入及容差规则，避免二进制浮点误差触发全量重建。

### 4.2 第一阶段核心表

| 表 | 主要内容 | 主键或唯一约束 |
| --- | --- | --- |
| `instruments` | 交易所、代码、名称、市场等 | 整数主键；交易所 + 代码唯一 |
| `financing_daily` | 日期、融资余额、融券余额、两融余额、净买入及原始字段 | 股票 + 来源 + 交易日期 |
| `shareholder_observations` | 统计日期、公告日期、人数、股东口径、来源记录标识及原始字段 | 股票 + 来源 + 来源记录标识；无标识时制定明确业务键 |
| `raw_daily_prices` | 不复权日行情及可用的 OHLC、成交字段 | 股票 + 来源 + 交易日期 |
| `adjusted_price_versions` | 股票、来源、复权类型、覆盖范围、校验状态、生成时间 | 版本 ID |
| `adjusted_daily_prices` | 某一已完成版本的前复权日价格 | 版本 ID + 交易日期 |
| `sync_state` | 已成功覆盖范围、检查时间、数据水位、活动价格版本、下次全量核对时间 | 股票 + 数据集 + 来源 + 口径 |
| `sync_runs` | 更新范围、触发原因、开始/完成时间、数量、结果及错误摘要 | 运行 ID |
| `schema_migrations` | 数据库迁移编号、应用时间 | 迁移编号 |

业务表按“股票、来源、日期”建立范围查询索引。股东记录保留不同来源和人数口径，展示时选择可比记录；不能因为日期相同就将 A 股股东人数与全部股东人数直接覆盖合并。

`sync_state` 的最大日期只表示数据水位，不证明区间内无缺口。查询和校验还需结合来源覆盖、已知交易日期及缺失状态。合法的“无融资资格/无记录”与请求失败分别保存。

### 4.3 后续迁移表

| 表 | 内容与注意事项 |
| --- | --- |
| `financial_reports` | 财报事实、报告期、报表类型、公告/修订日期、来源原始记录；派生季度和 TTM 保持在计算层 |
| `dividend_events` | 分红事件及状态，优先采用来源稳定事件 ID；不能仅以报告期为唯一键，一年可能多次分红 |
| `valuation_observations` | 实际获取的估值观察数据与口径，不把前复权价格当作真实市值计算价格 |
| `industry_snapshots` | 行业分类与获取时间，避免后续分类变化悄悄覆盖必要的上下文 |
| `report_overrides` | 用户手工修正，保留零值、空值语义及修改来源，不能混入来源事实后丢失身份 |

旧 JSON 如果只保留月度结果或价格快照，迁移时标注为旧缓存数据，不能伪造不存在的完整日行情或原始响应。必要的派生缓存必须关联依赖数据版本和计算口径版本，初版优先按需计算。

## 5. 数据更新规则

### 5.1 融资：日存储、窗口增量、历史保留

1. 首次更新拉取该来源可提供的完整历史，校验分页、股票、日期、重复记录与必需字段后入库。
2. 后续从数据库最后一个有效数据日向前回看 **30 个自然日**，请求至当前可取得的最新日期。
3. 对回看窗口内记录执行 UPSERT，新增日期插入，修订日期更新；窗口外记录保持不动。
4. 候选响应缺失数据库已知日期或关键字段时，先判断来源明确撤回、分页遗漏还是异常响应；不能把缺失直接当作删除。
5. 全部候选数据校验通过后，在同一事务提交业务记录与成功水位；失败保留旧数据和原成功水位。
6. 图表使用按日期过滤的数据库查询展示最近 365 天，历史记录不因图表范围缩小而删除。

东方财富融资接口已验证可用日期过滤缩小返回范围；实施时仍需补充分页边界和修订场景验证。30 天回看不能覆盖所有更早修订，因此增加定期全量核对和手动重建入口。

### 5.2 股东人数：事实独立，口径明确

股东人数按来源统计日期保存，另存公告日期。F10 与明细来源各自留存，定义来源优先级前先验证人数口径是否相同，尤其是 A/H 股票。无法确认口径的记录标注未知，不能无提示连接到另一条统计口径曲线上。

股东人数可以先更新成功，再异步取得匹配价格。价格失败只影响价格曲线，不回滚已验证的股东事实。价格默认匹配统计日当日或之前最近的交易日，最大回退 15 个自然日；超限显示缺失，并保留实际匹配日期。

### 5.3 原始字段与修订

`raw_json` 保存本次来源真实返回内容；规范化字段如需沿用旧值，必须记录该值的来源运行或时间，不能把拼接后的记录称作本次完整原始响应。

- 必需字段缺失：拒绝受影响批次，保留旧数据。
- 可选字段缺失：允许按字段规则保留旧的规范化值，并记录不完整状态。
- 来源明确将字段修订为空：按该来源契约处理，不能用统一 `COALESCE` 永远保留旧值。
- 原始扩展字段需要合并保留时，保存独立的规范化扩展内容及沿用信息，不能只保护图表当前用到的几个字段。

记录内容哈希用于识别变化。无需永久重复保存每次完全相同的响应；运行日志保留结果摘要，重要修订保留必要追溯信息。

## 6. 共享价格服务与前复权更新

### 6.1 服务职责

所有图表按股票、来源、复权口径、日期范围请求共享服务；服务负责覆盖检查、获取、版本选择和日期匹配。缓存身份不包含图表名称。

| 消费方 | 取价规则 |
| --- | --- |
| 财务图 | 沿用披露日期匹配规则；保留既有长间隔参考价格语义 |
| 股东人数图 | 统计日及之前最近交易日，超出最大间隔不填充 |
| 融资图 | 同一交易日对齐，显示最近 365 天 |
| 估值价格曲线 | 所需月份的最后有效交易日 |
| 股息率、市值等计算 | 使用相应计算口径要求的不复权价格，不能误用前复权价格 |

并发请求同一股票同一价格口径时共用进行中的任务。已知需求范围先合并，后来的请求先复用已完成覆盖，再补足缺少范围。请求去重依靠应用层协调，数据唯一性与提交一致性依靠数据库约束和事务。

### 6.2 前复权更新算法

用户提出的“首次全量、后续比较近期、变化则重建”作为主体方案，但近期比较是变化检测手段，不是全部历史未变的证明。

1. **首次**：抓取来源可用且满足业务需求的全部历史，记录实际覆盖范围、来源与口径，校验后发布首个版本。
2. **后续**：获取数据库尾部至少 **20 个已有交易日**对应的来源价格，以及之后新增日期。不是仅查询最近 7 个自然日。
3. **对齐比较**：只在相同交易日期之间比较，统一精度。新日期的出现本身不属于历史价格变化。
4. **已有日期均未变化，有新日期**：复用已有历史，仅追加来源新记录，发布新版本。
5. **已有日期均未变化，没有新日期**：只记录检查成功，不重写价格历史。
6. **已有日期发生变化**：重新获取该股票完整所需前复权历史，校验并发布新版本。
7. **重叠不足或无法确认口径**：扩大查询；仍不能确认时全量重建，不能直接拼接。
8. **获取或校验失败**：继续使用上一个有效版本，提示更新失败，不推进成功水位。

程序长时间未运行时，需要主动回到数据库尾部取得重叠数据；单纯查询“今天之前 20 个交易日”可能与旧库没有交集。

增加少量更早的历史锚点核对，例如各年度最后一个交易日；实施前确认来源取点开销，若每次取点仍需全量下载，则不把它包装成廉价增量检查。锚点也无法发现所有局部修订。

建议每 **30 天**进行一次全量核对，并支持用户手动重建。到期任务在应用运行和相关股票刷新时执行，初版不额外安装后台定时任务。频率可配置，按实测请求成本调整。

### 6.3 前复权版本一致性

前复权版本是校验完成后的本地快照。初版保存当前版本与上一版本，使用中的旧版本延迟清理，避免无限累计。

为降低实现歧义，初版采用以下方式：无变化不创建版本；仅追加时用数据库内复制旧版本并插入新日期建立候选版本，不重新下载旧历史；重建时写入完整候选版本。候选数据校验完成后，在短事务中切换活动版本指针。后续如实测复制成本过高，再优化存储布局。

网络请求在事务之外完成。候选版本不可被正常查询选中。前复权历史可能存在零值或负值，不能沿用筹码旧快照的“价格必须大于零”校验。

来源分页也必须验证：不同页的重叠交易日、不同结束日期请求的同日期价格应符合统一复权基准；本地赋予同一个版本号并不能证明来源一致。若当前价格源无法满足要求，先解决来源或复权因子方案，不能发布混合口径数据。

页面加载时获取共享价格版本标识，各异步接口固定读取该版本。刷新产生新版本后，前端统一更新相关价格曲线；刷新过程可继续显示旧版。股东、融资等事实可先更新，接口明确返回事实时间与价格版本时间。旧版本已清理时返回可识别状态，让前端重新协调版本，不能静默改用另一个版本。

筹码两图默认前复权，可切换不复权；标题、图例、悬浮提示明确口径，并保存用户选择。不同股票切换时丢弃旧请求结果，避免异步响应串到新股票页面。

## 7. SQLite 运行、并发及备份

本机已检查的运行时为 Python 3.10.0、SQLite 3.35.5。选择 WAL 前必须检查实际加载的 SQLite 版本，不能只根据 Python 大版本推断。

SQLite 官方记录了 WAL-reset 并发缺陷，修复版本包括 3.51.3，以及回移修复的 3.44.6、3.50.7。实施时核验实际发行版是否包含修复。优先选择包含修复的运行时后开启 WAL；保留旧运行时则使用 rollback journal 和短事务串行写入作为兼容方案，不直接替换系统 DLL。

- 每个请求或工作线程自行管理连接并及时关闭，不共享一个跨线程连接。
- 每个连接启用外键检查，设置合理 `busy_timeout`；网络请求不占用数据库写事务。
- 业务数据与成功同步状态在同一事务提交。失败运行日志单独记录，失败不能被记作成功更新。
- 候选提交前检查所依赖的数据版本；若被其他更新抢先修改，则重读或重新计算，防止旧任务覆盖新结果。
- 初版以单应用实例为支持目标，启动时检测重复实例；进程内锁只用于去重，不能替代数据库正确性机制。
- “今天检查过”不能直接等于“今天不用更新”，应结合数据日期、检查间隔和数据源发布时间。

使用 SQLite Backup API 生成一致备份，不直接复制正在运行的数据库文件。保留迁移前备份和最近 7 份日备份；验证恢复后数据、版本指针和同步状态一致。

数据库、`-wal`、`-shm`、journal 文件及备份加入 `.gitignore`。Git 同步代码，不同步运行中的数据库；跨电脑搬迁使用备份/导出文件并验证恢复。数据库放本地磁盘，不放网络共享目录作为在线数据库。

## 8. 旧数据迁移与回退

1. 盘点每类 JSON 的路径、结构版本、股票数量、记录数、日期范围、异常文件和手工覆盖数据。
2. 生成迁移前备份，建立空数据库并执行结构迁移。
3. 按数据集导入，保留源文件路径和内容哈希作为迁移记录；同一文件重复导入不得增加重复记录。
4. 验证记录数、日期范围、字段值、单位、空值语义及图表响应。原始历史不完整的缓存明确标记覆盖限制。
5. 单个数据集通过验证后切换读写到 SQLite；其旧 JSON 保留为只读备份。
6. 所有模块迁移通过后移除 JSON 正常运行路径；保留明确的导入工具，不长期维护双写。

迁移失败不切换该数据集。切换后若需回退，先停止写入并备份数据库，再根据阶段恢复旧版本与对应缓存；若 SQLite 已有新数据，先导出兼容快照，不能让回退静默丢失新增数据。前复权等新增能力旧版不支持时，明确功能回退范围。

损坏 JSON 单独报告，不能导致其他正常股票无法迁移，也不能把损坏文件视为空数据成功导入。

## 9. 实施阶段与交付门槛

## 10. 验收清单

### 数据正确性

- 现有测试基线继续通过；上次已有 163 项通过，实施前重新确认实际基线。
- 融资零余额、负净买入、非融资标的、字段缺失、重复日期、错误股票和缺页均有明确处理。
- 增量更新不删除窗口外历史，旧日期修订能更新；候选漏掉已知日期时不能静默成功。
- 股东统计日、公告日、价格实际交易日分别保留；A/H 人数口径不混合。
- 财务、分红、TTM、ROIC 和估值结果保持既有口径；手工零值和空值不丢失。

### 前复权与复用

- 覆盖首次全量、无变化、有新日期、历史变化、无足够重叠、长假及长时间离线场景。
- 覆盖旧锚点变化、周期全量核对、零/负前复权价、不同分页基准不一致场景。
- 同股票并发图表请求不各自重复抓取完整历史；已覆盖区间直接读库。
- 重建失败继续使用旧版本；切换版本时多个图表不会静默混用前后两套价格。
- 价格匹配不使用目标日期之后的数据，停牌超限不无条件填充。

### 存储、迁移与体验

- 模拟提交中断，业务记录与成功水位保持一致；并发更新不丢失较新结果。
- 重复导入幂等；坏文件不影响其他数据集；源文件保留直至验证通过。
- 备份恢复后不仅通过完整性检查，还验证活动版本、业务数据和同步状态。
- 代表股票包含 `601919`、`600887`、`000001`，补充非融资标的、长期停牌和发生除权的样本。
- 页面切股、刷新失败和部分数据缺失时提示准确，已存在有效数据继续显示。
- 测量首次加载、缓存加载、融资增量、前复权追加及重建耗时和请求次数。先实测再定性能指标，不承诺未经验证的固定延迟。
- Python/SQLite 支持组合在文档中明确，并进行另一台电脑的启动及数据恢复验证。
