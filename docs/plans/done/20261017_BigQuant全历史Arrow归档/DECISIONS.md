# 决策

- 复用 BigQuantSDK.call/instrumented，只跳过其额外的 Parquet 输出层。
- 公共提供方仍为 bigquant，归档 dataset 沿用适配器已有 market.trade_snapshot.bigquant_inputs，实际范围/表/用途写 scope 和本次独立清单。
- 日期范围先探测，不把用户记忆中的2005年作为已核实起点。逐日计数作为下载传输完整性基准，历史证券名单覆盖仍未知。
- 每个完整年度一个可恢复分段；此次不覆盖或删除既有20天归档。
- 用户追加要求优先近期数据：当前在途段结束后，改为2026、2025、2024逐年倒序，避免额度先消耗在早期年份。
- 2026整年1037391行的Flight传输出现Unavailable，遵守最多3次有限重试后停止该段。后续新增年度超过60万行时拆为季度，季度亦倒序；已验收年度文件复用，不重下。
- 补充原始异常诊断后确认2026Q1的Unavailable实际为「数据配额不足」，不是网络错误；此前全年/Q2异常原文未捕获，不能断言其原因，不能将这些失败当作来源行数上限的证据。
- 来源明确本周配额50000000、已用45309716、此次请求4911296（306956行×16字段）。剩余4690284；不再拆分探测，按公共拒绝规则立即终止并登记至少一小时共享冷却，不建自动续跑。
- 公共SDK调度补充配额拒绝关键词识别，避免FlightUnavailable外观触发普通连接重试；新增隔离回归测试。
- 源拒绝立即停止；不规避冷却或SDK既有访问窗口。
