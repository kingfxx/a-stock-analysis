# 公司快照发布后的行业季度市值汇总方案

状态：已实现并通过隔离库验证；历史期未回填；8765 已重启并完成页面/API验收。

## 目标与范围

每个季度的公司交易快照完整校验、发布并冻结季度成员后，使用本地 `market_trade_snapshot` 计算三级行业市值，按审计版本追加到现有 `sw_industry_cap_quarters`。页面行业总额和覆盖率直接读取汇总结果，减少首次读取和缓存失效时的全历史公司快照聚合。

复用 `sw_update_runs` 管理任务、`collection_batches/sources` 管理公司快照采集、`sw_imports` 记录汇总审计版本。不新增控制表，不新增业务表，不额外请求数据来源。第一版不增加汇总表字段。

公司列表市值、PE、PB仍读取公司快照和财务资料；行业同比继续使用现有共同成分算法。已存在的历史汇总行保留并继续作为尚无新汇总版本季度的页面数据；以后季度快照发布成功后，以本方案的新审计版本替代该季度的历史汇总显示。

## 已有结构与约束

- `sw_industry_cap_quarters` 主键为 `(import_id, industry_code, quarter)`，已有期望数、有效数、已知金额、完整金额、交易日、目标日和名单口径字段。
- `sw_imports.content_hash` 唯一，状态仅允许 `complete`；适合记录成功发布的汇总版本，失败进度仍记录在现有任务中。
- `sw_cap_quarter_rosters` 保存季度目标交易日、名单口径和冻结名单版本，`sw_cap_quarter_members` 保存该季度固定公司及三级行业归属。
- 当前 `foundation()` 和页面从最新 `sw_imports.member_import_id` 获取当前名单。汇总审计记录必须保持这个当前名单指针，不能使用历史季度冻结名单替换它。
- 当前维护页通过 `sw_imports.obtained_at` 关联汇总表时间；新汇总版本的该时间记录实际汇总发布时间，不使用交易日。

## 数据选择与计算

每次处理一个明确季度；目标交易日与冻结名单来自 `sw_cap_quarter_rosters`。不存在冻结名单时先沿用现有 `freeze_roster()` 创建，再计算。名单创建失败时不发布汇总。

公司市值仅取 `market_trade_snapshot.total_market_cap`，精确匹配证券、交易所和目标交易日，并在最新版本中按以下定义优先级选择有效值：

1. `em-valueanalysis-v1`：东方财富原始快照。
2. `historical-suspended-preclose-v1`：经核验的停牌参考价估值。
3. `historical-composite-v1`：历史合成快照。

每家公司至多计入一次；不读取 `sw_cap_facts` 或 `market_quarterly_prices`。只核对市值有效性，股价缺失不导致已有有效市值被排除。零值或负值按源指标已实现的有效性定义处理，不新增以正数过滤的规则。

按季度冻结名单中的三级行业分组：

| 汇总字段 | 计算方式 |
| --- | --- |
| `expected_count` | 该行业冻结名单公司数 |
| `known_count` | 其中有有效目标日总市值的公司数 |
| `known_cap` | 有效公司总市值之和；没有有效值时为 NULL |
| `total_cap` | `known_count == expected_count` 且有成员时取 `known_cap`，否则 NULL |
| `trade_date` / `target_date` | 固定季度目标交易日 |
| `composition` | 沿用季度名单的原口径 |

名单中无行业归属的公司单独计数并记录，不能静默归入其他行业。未出现成员的行业不新增伪造的零市值行。源请求完整与公司市值覆盖完整分别记录；明确空期可以生成有效数为零的覆盖记录，但金额保持 NULL。

一级、二级总额继续由三级汇总向上累加；已知金额及有效数可以累加，完整金额仍要求全部对应成员覆盖。

## 审计版本与幂等

每次准备发布一个季度的行业汇总时，生成规范化输入签名，包含季度、目标日、冻结名单内容哈希、汇总定义版本，以及各成员实际选中的快照定义和总市值。用签名识别输入口径和金额是否发生变化。

与该季度最新有效汇总签名一致时复用已有版本，不新增记录。单纯重复采集、来源取得时间变化、快照其他非市值字段修订不产生新的行业汇总版本。名单、选值定义或有效市值变化时追加新版本，原汇总行保留。

`sw_imports` 新行保存：

- `obtained_at`：真实汇总发布时间。
- `content_hash`：含领域标识、季度、目标日、定义版本和输入签名的规范化哈希，避免与旧导入内容哈希混用。
- `member_import_id`：发布事务内读取的当前名单版本，保证汇总历史季度不改变当前分类指针。
- `source_manifest_json.scope`：`market_snapshot_industry_cap_aggregation`，作为新汇总与旧导入汇总的明确识别标记。
- 清单内容：汇总定义版本、季度目标日、冻结名单版本与哈希、输入签名、实际使用的快照行 ID 及定义版本、关联快照批次 ID、各行业覆盖统计、无行业归属公司数、实际计算与发布时间、所属任务标识。

快照行 ID 引用被保留的真实版本，用于复算审计结果；不会复制原始响应、公司完整字段或来源文件路径。快照批次可含多个定义和来源，不能把整个季度冒充为单一东财批次。

重新出现曾经使用的相同输入签名时，复用那个审计版本。页面不能简单取最大 `import_id` 判定新来源结果仍是当前结果：在现有 `sw_update_runs.result_json.aggregation_results` 中按季度保存新来源汇总的 `import_id`、输入签名、成功发布状态和实际发布时间，并优先采用当前成功映射。没有新来源汇总映射的季度继续读取原 `sw_industry_cap_quarters` 历史结果，选择该季度最新的非拒绝旧导入版本。整体任务后来失败时，已成功提交季度的映射仍有效；不能只选择整体状态为 complete 的任务。任务进度和最终报告更新必须合并并保留这些映射。不对已有季度做批量离线重建。

## 发布时点和失败恢复

推荐统一入口 `refresh_industry_cap_summary(db, quarter, operation_id)`，供以下流程复用：

1. 日常 `refresh_quarter()`：`collect_day()` 完成、`freeze_roster()` 成功后生成该季度汇总，完成后才把本次行业任务标为成功。
2. 历史快照采集：每个季度全部公司分页完成后立即生成该季度汇总；整段任务中断不丢弃已完成季度。
3. 历史合成、停牌参考价补齐：目标快照发布后，为实际影响的季度重算；不得只接入日常按钮而使其他修订入口留下旧汇总。
4. 已有历史期不回填：保留原汇总结果；新采集或修订任务完成后只为其实际处理的季度生成/更新新来源汇总。

汇总计算在读取一致性快照中完成；发布前短写事务重新核对冻结名单及市值输入签名。输入已变化则放弃候选、重新计算，不发布过时结果。新审计版本、该季度全部三级汇总行及任务结果中的当前版本映射原子提交。

公司快照与行业汇总分阶段发布，避免把网络采集或全历史计算放入长写事务。汇总失败时保留已发布公司快照；任务报告“公司快照已保存，行业汇总未完成”，不宣称整个任务完成。恢复时即使公司快照批次被跳过，也必须再次检查并生成汇总。

如果底层季度数据已修订而对应汇总尚未发布，页面展示上次已发布汇总并标明待重算，不能把旧行业总额与新公司市值声称为同一版本。检测使用发布结果和输入签名缓存，不在每次页面读取时扫描全部快照或自动生成汇总。

## 页面读取与同比

- 行业季度市值图、完整市值及覆盖率读取所选汇总审计版本的 `sw_industry_cap_quarters`；上级行业在服务端汇总三级结果。
- 行业排行中的总市值读取同季度预计算结果；缺失时显示待生成或待补，不回退旧公司市值来源，也不在 GET 请求中写入汇总。
- 公司列表保留公司快照的市值、PE和PB读取。
- 行业同比保持原算法：分别在当前季度和去年同季度的冻结行业成员中取共同公司，对共同公司的市值求和后比较。汇总表的两期总额之比无法替代该算法，尤其公司发生跨行业调整时。
- 第一版同比按需读取这两期公司市值，必要时使用有界缓存；不为了预计算总额就改动同比口径。若以后也要持久化同比，需要单独设计跨期依赖和上级行业跨三级迁移的去重规则。
- 行业汇总缓存按当前汇总版本集合失效；财务缓存按当前成员版本及财务发布版本失效。避免仅因新增汇总审计记录就无条件重载全部财务。

## 实施与验收

实现顺序：统一快照市值选择逻辑 → 汇总和版本发布入口 → 接入日常及修订流程 → 隔离库验证 → 页面优先读取新来源汇总、历史缺失时沿用旧汇总 → 重启8765并验收。

隔离验证重点：

- 与当前直接聚合算法逐季度、逐三级及上级行业对比金额和覆盖数。
- 多定义优先级、同公司去重、市值与股价缺失独立处理、零值和空期。
- 无变化不新增版本、真实修订保留旧版、历史输入重新出现时正确选择当前版本。
- 历史季度计算不改变当前行业名单，冻结名单不随后续分类变化重写。
- 公司快照成功但汇总失败、进程中断、恢复跳过快照后补生成汇总。
- 旧财务、旧公司市值、旧汇总版本及日常成员数据不被覆盖；来源和冻结名单可复算。
- 维护页用途、分类、数量、大小以及实际更新时间；同时覆盖空表和缺时间场景。
- 冷读取、缓存命中及更新后首次读取耗时，记录改造前后实际结果，不预设提升比例。

同步更新 `docs/sqlite-storage.md`、`docs/industry-data-schema.md`、`docs/database-maintenance.md`、市场快照来源说明和行业市值指标说明，以及 `maintenance.py` 的用途文字。没有结构变更时不新增迁移文件。验证资料放在 `data/verification/reports/`，临时库清理，日常后台与正式来源文件保留。
