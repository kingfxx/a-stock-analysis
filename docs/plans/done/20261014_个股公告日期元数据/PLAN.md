# 个股财报公告日期元数据方案

状态：已实施并验收。日期：2026-10-14。

## 目标与边界

在个股财务采集时查询巨潮公告元数据，区分正式报告首次披露日与后续更正／修订发布日期，改善企业经营趋势图的披露日股价匹配。新浪仍提供财务数值，人工核验覆盖仍具有最高优先级。

本功能只缓存结构化元数据、查询及判断记录；不下载 PDF、不保存 PDF 正文、不解析 PDF、不调用模型、不新增定时任务、不自动扫描全部已关注股票。已有正式财报 PDF 及其准备流程保持独立，不删除已有文件。2026-10-14 用户已授权继续实施本计划，包括有限样本采集、隔离测试及正式库迁移验收。

## 已确认的现状

- `FundamentalService` 读取新浪 lrb/fzb/llb，最后应用 `report_overrides`；本轮之前已修复披露日覆盖被重复归一化覆盖的问题。
- 新浪四类接口的沪电样本没有独立首次披露日／修订发布日期字段；`publish_date` 存在更正日期和年份错位，`update_time` 也不能替代公告日期。样本检查报告：`data/verification/reports/002463_sina_date_fields_20261014.json`。
- `CompanyReportService.discover()` 已使用巨潮股票索引及 `new/hisAnnouncement/query`，但仅取第一页 30 条、只识别年报／中报并选择最新版本，不适合作为首次披露日选择器。只复用其接口识别经验，不调用其 PDF 准备流程，也不宣称现有旧请求已受公共调度保护。
- 公共 `RequestCollector.get()` 已提供 GET 调度，巨潮公告查询使用 POST；必须在公共层补齐 POST 能力，保持同一套锁、预算、重试、拒绝停止、冷却和恢复探测。不要在业务适配器里直接 requests.post 绕开保护。

## 数据流与模块

1. 个股财务更新提交新浪事实；公告日期作为独立数据集按到期状态同步，失败不回滚已经通过校验的新浪事实。
2. `announcement_sources.py`：股票身份查询、巨潮 POST 查询、响应结构及分页校验、标题标准化；只返回元数据。
3. `announcement_service.py`：首次建档、尾部增量、定向补查、sync run 与公共 batch、元数据提交和旧值保护。
4. `disclosure_dates.py`：纯规则匹配与日期选择，生成判断结果及依据，不发请求。
5. `FundamentalService.read()`：先构造新浪事实与校正候选，再叠加公告日期结果，最后应用人工覆盖。所有消费者复用同一结果。
6. 财务更新响应及普通缓存页面读取均采用上述日期，随后通过现有 `financial_prices()` 匹配共享股价。重复 normalize 不得覆盖已选日期。

`CompanyReportService.prepare()` 不参与此链路。自动采集绝不访问 `static.cninfo.com.cn` PDF 下载地址。

## 存储设计（拟新增三表，最终迁移版本按实施时仓库最新版本递增）

| 表 | 主要字段与身份 | 用途与维护分类 |
|---|---|---|
| `stock_announcement_identities` | instrument_id、provider、org_id、有效状态、source_id/batch_id、obtained_at、updated_at；唯一股票×提供方 | 缓存已查询股票的巨潮身份，避免每只股票反复下载整份索引；个股数据 |
| `stock_announcement_metadata` | instrument_id、announcement_id、metadata_version、org_id、标题、announcement_time 原时间戳、published_on、adjunct_url、报告期、报告类型、全文/摘要/说明类别、原始/修订/未知标记、元数据字段指纹、source_id/batch_id/run_id、obtained_at、supersedes_id | 保留公告元数据修订；同股票×公告编号×版本唯一；个股数据 |
| `report_disclosure_dates` | instrument_id、报告期、报告类型、规则版本、结果版本、first_published_on、latest_revision_on、status、reason、所选原始公告行引用、修订公告行引用、候选引用及结构化理由、是否当前结果、previous_result_id、created_at/validated_at、run_id | 可追溯的日期判断历史及当前结果；个股数据 |

- 原公告和每次更正是不同公告，不合并成一个日期；修订全文和更正说明也分别保留。`latest_revision_on` 只描述已缓存候选中的最新修订公告日，不保证识别全部正文变动。
- 同公告编号元数据真实变化才新增版本；重复请求仍登记公共来源，未变化事实不复制、不伪造新取得时间。字段指纹只对选定元数据求摘要，明确不是 PDF 内容哈希或响应原文哈希。
- 请求记录、脱敏参数、页范围和真实取得时间复用 `collection_sources`；任务与水位复用 `sync_runs/sync_state`，不另建任务体系。事实外键校验所属股票／批次／来源；当前判断通过唯一约束或等效事务规则保证一份。
- 本功能采用个股 `metadata_only`：原响应正文、完整 raw_json、片段、压缩响应文件及响应哈希均不保存；公共来源路径／哈希／字节数为空。业务表保存筛选后的结构化元数据及候选依据，不具有原文回放或 PDF 内容审计能力。
- 新表必须同步 `docs/sqlite-storage.md`、`maintenance.DESCRIPTIONS`；真实更新时间用 `obtained_at/updated_at/validated_at/created_at`，不以公告日／报告期代替。维护验收包括空表、缺时间、记录数、大小、分类和外键。

## 默认分类与扩展

2026-10-14 用户限定当前仅采六类：年报、半年报、一季报、三季报、业绩预告、权益分派。四类财报用于首次/修订日期选择；预告和权益分派只缓存元数据，不能当作正式财报披露日。不取全公告，删除无分类全范围更正关键词补查；更正说明只处理六类响应实际返回的记录，修订全文沿用所属财报类。

分类使用集中注册表和默认集合（稳定业务键、巨潮源分类代码、用途、定义版本）；接口支持传入注册分类集合，为后续更多分类兼容，不立即增加复杂选择器。公共batch.scope登记规范化分类列表/范围版本。分类集合纳入缓存和覆盖身份；新增分类必须核验源代码后登记；第一版通过重新完整校验所选分类集合的最近10年范围建立新覆盖身份，不用旧24小时检查时间跳过新分类。既有相同元数据幂等复用；普通同集合更新仍补尾部增量。按分类分别只补新增类别的请求优化留待以后，不能提前描述为已实现。非法/未知分类拒绝，不能用空分类参数变相采全部。

## 公告匹配

匹配前校验股票身份、公告编号、标题、时间、链接主机及查询范围。统一去除标题 HTML、空白及全半角括号差异，保留原标题。报告期由完整标题中的年份和明确的年度／半年度／一季度／三季度识别，不按公告年份猜报告期。

- 正式全文、摘要、更正说明分别分类；排除业绩预告、快报、审计报告、董事会决议、预约披露、英文版本及无明确适用报告期的公告。
- 第一版自动确定首次日期以明确的原始中文正式报告为主。摘要仅辅助印证；只有摘要或全文与摘要日期不一致时标记待核验，不自动提高可信度。
- 含“更正后、修订版、更新后”等明确后缀的正式报告归为修订版本；含“关于……更正”的说明公告不作为首次正式报告。
- 一份说明涉及多个年度时按标题明确列出的报告期关联，不能只取第一个年份；无法唯一解析或需正文才能确定关系时保留公告元数据、标记待核验，不下载正文。
- 不依据排序顺序选第一条，也不把“无修订关键词”单独当作已证实原始报告。重复原始标题但日期不一致、标题歧义、未知修订标记等需要保留候选并标记冲突。
- `announcementTime` 按 Asia/Shanghai 转为日期，保留原毫秒时间戳。附件路径日期只作校验线索；相差一天也不自动加减一天，更不能用实际采集时间代替公告日。

## 日期选择及可信度

不做日期数值加权平均，也不预设未经验证的概率分数。第一版采用证据等级和可解释状态。

| 状态／证据 | 首次日期与图表行为 |
|---|---|
| 已有人工覆盖（包括 null） | 始终优先；自动候选不同则提示冲突，但不覆盖人工值 |
| 完整查询范围内找到唯一明确原始全文，报告期/股票匹配，无摘要或时间冲突 | 采用公告日期，状态 `matched_original`；新浪一致可附 `sina_agrees` |
| 找到可靠原始全文，也有后续修订 | 首次日期保持原始全文日期，另存修订日期；新浪指向修订日时解释差异 |
| 已核验原始日期与新候选冲突 | 保留旧日期并标记 `conflict_retained`，等待核验；不得静默换到更早或更新日期 |
| 只有修订／摘要／说明或查询不完整 | `pending`；不能声称已找到首次披露日，不采用修订日期填补首次日期 |
| 查询失败或冷却 | 保留已缓存可靠日期，另显示失败/过期状态，不把失败当作无公告 |
| 还没有可靠公告结果且未出现明确修订冲突 | 可继续使用原新浪校正候选，明确标记 `sina_unverified`，不展示为公告核验通过 |
| 明确发现新浪日期对应修订、或出现无法解决的日期矛盾，且无可靠旧值 | 首次日期留空，断线并解释待核验原因 |

自动公告结果独立存储，不写入人工 `report_overrides`。保留 `source_publish_date`、新浪校正候选日期、最终采用日期和来源状态，避免再次归一化抹去结果。未下载 PDF，因此即使日期已匹配，也不保证财务数值是首次披露时版本，页面需明确此限制。

## 查询范围、频率与覆盖

- 范围只针对当前用户操作股票及本地财务展示范围涉及的报告期；当前公告历史上限统一为上海今天减10个日历年，首次/full/定向start/分类扩展均不得越界，闰日减年取有效月末。不删除旧财务或正式文件。首次启用在该股票下一次明确财务刷新时初始化；已有股票普通只读页面不批量建档。之后沿用个股财务到期同步策略，新功能不添加额外页面 GET 请求。
- 首次建档按实际需要范围（截断到最近10个日历年）到今天查询，最多最近10个日历年，不额外向前取同比辅助年。查询多个日期段并完整翻页；页容量必须先有限真实核验，现有 30 只是已用参数，不能假设是上限。
- 每个日期段联合检查总数、实际页条数、`hasMore`、跨页重复、代码和日期范围。2026-10-14 实测近90天响应含2条公告、`totalAnnouncement=2`、`totalpages=0`、`hasMore=false`，不能将 `totalpages=0` 解释为空数据。后续两股实测进一步确认该字段向下取整：沪电93条、海控91条都返回totalpages=3，但按30条页容量均需要4页（证据cninfo_pagination_shape_20261014.json）。不能直接依赖该字段确定翻页数量；按总数及已核验页容量向上取整计算请求页数，允许已证实的向下取整页字段，并结合 `hasMore` 和实际条数验证。多页段发布前复核边界页/总数，遇到查询期间变化重做该段有限次，仍不稳定则失败。网络和等待不持有 SQLite 写事务。
- 首次日期仅在相应查询范围已完整验证、明确候选唯一时自动确认。来源历史可能截断，需单独记录各报告期 `original_found/revision_only/missing/ambiguous`；分页成功不等于历史覆盖完整，未知历史范围保持 `unknown`，不把区间最早日期声称为所有历史的首次日期。
- 增量按公告发布日期水位补尾部，并回看最近 90 个日历日以检查修订／延迟入库；旧报告的新更正按新公告日自然进入增量，不受其报告期旧年份限制。90 天是工程回看策略，不承诺捕获任意历史元数据修改。
- 相同股票公告数据成功检查后 24 小时不重复普通检查；手动刷新可触发一次增量检查，不能绕过冷却。久未检查补齐水位到今天的整个空档。
- 缺失／冲突报告期允许用户显式定向补查；明确全量核对才扫描当前股票的所需历史范围。不自动启动全股票回填或定时核对。更早范围由用户扩大展示范围或明确补查触发。
- 不因查询失败/临时缺行删除历史公告，不以无返回解释撤回。股票身份查询成功缓存；身份缺失或接口拒绝不冒充不存在。

## 公共调度与网络约束

提供方统一 `cninfo`，股票索引、公告查询、分页、必要 cookie 获取共享同一预算与锁，跨进程和重启持久化。既有正式 PDF 准备链不在第一版改造范围；文档必须明确旧链未统一，不能宣称全部巨潮请求已受新保护。

巨潮 `cninfo` 使用公共提供方级授权策略，并发 1；完成后间隔 2 秒、jitter 0、滚动 60 秒至多 30 次、每 20 次无额外休息。GET 和 SDK invoke 共用同源锁、预算、记录、拒绝停止及冷却。401/403/429/验证码/频率拒绝立即停止本轮全部 cninfo 请求，至少冷却一小时并遵守重复拒绝延长及更长 `Retry-After`；普通错误最多三次，等待 60/120 秒＋随机间隔。恢复只发一次结构有效探测。遵守可取消等待、自动失败十分钟抑制及不绕过拒绝。此策略不放宽其他来源默认下限，也不改变四个股票来源的 `stock_fast` 行为；旧独立巨潮链仍不在公共调度保护范围内。

公共层补齐 POST 请求时测试参数记录包含 HTTP 方法及表单；不把 GET 和 POST 相同参数混为同一请求身份。选择复用现有调度内核或扩展统一 request 入口，避免复制一套限速代码。冷却验证须检查巨潮索引/公告响应结构，不只检查 HTTP 200。

## 页面与消费者

先显示原缓存，公告同步显示独立状态；财务和公告均结束后重新读取合并结果，允许新浪成功、公告失败的部分成功结果。请求等待不阻塞后台其它提供方。不得自动调用模型。

股价悬浮提示显示采用披露日、实际交易日、日期来源；有修订时另显示最近已知修订日；未核验／冲突明确标记。财务首次披露日不是财务数据版本时间，也不是公告页面上传时间。

季度／年度／TTM、披露日股价及市值、PS 的已披露筛选等消费者必须审查一致性。不能一处用巨潮日期、一处仍重复执行新浪年份校正。保留必要 API 字段供验证，用户流程不展示内部表名或指纹。
