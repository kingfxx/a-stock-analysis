# 个股接入公共调度，暂缓原文归档

日期：2026-10-14。状态：P0–P5 已完成。P5 已在宿主侧重启 8765，启动日志、监听 PID、首页及只读维护 API 均已核验，Codex 浏览器可见页面；后台保持运行。用户于 2026-10-14 授权按本计划实施。独立于财务四表／行业整合计划，不修改其进度。

## 1. 本次要做什么

将个股六类数据及估值附带的行业快照请求接入 `quarterly_dashboard/collection.py` 的同源请求保护；保留个股同步控制、业务存储及页面按时间自动更新。只增加公共批次和请求结果元数据，不新增完整响应归档。

用户已确认：估值、融资有每日更新需求；页面根据时间自动更新是有意设计。缓存归档暂不做，不做每股 ZIP、按年分包、原文 BLOB 或逐次响应文件。执行已接入公共调度并通过隔离回归；未运行真实采集、未回填或迁移日常数据库。

## 2. 当前实现依据

已查阅根 AGENTS、采集规则及财务规则，以及以下实际入口：

- `web/index.html:loadDashboard`：普通刷新和全量刷新拆成多个 API 调用。财务、股价和筹码可并行，分红／估值按财务结果安排。一轮浏览器刷新没有持久化后端父任务。
- `server.py:load_chart_data/price_bundle/p4_services`：调用 FundamentalService、DividendService、ValuationService、ChipService、PriceService。正常服务仍创建普通 Session 直连，未接公共 RequestCollector。
- `sync_runs` 按股票／数据集／来源／复权方式记录执行；`sync_state` 保存成功水位、检查时间、revision 和活跃价格版本。`complete_sync` 用 revision 防旧任务覆盖新提交，事实、成功结果和水位同事务提交。
- 事实 raw_json 是拆分后的来源记录，不是完整分页 HTTP 响应。现有旧 JSON 缓存用于兼容／导入，日常 SQLite 服务不逐次同步写回。
- 价格有不可变前复权版本、候选校验、活跃版本及 lease；这些不能因统一调度而删除或改成逐行覆盖。
- 既有个股更新频率并非完全相同：财务／分红／估值存在 24 小时检查逻辑；融资／股东人数有上海自然日检查；价格有日检查、短时请求合并及定期历史审计。保留这些默认策略，不把所有模块改成每日全量。

## 3. 存储和职责

### P0 请求链与频率基线（2026-10-14 代码核对）

普通页面链路为 `render_page` 初始 HTML 缓存 → `web/index.html:loadDashboard` 并行发起 `/api/prices`、财务、筹码；分红等待财务成功，估值在需要财务时等待财务成功；收到价格版本后再请求价格 bundle。单个用户点击不是一个后端持久化 operation。

| 链路／真实请求 | 当前实现及可产生的请求 | 频率／范围控制 |
| --- | --- | --- |
| 新浪个股财务 lrb/fzb/llb/gjzb | `FundamentalService.update` 每数据集建 `sync_run`；`_collect` 每页请求，完整范围按 200 期分页，增量按 2 期，跨页后重新取第一页核验。仅 lrb/fzb/llb 进入普通事实解析；gjzb 当前在服务循环中更新但 `read` 未消费。底层 `sources.fetch_financial_report_page` 每次 `Session.get` 是一个真实请求。 | 有数据时默认 24 小时检查；显式 refresh/full 绕过。缺数据或到期审计可全量分页。 |
| 东财股东人数／融资 | `ChipService.update` 对股东两套来源分别建 run；`chips._fetch_chip_report` 每页 500 条，最多 100 页。股东来源还可能发起 `RPT_HOLDERNUM_DET` 第二套查询。融资历史缺口会在同 run 触发无起始日补偿。 | 默认按上海自然日 `checked_today`；显式 refresh/full 绕过。增量按检查时间回看 30 天（股东）或水位回看 14 天（融资）；初次/全量为未限定起点。 |
| 东财分红事件 | `DividendService.update` 全量分页，或增量分别查 NOTICE_DATE、EX_DIVIDEND_DATE；待实施报告期逐期复查；精确查询异常可能再发起全量补偿。每个分页由 `_all_pages` 调用 `valuation.fetch_dividend_event_page` 发出一个请求。 | 已知记录默认 24 小时；显式 refresh/full 绕过。增量窗口为 checked_at 前 30 天；full 或未知状态全量。 |
| 百度 PE/PB/市值 | `ValuationService.update` 按三个指标各建 run；每指标可能按多个观察窗口调用 collector，尾部无重叠时依次扩大窗口，最多补查近三/五/十年；每个指标×窗口各一请求。 | 有数据默认 24 小时；full/首次/周期审计会取初始多个窗口；增量优先近一年，按尾部空档扩大窗口。 |
| 东财行业估值快照 | `ValuationService._update_industry` 调 `valuation.fetch_industry_snapshot_details` 单请求。 | 同为 24 小时检查；refresh/full 绕过。 |
| 腾讯日线 raw/qfq | `PriceService.ensure` 调 `sources.fetch_price_history`；每段日期范围按最多 640 条向历史翻页、页间 20 条重叠。raw 缺少已有重叠日会全历史补偿；qfq 可能逐个旧锚点请求，复权不明时同一窗口再分别请求 raw 与 hfq 校验，发现变化后全历史重建。每次底层 `Session.get` 独立计数。 | 常规按上海自然日；显式 refresh 仍受 5 秒请求合并；周期审计或 full 才扩大到 1990 年起全历史。qfq 锚点当前最多两个。 |
| 腾讯股票简称及页面附属请求 | 初始名称缺失时可通过 `fetch_stock_name` 单次取腾讯报价；财务披露日价格、分红收益率等辅助链复用价格服务和已有事实，不能绕开 `PriceService` 另计 fetcher。 | 仅名称缺失触发；价格仍按其自身状态控制。 |

异常分支基线：各 fetcher 均有结构／业务校验；公共 collector 现有 HTTP 500/502/503/504 最多三次尝试并逐次登记，普通 HTTP/解析业务错误不通用重试，401/403/429、验证码、反爬 HTML 会阻断 provider 并冷却。接入时需要避免被筹码融资缺口全量补偿、分红窗口补偿、价格窗口扩大或 qfq 口径核验吞掉公共 `ProviderBlocked`；这些分支中发出的每个真实 HTTP 请求都必须经过同一 provider 锁及预算。当前来源模块直接使用 `Session.get`，并未接公共调度；本节仅记录现状，不代表已接入。

- 现有 raw_json、字段来源、哈希和同步 run_id 的写入规则；本期不补造旧请求、不迁移旧历史、不删除旧缓存。
- 个股新浪财务优先和既有计算口径，不自动改用全市场财务或交易快照。

### 复用公共表

- `collection_provider_state`：共享预算／冷却，eastmoney 与全市场财务和快照共享，sina 与指数日历共享；tencent、baidu 各自独立。不能用接口名或股票代码拆分 provider 绕过预算。
- `collection_batches`：本轮某个数据集／请求范围的执行和覆盖元数据；初版一条 sync_run 对应一个主要 batch，真正独立校验的子范围需要时再拆。domain 建议 stock，dataset 建议 stock.financial.lrb、stock.financing 等；scope 显式带股票、交易所、实际来源接口、日期／报告期／窗口、复权方式、解析和定义版本、运行模式。
- `collection_sources`：每次实际请求及重试的脱敏参数、尝试序号、HTTP／请求／解析状态、取得时间和安全错误摘要。只存元数据；不存整页响应、响应片段、响应原文哈希或其压缩副本。相关 file_path、compression、raw_sha256、stored_sha256、hash_basis、raw_bytes、stored_bytes 保持 NULL，不能编造文件或用空文件代替。
- 在批次 scope/result 明确 `evidence_mode=metadata_only`；维护／来源展示注明“未归档原文，仅保留请求结果与现有业务 raw_json”，不把这种来源描述为完整可重放证据。无响应和主动不归档须能通过请求结果和 evidence_mode 区分。

复用 `operation_id=sync_runs:<id>`，scope 带 sync_run_id；这是一个同步子任务的关联，不声称等同整次浏览器点击。不新增个股 operations 控制表，也不把浏览器内存状态冒充持久化父任务。事实仍以既有 run_id 关联同步，公共批次再关联该 run；本期无需在每条事实增加公共来源外键，不能宣称已有逐行到分页的精确公共来源映射。

目标是不新增业务表或大规模重建事实表。公共表当前允许文件／哈希为空，优先无需 schema 变更；若实施发现约束不能表达，应记录证据和最小迁移理由，不自行扩张到完整来源迁移。

## 4. 公共层改造方式

目前 `RequestCollector.get` 把调度、响应归档和来源登记绑定在一起，不能直接调用后再删除文件。

1. 在公共 collector 增加显式的证据策略：默认继续完整归档；仅本次个股入口显式选择 metadata_only。共用同一套发送前预留、provider 锁、请求、完成后计数、拒绝判断、恢复探测和重试；禁止复制另一套限速实现。
2. 两种模式都逐次登记请求结果。无原文模式只登记元数据并把 Response 在内存交给现有解析器，不写临时原文、不计算归档双哈希、不把正文塞进 error/result_json。
3. 公共 get 的既有默认行为、返回约定、默认完整归档和 read_source/reusable_source 不变；metadata_only 来源不可复用为响应缓存，不能调用 read_source 冒充可重放。指数、全市场财务／分类／快照继续原有完整归档策略。
4. 为个股低层取数提供薄适配层，将既有 fetcher 的 Session.get 调用接到 collector。优先保留解析函数和依赖注入契约。session 仅负责传输，业务解析仍在原模块；明确每页解析成功／失败的登记点，不能 HTTP 200 就标整个数据集校验成功。
5. 同一 run 的分页、补偿、价格锚点、raw/qfq 基准核对、首次页复查等，每个真实请求都须穿过公共入口。外层一次 fetcher 调用可能含多次网络请求，不能按一次计费或计数。
6. 结构变化和业务校验错误不当作网络临时错误重试。对 401/403/429、验证码、反爬的公共阻断异常，不得被“换大窗口／换接口／全量补偿”吞掉继续同源访问；先检查 provider 状态再发送。其他提供方可继续。

## 5. 更新与页面行为

- 保留现有页面自动检查，尤其估值／融资补新；保留原来的缓存有效期、周期审计、必要重叠窗口及首次建档策略。暂不统一改造自然日／24 小时判定，也不将每日检查变为全量刷新。
- 明确三种模式：自动到期检查、手动刷新、显式全量核对。模式与触发原因登记批次；手动全量不被普通 TTL 误跳过，但不能越过公共冷却或借此扩大当前股票以外的采集范围。
- 页面先显示现有缓存，等待公共额度时保持可读；使用现有异步加载结构，不改成等所有来源完成后才显示。核对长等待期间按钮、浏览器超时和 API 错误提示，不能显示空白或误报完成；失败仍保留原数据并提示。
- 同股票同数据集请求复用现有 data_lock 和水位二次检查，避免多标签页重复拉历史。自动请求失败后不得仅因成功水位未更新就在短时间开页连续重试：普通临时失败建议复用现有 600 秒检查尺度做 10 分钟自动重试间隔，依据最新失败 sync_run 判断；不更新成功水位或伪装检查成功。手动重试可绕过此自动间隔，但受公共预算／冷却约束。
- provider 冷却期间不发送探测；到期按公共机制单次有效恢复探测，必须对新浪 JSONP、腾讯价格和百度嵌套 JSON 使用来源适配的健康检查，不能照搬东财 data 字段判断。拒绝后不能在本 run 中重建 collector 清除 halted 状态。
- 全市场采集中允许个股按同源额度排队，其他来源独立继续。初版不增加个股优先队列，也不增加“检测全市场正在采集就暂停全部个股”的策略；这两项并非当前用户需求。
- 不新增整轮父任务、跨浏览器任务推送、常驻后台队列、定时采集或任何模型调用。本期继续既有请求触发方式。

## 6. 提交、失败和中断

完整业务分段验证后，在 complete_sync 所有者的短事务中提交事实、同步成功状态、水位和对应公共批次完成状态；若需增加提交回调，应保持其他调用兼容。source 请求记录可在事实失败前持久化，事实失败不得回滚掉实际请求历史。

sync_run success/no_data 与公共 batch complete 仅描述执行；覆盖根据既有来源可核实程度单独登记，不能用首末日期和行数宣布内部连续完整。显式无数据、未披露、业务不适用、请求失败须分开；不改变既有“有值不可被无数据替换”保护。

异常时关闭关联 batch，保留旧事实和有效价格版本。启动恢复按 sync_runs:<id> 关闭受中断的 stock batch，保留请求结果；不误伤行业、指数及其他任务。取消等待检查可复用 sync_run 状态和公共 cancelled 回调，不另造取消状态体系。

无原文缓存意味着失败恢复只能复用已经成功发布的业务段；未发布段重新通过公共调度请求。不得声称本期支持逐页原文重放／断点缓存，也不能把已发布 raw_json 拼成原始 HTTP 响应。

## 8. 验收场景

1. 假时钟模拟跨线程／跨进程／重启预算，个股和全市场竞争 eastmoney，共享计数；sina／tencent／baidu 独立。默认并发 1，完成后 10–15 秒，滚动 60 秒至多 5 次，每 20 次额外休息 60–120 秒；401/403/429／反爬冷却及 Retry-After 不变。
2. metadata_only 成功、失败、解析失败、网络无响应、每次重试均有元数据，且没有新建任何原文归档文件／ZIP／响应表／BLOB；旧请求的归档文件不被删除，原有日常备份不算新增响应归档。
3. 指数、全市场财务／分类／快照仍完整归档、双哈希有效；原先 R1–R7 相关回归继续通过。请求结果合并保留其他组件已经提交的审计元数据，避免重复此前覆盖问题。
4. 当天已检查／TTL 有效时跳过、跨日／到期补新、停用后补尾部、显式全量、自动失败 10 分钟间隔、手动重试、冷却不重复发送；失败不前移成功水位。所有日期测试用固定时钟。
5. 分页截断／变化／重复、缺字段、有效零负值、空响应、数据源明确不适用、拒绝被补偿分支吞掉；HTTP200 不等于执行或覆盖成功。股票／日期／窗口身份不能串用。
