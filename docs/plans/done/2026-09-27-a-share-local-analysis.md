# A 股本地投资分析系统：详细实施计划

日期：2026-09-27　状态：阶段 0 进行中；已完成首轮实测，尚未通过放行关口。实测结果见 [数据源矩阵](../data-sources/matrix.md) 和 [技术决策](../data-sources/decision.md)。

> 依据用户提供的《A股本地投资分析系统_开发计划.md》。本文只定义实施步骤与验收证据；附件中的“先做阶段 0”视为项目约束，不代表数据源已经可用。

> **范围更新（2026-09-27）：** 用户明确接受首版不保存完整日线，以季度财务图为核心。首版页面按[季度方案](2026-09-27-quarterly-dashboard.md)执行；本文件中多年日线、成交额、历史估值的前置关口适用于后续扩展，不再阻断季度对照页面。

## 目标与边界

在 Windows 个人电脑上输入一只 A 股代码，按需保存其日线、财报、现金分红及股本事件，并在本地页面查看四组柱线对照及 PE、PB、股息率历史。所有历史估值按当日可见信息计算。首版不做交易、分钟线、全市场批量下载、回测；“市值／营收”仅表示同图对照。

当前工作目录为空且不是 Git 仓库，没有现有实现可延用。本文件是可执行路线图，实际字段映射、依赖版本及数据源选择必须在阶段 0 的证据上确定。

## 阶段 0：数据源可行性实验（首个实际开发任务）

### 0.1 固定实验样本与环境

- [ ] 选 3 只普通 A 股：沪市、深市各至少一只，另选上市历史较长且有分红/股本事件的一只。记录代码、交易所、选择理由、上市日期、测试时间和市场是否开市。样本代码仅作实验参数，不写死在主系统中。
- [ ] 记录 Windows 版本、Python 版本、mootdx 及其关键依赖的精确版本、网络环境和数据抓取时间。为实验建立独立虚拟环境；只安装探针所需依赖。
- [ ] 建立 `experiments/source_probe/`；探针分别调用日线、财务、公司行动。输出脱敏的原始响应摘要及结构化 JSON/CSV，保留请求参数、状态、耗时、行数、最早/最新日期、错误类型。大体积原始数据放到忽略目录，提交小型核对样本和日志模板。
- [ ] 先确认数据使用条款、请求频率与是否需要凭证；不得通过轮换服务器等方式绕过限制。

### 0.2 日线验证

- [ ] 对每只样本测试 mootdx 线上日线：分页取得多年记录并重复调用；核对日期顺序、OHLC、成交量、成交额、单位、价格精度、停牌日、最新已结束交易日。不能以“请求成功”代替“有效非空数据”。
- [ ] 每只股票抽取早、中、近三个交易日，与可公开核对的独立行情或交易所记录比对；记录差值及可能的复权/单位原因。
- [ ] 对无数据、部分历史、时间戳落后、异常返回分别保存证据。失败时只进行有限重试并记录原因，不无限切换 IP 或服务器。
- [ ] 若线上日线不通过，调查合法替代日线来源；同时实测通达信官网盘后包能否下载、文件格式、更新频率、磁盘/流量成本、能否只抽取指定股票。盘后包属于整包下载时，在矩阵中明确这与“按需股票”需求的冲突及本地过滤方案。

### 0.3 财务、披露日、公司行动验证

- [ ] 财务：取得多年年度、半年度及季度记录，核对营业收入、归母净利润、归母净资产的字段含义和累计/单季属性；比对至少两份正式财报，逐项记录报告期、实际披露日、版本/更正信息。若只提供报告期而无披露日，标记为不能独立支持历史时点估值。
- [ ] 公司行动：核对现金分红每股/每 10 股单位、税前税后口径、公告/股权登记/除权除息/实施日期及股本变化生效日。每只样本至少检查一例分红，长历史样本检查一例股本变化；若不存在事件，换样本并记录。
- [ ] 检查多个来源的代码格式、交易所标识、日期时区、币种与单位。对财务修订做同一报告期不同版本的可获得性调查。
- [ ] 对缺字段逐一评估补充来源；若需付费，记录费用、权限、历史覆盖、查询额度和免费替代方案，再决定是否纳入。

### 0.4 实验交付与决策

- [ ] 生成 `docs/data-sources/matrix.md`，每行对应一个必需字段：候选主源/备源、接口或文件、时间覆盖、请求限制、许可、样本行数、核对结果、缺口和决定。
- [ ] 生成 `docs/data-sources/decision.md`：明确日线、财务、披露日、分红和股本的来源组合；列出不可用功能及后续补救；记录选择理由和复测日期。
- [ ] 判定关口：日线须至少覆盖多年且最新交易日可核对；历史 PE/PB 必须有实际披露时间；市值需可确定当日总股本；前复权需可确定事件及因子。任何关口不满足时，将相应指标/图表列为不可交付，先解决来源，不以推测值补齐。

**阶段 0 验收证据：** 探针在 3 只股票上可复现，矩阵有样本和时间戳，人工抽样有原始对照，失败同样留痕。此阶段不声称数据源已通过。

## 阶段 1：单股数据闭环

### 候选结构（经阶段 0 修订后定稿）

```text
pyproject.toml                 # Python 依赖、命令入口及检查命令
src/investment/config.py       # 本地路径与运行配置
src/investment/domain.py       # 代码、日期、金额、来源/版本等统一类型
src/investment/sources/        # 每个已验证来源独立适配器
src/investment/storage.py      # SQLite 连接、事务、迁移
src/investment/ingest.py       # 首次抓取、分页、增量与回补编排
src/investment/cli.py          # update CODE、状态查询等命令
tests/fixtures/               # 经脱敏的固定源响应及人工核对样本
tests/test_ingest.py
docs/data-sources/             # 实测矩阵和来源决策
```

### 任务与完成条件

1. **源接口与规范化**：将已选来源映射为统一证券代码（交易所 + 六位代码）、日期、数值单位、原始响应标识。保留源原值与抓取时间；格式或单位未知时拒绝入库并记错误。用固定样本测试两个来源的同一字段归一化结果。
2. **SQLite 迁移**：先定义 `security`、`daily_bar`、`financial_filing`、`financial_fact`、`source_record`、`update_run`、`watermark`。行情以证券+交易日+来源+源版本作唯一约束；财务以证券+报告期+披露日+来源+源版本识别修订。用迁移脚本建库，不把二进制数据库提交到代码仓库。
3. **单股首次更新**：`update CODE` 只请求指定股票；将抓取、解析、校验、写入、推进水位放在明确的事务边界。打印新增、修订、跳过、缺失数量。
4. **增量与回补**：从已成功水位向前重抓若干交易日；财报/事件使用较长回看窗口并按源版本或内容哈希检测修订。空响应、部分分页、解析失败不得推进该数据类别水位；失败可重跑。
5. **验证**：同一股票连续更新两次，记录行数与哈希；第二次不产生重复记录。注入空页、断网和重复数据，确认现有记录未丢失、错误可见、重跑可恢复。

**阶段 1 验收：** 一只股票从空库到历史日线和核心财务完成；重复运行幂等；只更新目标股票；水位和错误日志能解释每次运行结果。

## 阶段 2：时点正确的指标计算

### 数据模型增量

增加 `corporate_action`（事件类型、公告/登记/除权/实施/生效日期、现金额、股本前后、来源版本）、`forecast`（证券、预测年度、利润值、作出日期、录入日期、来源及修订）、`metric_snapshot`（计算日期、指标、值或缺失原因、输入版本指纹、算法版本）。原始事实不覆盖；重算快照可删除再生。若来源无法提供某日期或修订记录，存缺失状态，不能凭字段名称猜测。

### 计算顺序与口径

1. **财务时点筛选**：在交易日 `D` 只使用披露时间不晚于 `D` 的版本。若只有日期无时刻，按次一交易日可见处理，避免当日收盘前是否披露不明造成前视偏差。更正报告从更正实际可见日生效；旧版本保留。
2. **累计转单季**：Q1=一季报累计；Q2=半年累计−Q1 累计；Q3=三季累计−半年累计；Q4=年报累计−三季累计。必须同一会计年度且各期按当时可见版本；断档显示缺失。TTM 为最近连续四季之和。
3. **总市值与复权**：总市值=当日未复权收盘价×当日已生效总股本。对除权除息事件计算前复权序列并用样本日核验；复权价只用于股价走势，市值始终使用未复权价。总股本历史缺失则市值及依赖它的指标缺失。
4. **估值**：静态 PE=市值/当时已披露最近完整年度归母净利润；TTM PE=市值/可见的最近连续四季利润；动态 PE=市值/指定年度在当时已录入的预测利润；PB=市值/当时已披露最近一期归母净资产；股息率=最近 12 个月已实施现金分红总额/当日市值。利润小于等于零时 PE 为“不适用”；净资产小于等于零时 PB 为“不适用”；分红数据覆盖不完整时股息率为“缺失”，不能默认为零。
5. **依赖重算**：新增/更正财报、股本、分红或预测后，按受影响日期范围重算；保存输入版本和算法版本，支持人工复核。

**测试矩阵：** 构造披露日前后各一日、同日盘后披露、跨年 Q4、财报更正、缺失季度、股本变更、除息、负利润、零净资产、预测录入晚于历史日等样本。每个指标至少选两个真实样本日期对照原始行情和财报，并记录手工计算式与差异。

**阶段 2 验收：** 五项指标分别显示数值、口径、来源及缺失原因；历史曲线无未来信息；事件后重算结果可解释。

## 阶段 3：本地分析页面

技术建议：Python 本地服务 + 本地网页 + SQLite；绘图库与 Web 框架在阶段 0 后按实际依赖、离线运行和交互需求确定。服务只监听本机。页面从统一查询层读取数据，不直接调用外部数据源。

1. 输入含交易所/六位代码的股票，显示证券名、最近成功更新时间、各类别覆盖范围和来源状态；提供手动更新按钮及明确的运行结果。
2. 图表切换四组：营收+归母净利润、总市值+营收、总市值+归母净利润、前复权价格+归母净利润。财务柱形图可切年度、单季度、TTM；市值/股价按交易日绘制，财务值在两个披露日之间采用“截至该日最近可见值”阶梯规则。不同量纲用左右轴并标单位。
3. 展示静态 PE、TTM PE、动态 PE、PB、股息率各自历史图。动态 PE 无预测时显示“暂无数据”；零负利润等状态不连线误导。悬停显示数值、单位、行情日期、报告期、实际披露日、来源和口径。
4. 页面查询与指标计算分离；同一图表点与 `metric_snapshot` 可对应。错误、缺口、来源失效在页面显式提示。

**阶段 3 验收：** 切换四组对照及三种财务周期，图例与双轴单位正确；抽取页面上至少十个点，与数据库输入及手工计算核对；缺失状态不画成零。

## 阶段 4：运行维护与交付

1. 连接超时与有限重试；源故障时切换已验证备源并记录来源变更。部分更新结果单独标状态，不显示“全部成功”。
2. 定期回补财报及公司行动，对更正和迟到数据触发受影响日期重算；提供数据审计命令，检查重复键、日期倒序、异常价格/股本、缺失披露日和指标输入指纹。
3. SQLite 备份采用一致性快照，按日期保留；实际执行一次从备份恢复到新路径，验证记录数量、完整性与主要查询结果。
4. 写 Windows 本地安装、启动、更新、备份/恢复说明；固定可用依赖版本；运行自动化测试和一次离线页面启动验收。

## 优先级与预估节奏

阶段 0 是阻断关口，预计 2–4 个工作日；阶段 1 预计 3–5 日；阶段 2 预计 5–8 日；阶段 3 预计 4–7 日；阶段 4 预计 2–4 日。均为单人开发的粗估，数据源不可用、披露日/股本历史难获取时需重新估算。先做可核对的单股闭环，随后再扩大到多股按需输入。
