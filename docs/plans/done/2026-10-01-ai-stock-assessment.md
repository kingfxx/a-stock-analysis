# AI 股票综合研判：首版实施计划

日期：2026-10-01。状态：首版代码已实施，真实账号与分析质量验收待完成。使用与验证边界见 [AI 股票综合研判](../ai-stock-assessment.md)。

## 1. 目标与已经确定的方向

在现有本地 A 股分析页面上，增加按股票手动生成的 AI 综合研判。用户先看到简短倾向，再查看经营、估值、筹码的支持证据、反面证据和后续观察条件；结果可保存、重开和追溯。

用户已认可：利用现有经营指标、估值分位和筹码数据分析；优先通过官方 ChatGPT 订阅接入；分析结果保存 SQLite；先做股票层面的研判，不直接执行交易。本次交付为设计与实施计划，尚未接入账户、调用模型或修改数据库结构。

首版采用以下默认范围：

- 分析风格为价值投资，参考周期为中长期 1–3 年；界面明确标注此假设。
- 经营和估值是主要依据，筹码用于补充背景和提示风险，不设置没有验证依据的固定打分权重。
- 同时参考 3/5/10 年估值位置，不受页面当前选中的图表指标、周期、年限或展示频率限制。
- 综合倾向为“买入候选、观察、谨慎、回避、信息不足”。“买入候选”表示值得进一步研究，不表示立即下单。
- 不包含个性化仓位、持仓成本、目标收益率、买卖价和止损价。后续如加入持仓，另做个人操作建议层。
- 首版只分析本地已有数据，不联网搜索新闻，不批量扫描，不定时消耗订阅额度。

首版成功的标准是：结论有据可查、能识别数据不足、能表达冲突、更新后能知道旧结论已经过时。投资收益率不是本轮软件验收目标。

## 2. 页面入口与结果展示

### 2.1 按钮放置

将“AI 研判”作为独立按钮，放在顶部 `.context` 股票信息行的右侧，位于选股区下方、经营图上方。不要塞进估值指标或财务指标控件，避免让用户误以为它只分析当前那张图。

按钮采用现有深色界面的描边样式，青色文字，视觉权重低于“查看”。生成中显示“分析中…”并禁用重复提交。附近保留小号“AI 设置”文字入口；模型和账号设置集中在这里，不占用选股区。

```text
标的 长江电力 600900   最新报告期 …   本地缓存更新 …      [ AI 研判 ]  AI 设置
─────────────────────────────────────────────────────────────────────────
AI 综合研判   [观察]   一句话说明主要矛盾                  [查看报告] [历史]
生成于 …     财报截至 … / 估值截至 … / 筹码截至 …
─────────────────────────────────────────────────────────────────────────
现有经营图
现有估值图
现有筹码图
```

窄屏时股票信息换行，AI 按钮在信息行末尾单独占一行；不得挤压股票名称，也不得造成整页横向溢出。

### 2.2 页面摘要条

股票信息行下方增加一条紧凑摘要，不在默认页面展开长报告：

- 尚无分析：显示“结合经营、估值与筹码形成综合研判”，按钮为“生成研判”。
- 已有成功分析：倾向标签、一句话结论、生成时间及“查看报告 / 历史”。
- 本地相关数据发生变化：保留原结果，加“数据已变化”提示和“重新分析”。
- 最近一次分析失败：继续保留上一次成功结论；失败提示只描述本次任务。
- 有新成功结果：更新摘要，并将旧结果保留在历史记录中。

“AI 研判”顶部入口：无结果时打开抽屉并生成；已有结果时打开最近成功报告，不自动再请求模型。真正再次消耗额度的操作统一叫“重新分析”。

### 2.3 完整报告用右侧抽屉

桌面端使用固定在右侧的报告抽屉，建议宽度 `min(720px, 52vw)`；内部独立滚动，页面保留当前股票和图表状态。抽屉宽度以 1280/1600 像素窗口验收后调整。800 像素以下使用全屏抽屉。

选择抽屉，是为了让用户在查看报告时仍能回到原图，不新增独立页面、不丢失图表筛选。关闭后保留滚动和选择状态。抽屉遮罩、关闭按钮、Escape、键盘焦点限制及关闭后的焦点恢复均需支持。

### 2.4 信息层级与样式

沿用现有视觉系统：背景 `#101417`、面板 `#1a2227`、正文 `#edf4f4`、辅助文字 `#9aadb3`、边线 `#304049`、操作色 `#38c4dc`。中文继续使用当前字体栈，数值使用等宽数字。

报告标题 20–22px，正文 14–15px，辅助信息 12px。倾向使用短标签，不做夸张大字或仪表盘。标签色建议：买入候选为青绿，观察为蓝灰，谨慎为琥珀，回避为浅红，信息不足为中性灰；同时提供文字，不能只靠颜色区分。

默认阅读顺序为“综合倾向 → 一句话理由 → 分维度判断 → 支持与反面证据 → 改变判断的条件 → 待核实事项”。每条理由控制在 1–2 句，支持与风险各最多 3 条；详细数据通过展开查看，避免长篇堆砌。

不展示未经校准的“胜率 80%”“信心 95 分”或综合打分。数据完整性由程序判断；模型推理的不确定性用具体缺失与冲突解释。

## 3. 生成过程与交互状态

| 状态 | 用户看到什么 | 操作与处理 |
| --- | --- | --- |
| 未连接 ChatGPT | 连接说明与官方登录按钮 | 登录后返回当前股票；不会因登录成功自动开始分析 |
| 已连接但没有计划使用权限 | “尚未授权使用 ChatGPT 额度” | 明确区分登录与额度授权 |
| 无历史结果 | 空状态和生成按钮 | 点击后读取本地数据并启动任务 |
| 数据正在更新 | “数据更新中，请稍候” | 暂停新分析，已有报告仍可看；更新失败后允许按保留的数据做受限分析 |
| 数据不足 | 列出缺失的关键资料 | 不调用模型；提示先刷新数据或查看已有资料 |
| 排队 / 准备数据 | “正在整理数据” | 不显示虚构进度百分比 |
| 模型处理中 | “正在分析”与已用时间 | 可以取消；原成功报告保留 |
| 校验输出 | “正在核对结论与数据依据” | 校验通过前不显示正式倾向 |
| 成功 | 完整报告和摘要条 | 持久化后再更新页面 |
| 失败 / 额度不足 | 简洁原因及重试 / 设置入口 | 不覆盖旧成功结果，不静默切换付费 API |
| 取消 / 后台中断 | “分析已取消 / 中断” | 终态保存；重新生成必须由用户触发 |

首版只向页面流式传送任务状态，不逐字展示未经验证的模型结论。后台仍按官方要求读取模型事件流，但只有收到成功终态、完成输出校验并保存后，才展示完整报告。

打开页面、查看报告、查看历史、切换股票和切换图表均不得产生模型请求。首次生成和重新分析是唯一消耗额度的入口。重新分析按钮旁标明“使用 ChatGPT 额度”。

账号首次连接时说明：会将当前股票的分析摘要发送给 OpenAI；摘要不包含股票分组、最近查看、个人笔记或整个数据库。允许在发起前展开“本次分析的数据范围”。

同一股票重复点击返回已有活动任务。首版全局最多一个模型任务正在运行，允许一个等待任务；其余操作提示稍后再试。多标签页通过数据库约束去重，不能仅靠前端按钮禁用。

切换股票时，抽屉切换到新股票的报告；旧任务继续完成并归属旧股票，不把结果写入新股票的页面。关闭抽屉或网页不自动取消任务，明确点击“取消”才取消。恢复页面时读取任务状态和已保存结果。

## 4. 分析框架与结论边界

### 4.1 先整理事实，再形成解释

复用 `core.py`、`roic.py`、`valuation.py`、`chips.py` 的现有计算，程序负责金额、同比、比率、历史分位、零值与缺失值处理。不要让模型重新从原始累计财报自行拆季或计算 TTM。

模型负责说明：经营趋势是否持续，利润与现金流是否一致，债务风险与估值是否匹配，不同年限的估值结论是否冲突，哪些证据支持或削弱买入候选判断。

首版不进行 PE/PB/PS 三项平均打分，也不把股东人数下降、融资净买入为正解释为必然利好。周期企业需要正常周期盈利，金融企业不能直接套一般工业企业的现金流和债务规则；行业类型不明时必须保留适用性疑问。

### 4.2 综合倾向的含义

| 倾向 | 允许表达的含义 | 必须说明 |
| --- | --- | --- |
| 买入候选 | 经营质量与价格吸引力有共同支持，值得进一步核实 | 关键风险、仍缺少的定性信息及候选条件失效的情形 |
| 观察 | 证据有冲突，或需要下一期财报 / 更合适的估值 | 等待什么变化，而不是泛泛“持续关注” |
| 谨慎 | 经营、盈利质量或财务风险已出现明显不利证据 | 哪项风险、对应报告期及其影响 |
| 回避 | 现有证据对中长期投资逻辑有较强否定 | 否定依据及重新考虑所需条件，不预测一定下跌 |
| 信息不足 | 缺少关键资料，无法支持综合判断 | 缺少什么、哪些维度仍可分析 |

上述是产品分析规则，不是已经验证有效的交易策略。历史低位不能单独触发“买入候选”，历史高位不能单独触发“回避”。负 PE 不能解释为便宜；高股息率不能替代分红可持续性判断。

### 4.3 数据质量门槛

前置检查分两层：

1. **无法分析**：没有可读财报、没有可用估值 / 价格事实、关键记录归属错误或快照无法保持一致。返回明确缺项，不消耗模型额度。
2. **可以受限分析**：部分财务字段、分红或融资数据缺失。继续分析已有事实，给受影响维度标记“资料不足”，不补零、不推断缺失事实。

“买入候选”要求有可评估的经营趋势、盈利质量和适用的估值证据；相关关键输入缺失时不能给此倾向。特殊行业的适用规则必须明确，不能因通用公式不适用直接判定企业高风险。

不设通用“净现金必须为正”“股息率必须超过某值”等机械条件。筹码缺失通常不阻断经营与估值研判。新闻和竞争优势尚未采集，作为常规待核实事项，不因此让所有股票都只能得到“信息不足”。

业务数据日期与抓取日期分别显示。数据陈旧程度要考虑真实交易日、节假日、停牌和财报周期；不能简单认为“价格不是今天”就过期，也不能把今日抓取当成今日观察。

## 5. 输入摘要与证据结构

### 5.1 每次生成固定的分析快照

生成快照由后台完成，不接受浏览器上传的财报和分位数作为可信输入。浏览器只传股票代码、模型、分析视角和生成操作。

| 内容 | 首版摘要范围 | 口径与注意事项 |
| --- | --- | --- |
| 股票信息 | 代码、名称、可用行业信息 | 行业来源和取得日期；没有时标记未知 |
| 财务 | 最近 12 个单季度、最近 8 个 TTM、最近 5 个年度及同比 | 从足够的前置报告重建；读取至少覆盖所需同比、TTM、ROE/ROIC 端点的历史，不能截断后再计算 |
| 盈利质量 | 毛利率、净利率、ROE、ROIC、经营现金流、简化自由现金流、CapEx | 保留估算标识、异常和缺失原因；现金流与利润必须使用同一周期 |
| 财务风险 | 期末货币资金、有息负债、净现金 / 净负债及变化 | 时点值不加总；债务为简化口径，未知组成不补造 |
| 分红 | 最近年度已实施归属分红、已实施分红率、近 12 个月股息率 | 归属年与实施日期区分；未实施不代表未来零分红 |
| 估值 | 四种指标在 3/5/10 年的最近值、实际日期、分位、样本数、参考线、当前同行业均值 | 保留取样频率、版本与稀疏提示；股息率中间样本不能冒充日度样本 |
| 股东人数 | 最近最多 8 次有效观察及同口径变化 | 统计日与公告日分开；不宣称筹码属于某个机构 |
| 融资 | 最近最多 120 个已有交易日的摘要及 5/20/60 交易日变化 | 只在窗口覆盖足够时计算；记录样本数与缺失，不补造休市 / 缺失日期 |
| 价格 | 最近收盘价、实际交易日和用于对照的变化摘要 | 市值 / 股息率使用未复权价；趋势使用前复权价，固定已完成价格版本 |
| 数据质量 | 各数据集覆盖范围、最近观察日、来源错误、缺失字段、估算口径 | 转为明确的输入限制，错误不隐藏 |

这些范围是上限，不要求每只股票都具备完整历史。计算读取范围与传给模型的展示范围分开；需要的同比基期和资本端点也保存在快照中。首版目标输入规模约 8k–15k tokens，真实样本测量后调整；不能为了压缩把风险或口径说明删掉。

### 5.2 一致性与证据编号

在同一个 SQLite 只读事务中读取各类事实、手工覆盖和已完成的价格版本，先复制必要记录再释放连接；模型请求不能占着数据库事务。需要给现有仓储提供共享连接读取入口，避免多个独立连接拼出混合版本。

保存程序实际给模型的完整 JSON，以及用于重算摘要的有限原始输入、来源行标识 / 内容哈希、同步任务 ID、价格版本、计算口径版本。输入例子：

```json
{
  "schema_version": "stock_assessment_input_v1",
  "instrument": {"code": "600900", "name": "长江电力"},
  "analysis_profile": {"style": "value", "horizon": "1_to_3_years"},
  "evidence": [{
    "id": "valuation.pe.3y",
    "metric": "pe_ttm",
    "value": 19.29,
    "unit": "倍",
    "observed_on": "2026-09-30",
    "percentile": 18.6,
    "sample_count": 726,
    "sample_frequency": "trading_day"
  }],
  "limitations": ["历史分位仅表示相对历史位置；不等于内在价值"]
}
```

例子只展示结构，实际值必须现场由后台读取。每条结论通过 `evidence_ids` 引用快照中的证据，点击“依据”展示当时的值、周期、来源与计算说明，而不是只跳到已经更新过的当前图表。

## 6. 输出协议与程序校验

输出为受约束的 JSON，界面从结构化字段渲染，避免任意 HTML 或模型拼接的页面代码。

核心字段：`schema_version`、`verdict`、`summary`、`dimensions`、`supporting_factors`、`risks`、`change_conditions`、`unknowns`。每个维度有状态、简短说明与 `evidence_ids`；支持和风险项有说明与证据；改变判断的条件有方向、所需变化和可核实的指标 / 事件。

首版维度为经营趋势、盈利质量、财务风险、估值、筹码，各维度枚举与综合倾向分开。例如估值为历史偏低 / 中值 / 偏高 / 分歧 / 无法判断，不把“中值”写成“合理价值”。

模型返回后必须检查：

- JSON、版本、枚举、字段类型、数量与长度是否合法。
- 引用的证据 ID 是否真实存在、对应当前快照和股票。
- 引用数据中的数值、日期与单位由程序呈现；模型正文优先只描述关系和趋势，减少重复抄数字造成的错误。
- 数据不足时是否仍给出不符合门槛的买入候选；是否把负 PE 当成低估、把融资流入当确定上涨。
- 是否出现输入外的公告、预测盈利、机构身份、确定涨跌、目标价或虚构来源。
- 是否收到模型成功终态；中断流、拒答和失败不能仅凭一段文字当成成功。

结构与证据存在性可以自动验证，正文中的所有语义无法完全靠程序证明。需要结合约束提示词、固定案例和人工验收检查。校验不通过将任务记为失败，保留原因和受限原始输出供本地诊断，不静默改写成另一种正式结论。

不自动进行多轮“让模型修复自己的答案”；避免失败后再次消耗额度且结果不可追踪。结构化输出是否受当前订阅路由及所选模型支持，必须在接入验证阶段实测；若不支持，则要求 JSON 文本并执行相同校验。

## 7. ChatGPT 订阅接入与账号设置

### 7.1 首选官方 SIWC 路径

官方文档目前支持本地 / 开源应用通过 Sign in with ChatGPT 请求计划使用权限，并使用 OAuth access token 调用公开的 Responses API。登录身份与使用订阅权限是两回事，不能把“登录成功”直接当成模型可调用。[官方概览](https://developers.openai.com/siwc/token-sharing-open-source)

本项目优先选择“官方登录组件 / SDK 处理 OAuth，Python 后台调用 Responses”的小范围接入，不让模型取得本地 shell、文件写入或数据库写入能力。若官方 SDK 需要 Node，使用仅处理账号的本地辅助进程，不为此重构整个前端；是否引入此依赖由阶段 A 的实际验证决定。

不读取或复制 Codex 的现有认证文件，不复用网页 Cookie，不使用逆向的 ChatGPT `backend-api`，不自动切换到计费 API Key。账号不可用时保留本地报告查看功能，提供清楚的错误与重新连接入口。

OAuth 采用官方规定的动态注册、PKCE、state、nonce 和 ID token 校验；持久化安装的稳定 `ext_agent_host_id` 和已签发的 `client_id`，重启不重新注册。模型列表使用当前账号的官方列表接口，显示官方名称并保存实际 slug；不能将列表出现视为已经有调用资格。[注册与登录](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[模型与请求](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

当前预览要求请求使用 `store:false`、`stream:true`，并将需要的上下文放进本次输入；不依赖服务端会话续接。不要按普通 API 的印象发送当前不支持的字段或工具。必须处理额度不足、权限不可用、取消、中断和终态失败。实现前重新核对文档，不能把今天的预览限制当成永久协议。[预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

### 7.2 设置界面

“AI 设置”用独立设置面板，包含账号显示名、连接状态、按官方规范显示的 `Continue with ChatGPT` 登录入口、模型选择、额度管理链接、断开连接。首次连接解释使用 ChatGPT 计划和股票摘要发送范围；以后不反复弹确认。

首版一个当前账号和一个默认模型，不做多账号管理界面。模型不写死为某个固定型号；首次让用户从可用列表中选择，以后沿用选择。退出账号不删除过去的股票研判。

token 存在操作系统保护的本地凭据存储中，优先使用官方 SDK 的安全存储能力并核实 Windows 支持；不得保存在股票 SQLite、浏览器 localStorage、日志、计划文档或 Git。非敏感的账号引用、客户端与主机标识可以保存在忽略的本地配置目录。实现时补充必要 `.gitignore`，备份文档注明凭据不随数据库备份恢复。

断开连接会清理本应用的凭据及内存 token；撤销平台授权另通过 ChatGPT 的应用管理设置完成。重新启动后按官方流程刷新 token；刷新失败显示需要重新连接，不无限循环。

## 8. SQLite 保存方案

继续使用 `data/stock_analysis.sqlite3`。当前结构版本为 6，拟新增 `007_ai_assessments.sql` 升级到版本 7，注册到 `storage.py` 的迁移列表。升级前使用现有一致备份机制，保留全部事实、分组和排序。

建议三张表，快照与任务分开存储：

### 8.1 `ai_analysis_snapshots`：分析输入

| 字段 | 用途 |
| --- | --- |
| `id` | 主键 |
| `instrument_id` | 外键关联 `instruments`，删除采用限制策略 |
| `input_schema_version`、`calculation_version` | 输入协议与摘要算法版本 |
| `snapshot_hash` | 规范化的实际分析输入哈希，用于去重及数据变化比较 |
| `input_json` | 完整的实际模型输入摘要，包含分析视角和证据 |
| `source_manifest_json` | 来源范围、有限原始输入、行哈希、覆盖项与价格版本等追溯信息 |
| `quality_json` | 缺项、估算口径、数据日期、适用性等质量检查结果 |
| `captured_at` | UTC 捕获时间 |

唯一约束建议为 `(instrument_id, input_schema_version, calculation_version, snapshot_hash)`。快照生成后不可修改；相同输入可以被不同模型或重新分析任务引用。

`snapshot_hash` 包含所有实际影响分析的输入、分析视角、单位、口径及质量限制；排除捕获时间、纯抓取成功时间和不影响数值的来源任务 ID。完整追溯元信息另外保存，避免只刷新了抓取时间就将旧报告标成过期。股票分组、页面控件和最近查看不参与哈希。

### 8.2 `ai_analysis_runs`：每一次任务和结果

| 字段 | 用途 |
| --- | --- |
| `id` | 不可预测的任务 ID，也是接口查询标识 |
| `instrument_id`、`snapshot_id` | 关联股票和输入；用复合关系防止任务引用另一股票快照 |
| `request_key` | 客户端生成的幂等键，唯一；网络重发不重复创建任务 |
| `provider`、`auth_mode` | 首版为 OpenAI / ChatGPT plan |
| `account_ref` | 非敏感的本地账号引用，用于活动任务归属；不存 token |
| `model`、`resolved_model` | 请求模型及响应实际模型（若提供） |
| `prompt_version`、`prompt_hash`、`prompt_json` | 固定指令的版本、哈希和完整内容；保证后续可复核 |
| `output_schema_version`、`analysis_profile_json` | 输出协议和参考周期 / 风格 |
| `status` | `queued / running / validating / succeeded / failed / cancelled / interrupted` |
| `verdict`、`summary` | 成功报告的倾向与短结论，用于摘要和列表 |
| `result_json` | 完整校验后的结构化报告 |
| `validation_json` | 校验结果、版本和受限分析标记 |
| `response_id`、`usage_json` | 供应商返回的请求标识与实际用量；没有则为空，不推算费用 |
| `diagnostic_json` | 失败分类及必要受限原始输出，不包含凭据或完整网络头 |
| `created_at / started_at / completed_at` | UTC 任务时间；界面转为北京时间 |

成功终态要求 `result_json`、`verdict`、`summary`、`completed_at` 完整；其他状态不能被当成正式报告。对 `instrument_id`、时间和状态建索引；通过部分唯一索引保证同一股票最多一个活动任务。成功结果不原地改写，新分析追加新行。

后台维护状态时使用短事务和条件更新，例如只允许 `running` 进入 `validating`；取消后到达的模型成功事件不能把 `cancelled` 改成成功。初始任务、快照关联和幂等校验在同一写事务完成；网络请求位于事务外。

### 8.3 `ai_analysis_preferences`：非敏感设置

单用户设置保存默认 provider、模型 slug、分析视角 / 协议版本及更新时间。首版不保存持仓和仓位。账号 token、OAuth 注册资料和授权回调不进入此表。

最近成功报告通过查询 `ai_analysis_runs` 生成，不另建“当前结果”副本。模型 / 规则升级后，旧报告仍保留并标明版本，不自动请求新报告。

### 8.4 备份、保留和数据变化

三张表纳入当前 Backup API 的备份与恢复验证。升级前备份必需；按用户后续要求，AI 分析不单独触发备份，沿用原有日备份规则，不覆盖当天已有备份。退出账号、删除分组和切换股票不删除分析历史。

首版不自动清理成功报告或相关快照。失败诊断输出设置体积上限并脱敏；未来有明确容量需求再增加历史清理功能，不提前增加复杂的分区或外部文件库。

重开报告或相关事实更新后，重新构造当前相关摘要并比较输入哈希。提示“数据已变化”时显示变化类型，如新财报、新价格、估值变化、融资变化；原结论仍对应旧快照。刚生成的结果若其间数据已更新，同样标记变化，而不是偷偷将新数据塞进旧报告。

质量与日期提示和输入变化是两件事：数据没有变化但查询长期失败，也要显示当前数据状态；不能靠哈希一致就宣称资料新鲜。历史分位随时间窗口滚动发生变化时，应被视为实际输入变化。

## 9. 后台接口与模块边界

建议新增：

| 文件 / 模块 | 职责 |
| --- | --- |
| `quarterly_dashboard/analysis_snapshot.py` | 一致读取、摘要计算、质量检查和哈希 |
| `quarterly_dashboard/analysis_repository.py` | 三张表读写、幂等、状态约束及历史查询 |
| `quarterly_dashboard/analysis_service.py` | 任务编排、去重、取消、重启恢复、输出校验 |
| `quarterly_dashboard/ai_provider.py` | 官方模型列表与 Responses 流，清晰隔离认证适配 |
| `quarterly_dashboard/prompts/stock_assessment_v1.*` | 固定分析指令与输出协议 |
| `web/ai-assessment.js` | 摘要条、抽屉、设置与任务状态更新 |
| `quarterly_dashboard/migrations/007_ai_assessments.sql` | 新表、索引与约束 |

保持当前 Python 本地 HTTP 服务；扩展现有 Handler，不引入新 Web 框架。推荐接口：

- `GET /api/ai/status`：连接与权限状态、当前模型选择，不返回凭据。
- `GET /api/ai/models`：用户打开设置时请求账号可见模型；日常页面不反复访问供应商。
- `POST /api/ai/connect`、`POST /api/ai/disconnect`：开始官方登录 / 清理本应用连接；OAuth 回调由适配层按官方规范处理。
- `POST /api/ai/preferences`：保存模型及固定分析视角。
- `GET /api/analysis?code=...`：最近成功报告摘要、活动任务及当前输入变化状态，只读本地。
- `POST /api/analysis`：检查数据与权限，接受 `code / model / request_key / force`，返回 `202 + run_id`；相同分析已有成功结果且 `force=false` 时直接复用。
- `GET /api/analysis/runs/{id}`：查询任务状态和已校验报告；前端还要核对当前股票和任务 ID。
- `POST /api/analysis/runs/{id}/cancel`：取消任务，不复用完成任务 ID。
- `GET /api/analysis/history?code=...&cursor=...`：分页查询历史，每页 20 条，只返回列表摘要。

历史报告、当前成功结果都通过本地 GET 查看，即使账号失效仍可使用。复用键需包含股票、实际输入哈希、模型、分析规则 / 输出协议及分析视角；不能只按股票代码缓存。

前端采用递增至最多 3 秒的任务轮询，任务终态或当前页面不再需要时停止；不轮询供应商。后台初始超时建议为连接 15 秒、无事件 60 秒、总任务 180 秒，可据实测调整；不把这些值展示成完成时间承诺。

模型请求禁用自动重试。服务端 HTTP 自己的后台 worker 不等于官方 API 的 `background` 参数，不能混淆。取消尽力关闭请求，并明确已经消耗的额度未必可撤回。

沿用 `127.0.0.1` 监听；新增所有会写入、调用模型或改变账号状态的接口都做 Origin / Host 校验、JSON 类型与长度限制，并增加启动时生成的本地会话防跨站令牌。返回值不泄露认证文件路径、token 或完整异常网络头。模型输出用文本节点与受控组件渲染，不能用未经处理的 `innerHTML`。

启动时将此前的活动 AI 任务标记为中断，不自动重新扣额度；与来源同步任务恢复分开处理。退出账号时取消该账号等待 / 运行任务，并处理取消竞态。SQLite 繁忙时短事务可有限重试，不重试模型请求。

## 10. 实施阶段与完成条件

### 阶段 A：订阅可行性验证

核对实施当天官方文档；验证本机 Windows 的官方登录、权限授予、凭据保护、模型列表、一次无股票数据的最小请求、流成功终态、重新启动 / 刷新 token 和断开连接。接着验证输出格式和取消行为。

完成条件：当前账号确实可以调用选定模型；实现依赖和 Windows 存储路径明确；失败分类可显示；不依赖 Codex 认证文件或逆向接口。若资格不可用，保留本地快照和界面方案，明确报告接入阻点，不把离线演示冒充成功，也不自动增加 API 账单。

### 阶段 B：分析输入和存储

增加迁移和备份验证；实现一致快照、复用现有计算、质量检查、证据编号、规范化哈希及任务状态机。用隔离库和固定样本验证，不请求真实模型。

完成条件：相同实际数据得出相同哈希；仅抓取时间变化不误报输入变化；新事实 / 手工覆盖 / 口径变化会改变哈希；快照不会混用价格版本；迁移不影响已有事实与股票整理信息。

### 阶段 C：模型分析与校验

接入官方 provider、固定提示词和输出协议，增加任务去重、队列、取消、超时、权限失效与校验失败处理。用模拟供应商完成故障测试后，再按手动触发方式验证真实模型。

完成条件：所有正式结果均有成功终态和可追溯证据；重试 / 刷新 / 多标签页不重复生成；失败与取消不会覆盖旧报告；模型请求不持有数据库事务。

### 阶段 D：页面与历史报告

增加顶部入口、摘要条、右侧抽屉、AI 设置、历史列表及证据展开；处理无结果、数据更新中、受限分析、生成失败、数据变化和取消状态。

完成条件：用户不用滚到页面底部就能发起或查看报告；完整报告易读；390 像素宽度无新增横向溢出；键盘可操作；查看历史不会请求模型；旧股票的迟到响应不进入新股票页面。

### 阶段 E：综合验收与上线

完成下面的功能与分析质量验收，整理 `data/verification/reports/` 报告。代码测试通过后按项目授权核对进程身份并自动重启 8765 日常后台，检查启动日志与页面；保留后台供用户人工验收。

人工真实分析从少量用户手动选定股票开始。记录实测输入规模、延迟、用量和失败模式，再决定是否调整摘要长度或模型配置。

## 11. 验收清单

### 11.1 自动功能验证

- 迁移、备份恢复、关联一致性、任务状态转换、幂等与活动任务唯一性。
- 单季 / 年度 / TTM 口径一致；负基期、0 股息率、缺失字段、历史分位端点处理正确。
- 同一读快照与价格版本；生成中来源刷新不会修改已经保存的输入。
- 接口故障：授权拒绝、token 过期、额度耗尽、流中途失败、无成功终态、超时、取消、重启、数据库写失败。
- 模型输出：不合法 JSON、未知证据 ID、错股票、字段超长、不符合数据门槛、拒答均不发布为成功。
- 界面：摘要 / 抽屉 / 历史 / 设置；重复点击、跨股票迟到响应、失败保留旧结果、查看不消耗额度、键盘与窄屏。
- 凭据不会进入 JSON 响应、SQLite、测试报告、普通日志或 Git；新增跨站调用拒绝机制可验证。

### 11.2 分析质量样本

固定案例至少覆盖：经营稳定的分红企业、经营改善但估值高位的企业、利润增长但现金流走弱的企业、周期高盈利低 PE、亏损负 PE、不同年限估值冲突、融资增长同时财务恶化、股东人数下降但不能识别机构身份、金融行业适用性、严重缺失与陈旧资料。

每类检查事实忠实度、口径、遗漏风险、理由和倾向是否一致，以及改变判断的条件是否具体。模型输出文字不同不要求逐字一致，但不能在没有输入变化时出现无法解释的相反判断；记录变动原因，不能用一次输出证明策略有效。

真实收益评估另立后续计划。当前财报历史可能包含后续修订、股本与公告点时版本有限，不能直接用现有历史图回放结果宣称预测能力。需要未来逐期留存研判，再做前瞻观察；若做回测，应先补齐点时数据并考虑交易成本与选择偏差。

### 11.3 环境与资料管理

自动测试使用临时隔离数据库，测试服务显式指定检查过的空闲端口，不能使用 8765 或日常库写入。真实账户验收仅在阶段 A / C 的实际接入操作中触发，不由自动回归测试扣额度。

来源样本放 `samples/`，报告放 `reports/`，维护工具放 `tools/`，日志放 `logs/`。验收后清理临时库、预览截图、浏览器配置和一次性脚本；正式库、正式备份和成功分析历史保留。
