# 个人持仓与复盘

## 目标与首版范围

两个券商账户分别记账，默认查看合并组合，也能切到单账户。**第一阶段同时导入招商持仓快照与已有的 2026 年历史成交，提供持仓分析和历史交易查询。** 华泰截图草稿按实施顺序接入。未导入华泰期间，页面明确标注「当前覆盖招商证券 1 个账户」。港股暂不纳入持仓市值及收益汇总，导入预览保留其排除原因。若汇总现金还涉及港股资金或未交收款，待流水核对后再确定纳入资产口径。

主入口为独立侧栏页面「持仓分析」。持仓快照与历史成交以独立标签页显示，各自保留筛选。

持仓明细将证券放在第一列、总市值放在其后，默认按总市值降序。数量列只显示持仓数量，现价／成本、持仓盈亏和今日盈亏保留双行。现金与证券仓位分别显示在对应汇总卡片下。券商比例原样留存，未取得的分项留空。今日盈亏显示带符号的百分比。无适用券商百分比时，从同口径收盘总资产减今日盈亏倒推日初资产，未调整出入金，页面标明估算。用已确认快照的修订版补齐可验证字段。

券商缺少 A 股今日盈亏明细时，可用本地相邻交易日未复权收盘价差乘快照持仓数量。仅对快照日收盘价和券商现价对得上的行估算。券商有同范围汇总时须先对平汇总，估算值标明来源，券商原始快照不改写。持续更新仍以已入账交易后的正确数量为前提。

- 私有样本位于 `data/verification/samples/my_trade/`，保留原件在 Git 忽略目录。文件头已核验为 BIFF8，仓库 `requirements.txt` 已有 `xlrd==2.0.2`。首个适配器直接读取原生 XLS，从表头识别同一工作表内的资金汇总和持仓明细。按实际内容识别文件格式，首个交付针对本样本结构。
- 资金行读取「币种」「余额」「可用」「可取」「参考市值」「资产」，原样留存源字段含义。「资产」已核对等于「参考市值＋可用」，「余额」与「可用」有差异。预览同时列出两条核对关系，区分券商展示资产与待核实的账面现金。现金未确认时可保存持仓快照及资金字段，展示纳入范围内证券市值和按证券市值计算的权重，待确认后再展示含现金的净资产和仓位。
- 明细读取「证券代码」「证券名称」「证券数量」「成本金额」「成本价」「价格币种」「最新市值」「当前价」「持仓盈亏」及适用的「参考汇率中间价」。代码按文本保留前导零。根据市场、产品及币种核对归类，对无法确认的证券在预览中列待确认。样本共 13 行，其中 12 行人民币报价，1 行港币报价。全表明细市值合计与券商参考市值一致，港币报价行的最新市值已含汇率折算，排除港股时从明细汇总中扣除一次。
- 成本金额和券商浮盈保留原值。样本多数行的成本价乘数量与成本金额无法精确到分对平，直接采用券商「成本金额」，保留成本价供核对。由快照显示的持仓浮盈标注为「券商持仓盈亏」，期初历史成本口径留待流水对账。
- 工作表内没有快照日期。文件名和表名为 `20271125`，文件修改日期为 `2026-11-25`。导入确认页展示差异，由用户选定北京时间对应的交易日及盘中／收盘状态。原文件名和文件时间仅作核查线索。确认收盘且日期可靠的快照才可设为期初，盘中快照可单独回看。

### 导入流程和展示

1. 打开「持仓分析」，选招商证券，导入本地 XLS，预览识别的资金、证券、纳入与排除数量，以及原始汇总与明细差异。日期必填，现金可以标记待核对。港股行即使排除，也参与券商原始参考市值的对账。
2. 确认后一次事务写入快照、资金和明细。文件哈希用于识别相同来源。同账户、日期及快照时点的相同内容重导返回已有结果。不同内容如有冲突，提示差异并显式确认更正，保留修订出处。导入证据仅在本地保存，原件、股东代码和金额不进入版本库、业务日志或测试夹具。
3. 第一阶段默认打开每户最近一次已确认快照，读取其全部持仓明细，展示原表市值、券商持仓盈亏和快照日期。个股最新本地估值可并列展示实际数据日期。流水接续后，当前持仓由认可的期初及其后已入账交易推算。新导的对账快照可比较差异，变更账本基点须明确确认，避免重复应用此前交易。ETF 暂无本地行情时，券商市值只用于其快照日期。个股可跳转既有投资笔记。
4. 华泰首份资料使用截图人工转录草稿，复用同一预览和持仓快照结构。日期相同且资金口径可比时展示合并净资产。日期不同可分别查看各自快照，同日合并数据缺口明确呈现。历史成交和资金流水到手后才启用区间收益。

## 招商历史成交导入

- 已有 2026 年历史成交查询样本，原生 BIFF8 XLS，有 59 条明细，实际记录日期为 2026-01-06 至 2026-11-12。以明细日期记录观察区间，查询区间和是否完整需结合导出条件及券商对账确认。
- 字段含成交日期、时间、买卖标志、成交价、数量、金额、成交编号、委托编号、证券代码和股东代码。实际包含 22 条买卖、18 条股息入账、9 条股息红利税补缴、5 条交收资金修正和 5 条交收资金修正取消。按券商业务标志分类，保留原值。买卖金额为正，样本全部买卖记录均与成交价乘数量对平至分，因此用它作成交总额，精确到账金额及费用用资金流水或交割单确认。分红、补税及交收修正先保留事件供对账，缺方向、币种或对应撤销关系的记录标记待核对。
- 成交编号有空值和重复，同日加股东代码也不能唯一标识所有事件，委托编号同样可复用。先按文件哈希识别整份重导，保留行号。跨批用日期、时间、业务标志、证券及金额等定位候选，明显重复须可追溯，重叠区间的歧义行在预览中核对。港股及币种不明记录显式标记，对应现金动作待资金流水核验。
- 第一阶段的持仓快照与历史成交各自预览、确认、保存，两个入口无需按固定顺序使用。历史成交进入账本表及复盘时间线，已保存的快照原值可回查。期初日及之前的成交仅用于回看。本站后续推算持仓时，从确认的期初收盘余额和之后已入账的事件计算。需要复算较早历史时，用可靠的期初余额、资金流水及公司行为对账，保留已有快照作校验点。后续导入资金流水时，将其与已保存成交事件匹配，买卖、股息和税金在账本只计一次。

## 建账与口径

1. 华泰已确认 2026-11-25 收盘，其期初现金采用用户确认的差额。招商独立确认交易日和现金口径。期初固定收盘持仓数量及可核实的账面现金，次日开始接续流水。逐证券保留成本及其来源，缺精确成本仍可记录数量或计算资料齐全的区间资产盈亏，涉及未知成本的浮盈估算和已实现盈亏按其覆盖显示。历史补录须从更早的可靠对账日重建，并复核现有基准日余额。
2. 账本至少支持买卖、出入金、利息、实收分红、费用及税、账户间划转、送转和拆并份额。成交数量按实际证券单位，金额按精确十进制计算，保存成交日、入账日及顺序等券商实际提供的字段。现金口径以对账单账面余额为准，核对时区分可用资金，避免成交和交割在同一笔现金上重复记账。版内暂按账户和证券移动加权成本，成本纳入买入费用，卖出净额用于计算已实现盈亏，股息单列。期初券商成本含义须核对，现金分红已冲减过成本时先厘清口径，避免重复计入。两账户都能对账后再比较盈亏，券商显示的摊薄成本可能采用不同定义。
3. 同账户证券卖出时结转对应成本，清仓后保留历史，重新买入开启新的持仓段。两个账户的内部现金划转用配对记录，在单账户视图作为资金流，在合并视图抵消。若跨日到账，合并视图跟踪已配对在途资金，悬而未配对的先列为待核对，避免当天凭空产生盈亏。首版不自动推断证券转托管或复杂公司行为，识别后列待处理。
4. 现金分红用券商流水实际到账金额，退补税用对应记录。公开分红和除权事件用于提示核对，股价字段用于估价。证券实收分红同时影响现金和盈亏归因，只记一次账户收益。
5. 区间盈亏金额 = 期末纳入资产 − 期初纳入资产 − 区间外部净入金。已实现与浮动盈亏、实收股息、费用用于解释盈亏，不能再加到净资产变化上。明确日期边界，期初收盘后的流水进入该区间，期末收盘的余额纳入期末资产。只有两个端点资产完整且其间资金流覆盖完整才发布该范围的总盈亏。聚合结果列出行情截至日期和缺失证券，缺口较多时可保留可核对日期上的金额复盘。
6. 首版优先提供金额和期末对账。净值、最大回撤及基准超额在第二阶段做。资金流时点估值和现金覆盖足够时，按外部资金流切段链接时间加权收益率，再绘制净值和回撤。按日数据采用明确的资金流时点约定，缺端点不生成完整曲线。基准须标明价格或总回报口径，选择同区间且口径明确的已保存序列。

同日合并视图按市场、证券类型和代码归并，同一标的展示一行、展开分户。合计数量使用同一估值日，同一标的市值用同一口径价格，分户原始市值仍可核对。剩余成本均可靠且口径可比时，合并成本价按合计剩余成本除以合计数量计算。账户或证券缺同日覆盖时显示缺口及分户实际日期，含现金净资产要求现金也有同日可比口径。

- 扩展本月、今年、自定义日期。开户至今入口提示有效历史仅覆盖 2026 年。日收益率估算为当日盈亏除以前一交易日 A 股收盘市值与当日买入资金之和。区间单利为日收益率之和，复利为每日增长因子连乘减一。缺值不连复利、无正数分母不报告收益率。累计盈亏与收益率曲线在零轴分色。
- 资产轨迹展示招商 A 股收盘市值，当前无可对账的独立 A 股现金，账户银证转账作为参考分开列示。盈亏日历可在年视图和月视图、金额和收益率之间切换，年视图显示 12 个月，点击可下钻。沿用只读 API，新增派生字段，不改存储表。

## 实现边界

| 层级 | 落点及职责 |
|---|---|
| HTTP 和展示 | 新增 `http/routes/portfolio.py`，由 `http/routes/dispatch.py` 显式分发，`http/server.py` 仅注册路由组。页面和私有 GET 走现有本机 Host 检查，预览、确认、更正的 POST 复用现有 Origin 和 `X-Local-Session` 检查，限定内容类型和大小。请求继续走 `RequestGate`，响应设 `no-store`。路由仅校验、调用和返回。模板及侧栏由 `http/rendering.py` 处理。页面、JS 和 CSS 按现有 `web/asset-map.json` 加入对应白名单，组合专用资源由组合路由匹配，避免扩大 `ShippingRoutes` 的职责 |
| 应用组装 | `application.py` 依据 `AppSettings` 注入已初始化数据库句柄与现有只读领域能力，行情按已初始化服务取得。初始化、备份和恢复重载走既有 `_initialize_runtime`、`_clear_runtime_services` 与 `runtime.py`。首批使用无常驻状态的服务组装，无组合专属缓存、锁、预览队列或调度器。GET 不走会惰性初始化数据库的通用入口，不走 `ensure`、`refresh`、首次建档、前复权租约或整股页面组装 |
| 组合领域 | `domains/portfolio/` 负责证券归类、查询、对账、来源留存、快照及流水提交。券商纯解析接收文件字节，产出结构化结果。组合和账本纯计算接收显式日期、行情及数量，不读文件、SQLite 或 HTTP。领域只依赖同层只读能力和存储基础，不导入 application 或 HTTP；组合笔记仍归 notes。首批不新增通用导入框架 |
| 数据所有权 | SQLite 保存四类组合事实，见首批表清单。证券在快照及交易中携带稳定身份。原有 stocks／valuation／financials 各自持有行情、估值和财务事实。已导入快照和流水不从属于股票关注状态，取消关注或清理不可删除组合事实。实施时验证清理既有来源后组合快照仍可回看，实时参考缺失正常呈现 |

|---|---|
| `portfolio_accounts` | 一个券商账户 |

| `portfolio_ledger_entries` | 一条按账户标识的原始成交或其他业务事件。保存业务标志、来源哈希及行号、已知数量和金额，以及对账状态。首批保存 2026 年招商历史明细，后续手录、资金流水和更正复用 |

快照表与明细表是一对多。最新快照按账户、业务日期、时间和有效修订选取。历史快照仍可按日打开。ETF 行情是否需要独立表，留待验证现有行情存储能否复用时决定。

- 预览只解析用户明确选中的文件，业务数据不写入。确认重新校验文件哈希及预览对应的账户、日期和修订基线。用 `Database.connection(write=True)` 与唯一约束保证并发重导、确认重试和冲突更正一致。原件由领域在配置注入的私有目录按哈希留存，先校验原件再提交引用。提交失败可以复用同一份原件，数据库只有提交成功的快照及引用。verification 下的样本和草稿供验收及显式导入，不作为启动自动导入或运行时读取目录。私有文件不开放静态下载，恢复时核对数据库引用与独立原件哈希。
- 新表按现有 migrations 链执行，同步 `docs/sqlite-storage.md` 和 `maintenance.py` 的 `DESCRIPTIONS`。快照头使用实际写入时间，明细按 `PARENT_TIMES` 关联快照头，核对 `TIME_COLUMNS` 和空表／缺值表现，交易日和快照日仅用于业务。隔离库验证旧版本升级、备份恢复及维护页发现、用途、分类、记录数、大小和时间依据。记录代表性占用和常用读取、写入耗时。上线时据实际实现更新后端及前端代码导航。

## 实施顺序与验收

1. **招商快照与历史成交一起交付。** 在隔离库用合成夹具验证快照导入和独立历史交易写入，真实样本只读核对 13 条持仓、港币行排除、原表汇总与现金差异，以及 59 条历史记录的业务类型、重复／空成交号、修正及取消。验收期初日及之前的成交不重复应用，费用和交收方向缺项可识别。验证快照查询、本地估值日期、ETF 行情缺口、笔记跳转，以及隔离迁移、备份恢复和新增 HTTP 边界，再按项目规则启用宿主 8765。
2. **手动单笔交易。** 在已有可用期初的账户上直接录入，无需等待导出文件。复用第一阶段的账本表，验证 A 股和 ETF 买卖、费用缺值与零值、更正、重复提交、与后续导入同笔成交匹配及真实分笔成交。
3. **接入华泰截图与资金流水。** 先让转录草稿走快照预览，日期与资金口径按资料覆盖确认。验收同一标的跨户合并、同日及异日覆盖状态、各户独立对账。资金流水阶段验证与已有成交匹配和重复入账防护、部分卖出、清仓重开、分红与退补税、送转、未配对与跨日划转、历史数据缺口及往期更正。两户对账通过且内部划转对合并区间盈亏为零后，再发布对应区间盈亏和贡献。组合复盘验收保存快照后内容可复核。
4. **连续绩效。** 数据覆盖足够后实现收益率、回撤及基准差。ETF 自动行情或穿透需另行核实来源。

验证按实际改动选择范围：新增路由覆盖本机 Host、Origin／会话、恢复门禁、路径匹配、响应不缓存和 GET 不写入，并定向运行 `tests/test_http_source_boundaries.py` 的对应检查。若提取共享估值投影，只补相邻估值和笔记快照回归；涉及清理改动时追加 `tests/test_stock_cleanup.py` 的对应场景。隔离库通过后，运行行为变更按项目规则安全重启宿主 8765 并做页面验收。计划文档变更只做静态检查。

#### 历史成交业务类别及字段

| 组别 | 选项与账本类型 | 手填字段与落库规则 |
|---|---|---|
| 买卖 | 买入／卖出，`buy`／`sell` | 证券、数量、均价。数量填正数，落库买入为正、卖出为负。沿用上表的成交额和费用规则 |
| 分红与税 | 股息入账，`dividend` | 填证券、券商入账日期和实际到账金额。输入正金额，`gross_amount`、`net_cash` 都记正。数量、均价和手续费留空，持仓数量保持原值 |

股息及补税采用实际到账或扣款日。A 股现金事件沿用账本的入账日。ETF 股息与本地公告事件按现有匹配逻辑对账，使用已确认的实际到账金额，并核验同笔分红只进入复算一次。允许输入「现金分红」「红利税补缴」等明确别名，在界面确认后归一为表中名称。

「交收资金修正」「交收资金修正取消」在现有历史中有记录，后续设计其录入时需选原流水并核对实际入账方向、金额及冲销关系。现有复算仅能识别已核对的部分样本。新股缴款／入账、配股与托管划转同样需要成组核对，再开放手工保存。首版保留这些券商原有历史记录并支持查看。

### 存储、来源和防重

- 两张表单写入既有 SQLite 表 `portfolio_ledger_entries`。复用账本持久化，将持久化字段补齐到现有 `fees` 列，券商导入路径仍可传空。新增手工来源由服务端生成带提交 ID 和用户确认字段的规范化 JSON，按内容 SHA-256 归档到现有私有 `portfolio_sources/`，记录 `source_sha256`、`source_name`、`source_row=1`、`fingerprint`、UTC `imported_at`。这一阶段沿用现有表结构。
- 表单一次提交生成稳定 ID，重试沿用相同 ID。同 ID 同数据返回已存在记录，同 ID 不同数据提示重新确认。在同一写事务复核提交 ID、账户和重复候选再入账。先校验和归档原始输入，事务失败可按同一来源安全重试。
- 跨来源识别候选要考虑同账户、日期、业务方向及归一后的数值。交易加证券、价格和数量，转账加方向和金额，辅以时间及流水号。成交号、委托号和银行流水号均用作核对线索。实现时用手录与券商导入两种顺序验证，保留合法分笔和原始来源，确认为同笔的重复行用现有 `duplicate_of_id` 关联并排除重复计算。补齐已有记录的券商证据和费用沿用上文的更正规则设计，单独核对其范围。
