# 设计决策

| 主题 | 本轮建议 |
|---|---|
| 实施顺序 | 第一阶段交付招商 XLS 持仓快照和已提供的 2026 年历史成交；按用户确认补齐华泰快照和同日合并。手动交易和资金流水后续复用同一事实结构 |
| 首批表 | `portfolio_accounts`、`portfolio_snapshots`、`portfolio_snapshot_positions`、`portfolio_ledger_entries`。快照头保存账户时点及汇总，明细按快照关联，交易事件独立保存 |
| 仓位展示 | 现金每份快照仅保存一次。优先按确认总资产计算仓位，现金未知时以证券市值为分母并标出口径 |
| 第一阶段确认 | 上载 XLS 先预览再提交；快照重传保留修订，历史记录以来源与行号保留，跨文件相同候选要求显式选择。来源原件按哈希存于活动数据库同级私有目录 |
| 建账方式 | 招商可先保存快照，确认收盘日及现金口径后设为期初。华泰已确认基准日和录入现金，合并区间从两户数据均足够之日算起 |
| 招商日期 | 文件及表名为 `20271125`，文件修改日期为 `2026-11-25`，表内无日期。导入时确认交易日和盘中／收盘状态 |
| 招商资金与成本 | 余额、可用、可取和券商资产分别保留。用户确认 2026-11-25 收盘现金为 12,773.42 元。成本采用原表成本金额，成本价与券商持仓盈亏供核对 |
| 招商历史成交 | 保存买卖及其他业务事件。期初前事件可回看，待资金流水到手后匹配实收实付及费用。成交编号和委托编号均不能单独用于去重 |
| 手动单笔交易 | 账户建账后可直接录入 A 股和 ETF 买卖，与导入走同一账本。后续导入匹配同笔成交时补齐证据及费用 |
| 华泰首份持仓 | 使用截图人工转录草稿，用户已确认 2026-11-25 收盘并采用总资产减证券市值作为期初现金。精确成本金额与交易随券商记录补录 |
| 双户合并 | 分户账本独立，同日按市场、类型、代码合并并展开分户。报价、日期和成本口径须可比，缺口显式显示。合并的内部划转抵消，跨日配对进入在途资金 |
| 首版收益 | 先做可对账的资产、盈亏金额和证券贡献。有完整估价及现金流后再做连续净值与绩效 |
| A 股和 ETF | 都进入账本。个股复用本地未复权行情和估值，ETF 缺价时允许带日期的用户输入或券商市值快照，跟踪指数只作为参考 |
| 历史盈亏临时估值 | 一天只涉及一只证券缺收盘时，使用该证券此前最近的本地未复权收盘价，记录实际报价日。缺少此前价格或涉及多只证券时保留缺口。原始行情和流水保持原值。 |
| 港股 | 暂时排除，范围内外资金移动按边界资金流处理 |
| 投资笔记 | 个股沿用已有 Markdown，组合复盘使用独立笔记身份和显式保存的数据快照 |
| 产品入口 | 独立「持仓分析」页，持仓快照默认为合并视图，历史成交以独立 Tab 展示 |
| 运行边界 | 组合属于独立领域，复用现有本机鉴权、恢复门禁和 SQLite 生命周期。读路径只调用已初始化的只读能力，组合不持有额外常驻状态 |
| 估值与来源 | 共享日期投影归估值域，组合与笔记分别调用。后续 ETF 批量行情走现有采集管理、来源预算及调度 |

招商快照的适配依据已齐。实际建账时确认日期和资金口径。华泰格式、两家历史流水能导出的长度、期初成本定义和划转配对依据随文件到手核实。
