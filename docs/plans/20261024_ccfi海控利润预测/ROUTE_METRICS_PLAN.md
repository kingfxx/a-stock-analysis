# 集团国际航线业务明细与历史回填方案

状态：已实施并完成2026-10-29现有15期回填；逐报告验收及两份旧报告独立解析限制见 `data/verification/reports/shipping-route-backfill-20261029.md`。

## 目标和范围

保留中远海控集团四条国际航线的财报原始累计货运量、人民币航线收入和折算美元航线收入；后续准备单期正式财报时提取，历史从已经存有的正式财报和解析资料补齐。提供可读的只读数据库视图。当前利润模型、默认情景与已保存预测不变，新增明细先用于解释和研究，不未经验证地进入预测。

2026-10-29只读盘点：现有集团业务指标覆盖2023Q1至2026Q3共15期，每期6项；15期均有对应正式财报记录。实际可提取范围以逐份PDF、解析文件及校验结果为准，不假定全部历史均完整。每期最多新增12项，15期理论最多180项，非覆盖承诺。若同一期存在修订或多份报告，逐份盘点并保留真实修订来源，不将不同版本混作一个报告。

## 存储与口径

复用 research_shipping_report_metrics，不修改既有表结构。metric 保持 teu、rmb、usd；scope 新增 transpacific、asia_europe、intra_asia、other_international，分别映射跨太平洋、亚欧（包括地中海）、亚洲区内（包括澳洲）、其他国际（包括大西洋），均为财报中的本集团航线；保留 total 和 domestic。basis=cumulative，单位、币种与原文一致。季度值由同年相邻期同指标差分，缺任一期留空；Q1使用累计本值。单箱收入仅在箱量为正且对应数据齐备时计算，不持久化派生结果。

新增提取器版本明确标识，记录 document_id、实际 parse_id、来源 PDF 页码及新增事实的真实写入时间。优先复用有完整页码的已登记解析；验证PDF哈希及解析与文档的关系，缓存不合格时使用已有正式解析流程重建；不从 verification 直接提供业务资料或为回填重新下载PDF。新提取器版本与现有六项共存时，读取端必须按 document/parse/提取版本确定优先顺序，禁止依赖 id 顺序无声覆盖或混用修订。提取版本是派生版本，不等于财报修订。

## 提取及历史回填

扩展现有三张集团表解析，排除“其中：本集团所属中远海运集运”子公司表；校验股票、报告期、表头、币种、单位、列顺序及四条航线、国内、合计。三季报选择当年累计列，直接披露的单季列仅用于交叉校验，不冒充累计；按各列核对航线汇总与集团合计，容许原表显示精度导致的合理舍入。每个指标记录其行所在实际PDF页，跨页时不能统一使用表头页。有效零和负值保留；缺失、格式不明、跨页不确定或对账失败时留缺口并记录原因，不猜测。

现有单期“准备此期正式报告与业务表”在用户明确执行时提取新增范围；历史批量回填需复用 collection 公共任务、分段、进度、互斥、失败记录和采集管理入口，默认关闭定时，不因页面读取启动。回填从本地已登记的范围内报告生成逐文档工作单，每个文档完成三表、哈希和来源校验后短事务发布；先保存验证证据，失败文档不发布未验证条目，其他已验证文档保留。按相同文档哈希、解析和提取版本幂等重跑；失败/缺口可定向重试。仅处理已登记正式资料，不触发外网下载、模型或扩大全市场采集授权。

## 查看及兼容

新增 SQLite 只读视图，关联 instruments、company_report_documents、company_report_parses，显示股票代码、报告期、中文指标与航线、原始值、单位、币种、累计口径、PDF页码、披露日、文档/解析ID、提取器版本、原件路径和真实写入时间。视图应清楚标识版本，避免把多次解析或修订误当多期；如提供当前版本视图，另保留历史版本可查。视图只展示原始累计事实，单季、增长和单箱收入在读取层按需要计算。

修正 business_quarters 只对模型必需的 total/domestic 人民币收入和箱量做逐字段差分；新增明细缺期或美元缺期不阻断既有锚点。旧预测版本读取和结果不被新行、不同提取版本或报告修订的混用改变；实际新增事实可供下一目标季度模型采用，但不修改历史快照。新增视图的维护用途及存储文档按项目规则同步。

## 验证与验收

1. 隔离样本覆盖Q1、半年、Q3、年报、跨页、不同布局、错币种、错季度、子公司表干扰、缺航线、零/负数、算术不平及修订；检验每行证据页、幂等、分段失败原子性与恢复。
2. 验证新增航线仅部分期存在、上一期缺字段、同时存在不同解析版本/报告修订时，原模型依然使用正确的四个基础字段；既有保存预测快照不变。
3. 先隔离库对全部已有财报逐份试提取，核对哈希及与原六项合计，至少抽查各类报告布局和2026Q3全部12项与原PDF一致；输出逐报告/逐字段覆盖及失败原因，不把执行成功当作覆盖完整。
4. 完成隔离测试并核对正式后台活动任务后，使用采集管理显式执行已授权的本地历史回填；验证数据库条数、无重复、证据引用、视图和页面；记录实际成功/缺失范围。若遇到结构不兼容、解析歧义或原件缺失则停在具体分段并如实报告，不补造。
5. 同步 docs/shipping-forecast.md、SQLite存储及维护说明；保存验收报告。涉及服务代码时按项目规则安全重启8765并检查日志和页面；测试及临时文件按规则清理。
