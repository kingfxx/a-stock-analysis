# 传统价值投资分析：信息缺口与后续建设计划

日期：2026-10-01。

状态：分析与规划已记录，尚未实施。2026-10-01 补充第一批建设框架、SQLite 命名与存储建议、抽取校验及验收步骤（见第 7 节）。本文将巴菲特、芒格、彼得·林奇、格雷厄姆等投资者的理念转化为项目研究需求，不代表这些投资者共同使用一套固定公式。阶段划分是后续建设建议，具体数据源、接口、存储结构及界面方案须在实施前核实。

关联文档：[现有 AI 研判计划](2026-10-01-ai-stock-assessment.md)、[AI 研判说明](../ai-stock-assessment.md)、[项目说明](../../README.md)。

## 1. 核心判断与研究顺序

当前项目能够观察公司的财务表现，但仍不足以解释公司为什么赚钱、还能赚多久，以及股东最终能得到多少。

后续研究顺序调整为：

1. 理解公司靠什么赚钱及其经营驱动。
2. 判断利润、现金流和资产的质量。
3. 核实竞争优势、再投资机会和资本配置。
4. 检查坏情况下的生存能力。
5. 按公司类型估算价值，再判断价格与安全边际。

下一阶段的重点是为每家公司建立有原文出处的生意档案，让财务变化能对应到经营原因。行情和筹码继续作为补充，不能替代企业价值研究。

## 2. 现有能力与实际分析范围

已具备的基础包括：

- 长期营收、归母净利润、增长率及利润率。
- ROE、简化 ROIC、经营现金流、资本开支和简化自由现金流。
- 货币资金、有息负债、简化净现金、已实施分红及年度分红率。
- 股价、PE/PB/PS、股息率、历史估值分位和当前行业均值。
- 股东人数、融资数据及其与股价的配对变化。

核查依据为 `quarterly_dashboard/sources.py`、`quarterly_dashboard/analysis_snapshot.py` 和现有文档。记录时，AI 财务证据仅提供最近 12 个单季度、8 个 TTM 和 5 个年度；本地更长历史不等于已全部进入模型输入。

当前 AI 尚未接入主营业务、公告、财报附注和经营异常原因资料。现有行业均值也不能替代具体竞争对手的经营对比。

当前三表接口返回范围大于标准化字段范围：应收、存货等科目应先核查原始响应及本地保留情况，再决定扩展解析或新增来源。不能把“尚未结构化”“未展示”“未进入 AI 输入”统一视为“没有抓取”，也不能仅因来源返回过字段就认定已有可用历史。

## 3. 七类关键缺口

### 3.1 生意结构与增长驱动

要回答：公司卖什么、卖给谁、怎样收钱，增长来自哪里？

需补充：

- 分产品、业务和地区的收入、毛利及历史变化。
- 销量、售价、单位成本；按行业补充门店数、单店收入、客户数等经营指标。
- 产品销售、订阅、工程项目等收入模式，以及收入确认和回款特点。
- 前五大客户和供应商集中度、关联方占比及重大变化。
- 行业需求、竞争格局和主要竞争对手。
- 增长来自量、价、产品结构、并购或合并范围变化的证据。

林奇式分析需要一条可验证的公司故事：增长来源、剩余空间及故事失效条件。相同营收增速可能对应不同质量，不能只看汇总增长率。

### 3.2 竞争优势与持续性

要回答：高资本回报为什么不会被竞争消灭？

| 判断方向 | 所需证据 |
|---|---|
| 定价权 | 提价记录、提价后的销量与客户变化、相对同行的价格和毛利 |
| 成本优势 | 单位成本、规模效应、产能利用率及同行成本位置 |
| 客户黏性 | 续约、复购、流失及替换难度、切换成本 |
| 渠道或网络优势 | 渠道覆盖、终端动销、平台参与者与交易活跃度 |
| 牌照或技术壁垒 | 许可期限、研发转化、替代技术和竞争者进入情况 |

长期高 ROIC 是线索，竞争者难以复制的原因才是进一步判断的依据。未披露的经营指标保留未知，允许人工补证；不能由 AI 根据行业名称补出护城河。

### 3.3 盈利质量与资产质量

要回答：利润能否兑现，资产账面价值是否可靠？

需补充：

- 扣非归母净利润、非经常性损益明细。
- 政府补助、处置收益、投资收益、减值及研发资本化等会计处理。
- 应收账款、应收票据、合同资产、账龄和坏账准备。
- 存货结构、跌价准备、周转及其与收入增长的关系。
- 商誉、在建工程、无形资产及减值。

目标是从“利润与现金流背离”进一步定位到正常扩张、回款恶化、库存积压等可能原因，并区分证据与待验证解释。

### 3.4 所有者收益与再投资需求

要回答：维持这门生意需要投入多少钱，实际可分配收益有多少？

需补充：

- 折旧摊销和长期资产变化。
- 维持性与扩张性资本开支的区分及估计依据。
- 维持经营所需的营运资金。
- 受限现金、必要经营现金及资金在子公司的分布。
- 少数股东权益，以及合并现金流的归属处理。

当前“经营现金流－资本开支”是分析起点，不等于精确股东可分配现金。维持性资本开支通常需要估计，应保存依据、假设和区间，不能机械等同于全部资本开支或折旧。

### 3.5 管理层与资本配置

要回答：管理层是否为每股价值增长有效使用股东资金？

需补充：

- 回购金额、价格，及最终注销或用于激励的情况。
- 增发、配股、可转债、股权激励及每股摊薄。
- 并购价格、业绩承诺、实际兑现及商誉减值。
- 重大投资项目的预算、进度和投产收益。
- 控股股东、管理层持股、激励安排及重大变化。
- 关联交易、资金占用，以及过去承诺的兑现情况。

增加每股盈利和每股价值视角；公司总利润增长不必然意味着每股价值增长。分红记录只是资本配置的一部分。

### 3.6 财务韧性与永久损失风险

要回答：坏情况发生时，公司能否撑住？

需补充：

- 债务到期分布、融资成本、短债与可用现金的匹配。
- 受限资金、质押、担保、诉讼及其他或有负债。
- 商誉和其他难变现资产占净资产的比例。
- 审计意见、内控缺陷、财报更正和监管处罚。
- 收入下降、毛利下滑、回款变慢情景下的现金承受能力。

账上现金不等于可自由使用的现金，净资产不等于清算可收回价值。债务总量与简化净现金不足以单独证明偿债安全，低 PB 不足以排除价值陷阱。

### 3.7 公司分类、内在价值与安全边际

要回答：应采用哪种估值方式，当前价格隐含怎样的经营预期？

需补充或建立：

- 缓慢增长、稳健增长、快速增长、周期、困境反转、资产价值型等分类及其依据，允许类型变化。
- 跨完整周期的盈利和资本回报，适用时扩展到十年或更长。
- 行业专属指标：例如银行的资产质量与资本充足情况，制造业的产能、库存和单位盈利。
- 正常化盈利或现金流估计。
- 悲观、基准、乐观情景及关键假设敏感性。
- 当前价格隐含的增长要求与安全边际。

历史分位描述市场过去的定价位置，不等于内在价值。周期企业盈利高峰时可能呈现低 PE，不能统一套用低倍数或 PEG 判断。行业分类已知也不等于通用财务和估值口径适用。

## 4. 分阶段补充顺序

| 阶段 | 建议补充内容 | 解决的问题 |
|---|---|---|
| 第一批 | 年报、半年报、重要公告；主营业务拆分；扣非与非经常损益；应收、存货、受限现金；审计与担保 | 理解生意并识别利润、资产及生存风险 |
| 第二批 | 同行经营对比、行业专属指标、回购与摊薄、并购和项目兑现记录 | 判断竞争优势、增长质量与资本配置 |
| 第三批 | 维持性资本开支估计、正常化盈利、情景估值与安全边际 | 判断何种价格值得进一步考虑 |

实施前先建立来源与字段清单，逐项标明已有可复用、需扩展解析、需新增采集、需人工判断。候选材料包括交易所和巨潮披露文件、公司投资者关系资料、行业统计及同行报告；尚未验证接口稳定性、历史覆盖和抽取准确性，不将候选来源写成已接入能力。

## 5. 证据组织与 AI 分析要求

- 每条新增证据保存股票、报告期或统计期、实际披露日、来源链接、原文页码或章节、单位和口径。
- 区分来源原文、结构化事实、计算结果、人工估计和模型判断。
- 记录缺失、未披露、不适用及抽取失败，不能用零值代替未知。
- 保存同行选择理由及可比性限制；不以行业平均代替经营竞争力判断。
- 经营变化的原因必须有证据；没有证据时以待验证假设呈现。
- 重要假设保留反证、比较基准、观察窗口和判断改变条件。
- 根据公司类型选择历史窗口和指标，避免重复季度及 TTM 数字挤占经营证据。
- 处理同一财报的更正版本与可见日期，不能将后续修订冒充当时已知。

当前 `candidate_allowed` 主要检查基础财务、估值和行业资料是否满足已有条件。这表示可以生成现有范围的报告，不代表完成价值投资核查。后续应区分“初筛可分析”和“关键问题已有证据”，具体门槛在实施设计时确定。

不得仅通过修改提示词，把缺失经营材料转化为更强结论；应先补证据，再调整分析范围及报告表达。

## 6. 后续验收方向

- 能说明公司的主要盈利来源，并用来源材料解释关键财务变化。
- 能区分高质量增长与价格、并购、一次性收益等驱动。
- 能指出竞争优势的支持证据和最强反证，资料不足时明确未知。
- 能识别可用现金、债务期限及资产质量对风险判断的影响。
- 能追踪资本配置对每股收益和价值的影响。
- 能按公司类型解释估值适用性，区分历史便宜和内在价值安全边际。
- 新证据及关键假设可追溯；抽取错误、缺项和修订不会被静默掩盖。

软件验收关注证据完整性、口径一致性和推理可核查性，不以投资收益率作为实施验收标准。

## 7. 第一批建设框架

### 7.1 目标、范围与交付边界

第一批交付一份能够追溯原文的公司经营与财务质量档案，优先回答：

1. 主要收入来自哪些业务，报告期内哪些业务发生变化？
2. 归母利润中有多少属于披露的非经常性损益？
3. 应收和存货变化是否提示需要进一步核实的回款或积压问题？
4. 货币资金中有多少明确受到限制，是否有重要担保或审计事项？
5. 上述结论哪些有证据，哪些因披露、采集或解析缺口仍不能判断？

本批建立证据与事实基础，不承诺完成护城河判定、精确可用现金估计、内在价值或完整行业模型。不能仅凭补齐这些材料就声称完成价值投资尽调。

建议默认覆盖最近三个完整年度年报，加上最新半年报及上年同期半年报；如果尚无更新的半年报，不把早于最新年报的半年报当作当前经营状态。上市不足三年的保留实际覆盖，明确历史不足。这是第一批可验证范围，不缩短已有三表历史；十年经营附注回溯留待来源和解析稳定后扩展。

重要公告采用明确类别，首批覆盖财报更正、审计或内控意见变化、担保及重大履约变化、资金占用或冻结，以及影响上述财务解释的重大事项。默认发现最近一个已覆盖年度期末至今的公告，并回溯最新报告中仍存续事项引用的前序文件；该发现窗口不等于完整事件历史。其他重大经营变动先保留文件、摘要和来源，不在第一批强制结构化所有事件。

### 7.2 采集前先验证来源与字段

| 内容 | 优先核查路径 | 第一批需要确认 |
|---|---|---|
| 年报、半年报、重要公告 | 交易所或巨潮披露文件；公司投资者关系资料作补充 | 公司身份、正式全文与摘要区别、披露日期、文件版本、下载与历史覆盖 |
| 三表已有科目 | 现有 `financial_reports.raw_json`，不足时通过现有源补齐 | 科目名称、单位、合并范围、历史完整性，能否直接扩展解析 |
| 主营拆分、扣非明细及附注 | 正式报告正文和附注；结构化来源作为抽取辅助 | 表头、期间、行列含义、单位、原文定位及合计关系 |
| 审计与担保 | 财报正文、审计报告及对应公告 | 意见原文、报告对象、担保存续状态与重复披露关系 |

目前代码已按报告期保存新浪返回的报告记录 JSON，并在读取时解析。因此，先检查这些已保存记录，避免重复抓取或建立另一份无来源关系的三表数据库。原始记录 JSON 不等于整份 HTTP 响应，也不保证含有所需附注。

首个实施产物应是小样本来源矩阵：字段是否存在、是否可定位原文、历史范围、更新方式、失败表现及可复用程度。公开候选入口尚未经过本批实测，不能直接写为生产可用接口。

### 7.3 命名规范与领域归属

新增表采用 `领域前缀_实体复数`，小写加下划线；不在业务表名中放数据源、年份、`new` 或 `v2`。既有基础设施表允许保留当前名称，不为满足复数规则机械重命名。

| 前缀 | 归属 |
|---|---|
| `disclosure_` | 披露文件、原文证据、抽取过程和资料覆盖状态 |
| `financial_` | 财务事实、主营拆分和财务附注 |
| `governance_` | 审计意见、担保等治理与责任事项 |
| `price_`、`valuation_`、`dividend_` | 行情、估值、分红；行情旧表前缀统一另做迁移 |
| `financing_`、`shareholder_` | 融资融券及股东资料 |
| `stock_`、`ai_analysis_` | 用户股票整理及 AI 分析 |
| `sync_`、`legacy_` | 同步过程与历史兼容 |

按实体本身归属，不按文件出处归属：担保公告和年报都属于 `disclosure_documents`，它们披露的担保关联同一类治理实体；不会因为担保出现在年报里就再造一套财务担保表。

- 索引：`idx_<完整表名>_<用途>`；独立唯一索引：`ux_<完整表名>_<用途>`；触发器：`trg_<完整表名>_<动作或用途>`。
- 股票外键统一沿用 `instrument_id`，文档用 `document_id`，抽取任务用 `extraction_run_id`，避免与现有同步 `run_id` 混淆。
- 日期用 `_on`，时间戳用 `_at`；`published_on` 保存只有日期的披露信息，确有时刻才保存 `published_at`，不虚构午夜时刻。
- 期间事实用 `period_start`、`period_end`；时点事实用 `as_of_date`；报告自身的期末用 `report_period`。
- 现有 `report_overrides` 可在专门迁移中改为 `financial_report_overrides`。旧表及字段重命名必须同步审查 SQL、触发器、测试、维护工具和文档，不修改已经执行过的历史迁移文件。

第一批新增表直接遵守规则；全库旧表重命名单独排期，避免与新采集逻辑混在一次变更中。

### 7.4 存储分层与建议表清单

采用“原始文档 → 有来源的披露事实 → 程序计算及分析结果”。不同公司的业务名称可不同，事实的期间、单位、范围、来源和校验方式统一。

下表是逻辑设计，DDL 在样本核查后确定。目标约为九张新增表；不为每个新指标建立新表，也不为凑表数合并生命周期不同的实体。

| 建议表 | 职责及关键关系 |
|---|---|
| `disclosure_documents` | 每份具体版本文件的股票、类型、标题、报告期、披露日期、来源标识、URL、本地路径、内容哈希及更正关系 |
| `disclosure_evidence` | 原文证据：所属文档、章节、PDF 页序、印刷页码、表头/行列位置、原文摘录；接口记录可保存 JSON 路径及来源键 |
| `disclosure_extraction_runs` | 文档抽取任务：解析器版本、方法、状态、诊断及必要模型信息；关联已有同步任务，不复制整个同步系统 |
| `disclosure_coverage` | 按股票、报告版本、主题记录资料覆盖、适用性、缺失原因和检查时间 |
| `financial_breakdowns` | 某份报告中的一组业务、地区或其他拆分，保存分类轴、口径、是否完整、是否可加总、合计与抵销规则 |
| `financial_facts` | 受控指标字典下的数值或分类事实，覆盖扣非、应收、存货、受限资金和主营拆分；关联证据、抽取任务及可选拆分组 |
| `governance_audit_reports` | 对应报告的审计或审阅性质、机构、意见、持续经营事项及相关原文证据 |
| `governance_guarantees` | 可识别的担保主体、对象、关系和业务身份，承担事件去重职责 |
| `governance_guarantee_observations` | 同一担保各披露时点的额度、实际余额、期限和状态，关联文档及证据 |

第一批不额外建立跨年永久分部主数据表；先忠实保存“某报告版本的一组拆分”。只有实际需要且有可靠依据时，再增加跨年分部映射。受限现金、非经常损益也先作为带类别维度的事实保存，避免每一类附注各造一张相同结构的表。

指标字典先作为有版本控制的配置维护：定义代码、中文名、数据类型、单位、期间性质、适用范围、允许维度和校验规则。第一批不支持任意用户创建指标；未来出现在线维护需求再考虑字典表。`financial_facts` 是受约束的财务事实集合，不用于存任意键值。

PDF 等原件存放在正式数据目录，例如 `data/disclosures/`，不放入可清理的验证缓存。数据库备份之外还需有按文件哈希生成的原件清单和增量文件备份；恢复验收必须核对数据库引用的原件仍存在。本文路径为拟定路径，实施时纳入存储文档。

### 7.5 财务事实的统一结构

每项事实至少描述以下内容：

| 维度 | 需要保存的信息 |
|---|---|
| 身份 | 股票、指标代码、原文科目名、所属文档/来源记录、抽取版本 |
| 时间 | 期间起止或时点日期；本期/比较期；对应报告的披露时间 |
| 范围 | 合并/母公司/分部；归母/合并利润；余额/净额；持续经营等适用口径 |
| 数值 | 原文数值、原单位和倍率、币种、标准化数值及单位、披露精度 |
| 明细 | 拆分组及受控维度，例如产品、地区、存货类别、受限原因、账龄 |
| 来源 | 证据编号、来源原始键或内容哈希、解析器版本 |
| 状态 | 是否披露、校验状态、冲突/替代关系及原因 |

常用筛选项用普通列；可变业务维度可使用经过字典校验、排序和规范化的 JSON，并生成稳定维度键。相同维度的不同 JSON 键顺序不应制造重复事实。唯一约束必须覆盖来源版本、指标、期间、范围和维度；可选字段的空值语义须显式设计，不能依赖可空列的唯一约束实现去重。

数值保留原文和精度。新事实的精确数值建议用规范十进制字符串保存，由 Decimal 完成换算和勾稽，展示时按需转换；不依靠对文本列的隐式 SQL 数值转换求和。金额、百分比、数量和单价分别定义单位，不能将存储类型为数值误当成口径一致。该规则适用于新增事实，不在本批全面改造已有 REAL 字段。

披露值、程序计算值、人工修订和模型判断必须区分。第一批事实表主要保存披露与核实后的修订；计算结果由有版本的计算层产生，保存输入事实编号。模型意见进入 AI 报告，不写成公司披露事实。

### 7.6 主营业务如何跨公司标准化

统一的是结构，不强行统一业务名称。例如两家公司分别披露“白酒”和“动力电池”，均可保存营业收入和营业成本；各自销量保留吨、GWh 等单位，不能因同为 `sales_volume` 就直接跨公司比较。

- 产品、业务、地区、渠道是不同分类轴。同一营业收入在多种拆分中重复出现，禁止跨拆分组相加。
- 产品×地区交叉披露保存为一个拆分组内的两个维度；不伪造公司未披露的交叉结果。
- 总计、小计、其中项、其他和抵销项显式标记。只对同一完整、互斥且口径一致的拆分执行合计检查。
- 公司仅披露达到门槛的主要业务时，覆盖状态为部分；未列出的业务不视为零。
- 原文名称保存不变。跨年重命名、拆分或合并只有在报告说明或其他明确依据下才能映射；没有依据就提示不可比。
- 营业收入、主营业务收入、分部收入及分部利润不可混用；合计目标由拆分组定义。
- 毛利率优先保留披露值；有同口径收入和成本时可另算并校验。禁止用分部利润冒充毛利。

### 7.7 第一批各主题的最小字段与校验

| 主题 | 最小可用内容 | 关键校验或限制 |
|---|---|---|
| 主营业务 | 业务说明原文；分部名称、分类轴、收入，披露时补成本/毛利率 | 本期与同期可比；拆分组是否完整；总计与抵销 |
| 扣非及非经常损益 | 归母净利、扣非归母净利、归母口径非经常损益净额；披露时保存税前项目及税额、少数股东影响 | 同期间归母净利－扣非归母净利与归母口径净额勾稽；明细按原文符号及税后归属转换，不机械相加 |
| 应收 | 应收账款净额；披露时补余额、坏账准备、账龄、票据和合同资产 | 余额－准备与净额勾稽；票据、应收款项融资、合同资产保持独立；不能简单全部相加 |
| 存货 | 净额及披露的类别、余额、跌价准备 | 余额－准备与净额勾稽；类别完整性与总计；非适用行业不强制要求 |
| 受限现金 | 金额、现金类别、限制原因、报告时点，披露时补解除条件 | “受限资产”总额不能当受限现金；只有确定属于货币资金的项目才参与相关比较；部分明细不能冒充完整受限总额 |
| 审计 | 对应财报、审计/审阅/未经审计、机构、意见原文及标准类别，持续经营/强调事项/关键审计事项 | 财报审计与内控审计分开；关键审计事项不自动判为负面；未找到意见不等于无保留意见 |
| 担保 | 主体、对象、关系、批准额度/实际余额、披露和统计日期、状态，披露时补期限 | 总额度与已发生余额分开；集团汇总与单笔明细分开；不同日期的余额不累加；无法识别同一事件时禁止自动归并 |

数值误差容限依据原文单位、舍入精度和参与合计的项目数确定，不使用一个宽泛固定百分比掩盖抽取错误。勾稽成立是必要检查，不能证明语义全部正确。

第一批允许银行等公司进入资料档案，但金融企业的应收、存货、现金流等指标按适用性显示；专属风险指标尚未覆盖时，不能套用普通工业企业结论。

### 7.8 抽取、校验与缺失状态

建议流程：发现文件 → 下载并核对身份/哈希 → 定位章节和表格 → 抽取候选事实 → 口径与数值校验 → 发布有效事实 → 生成可追溯摘要。

优先使用确定性解析；复杂表格允许模型辅助，扫描文件按需 OCR。记录所用方法及版本。后台更新不得隐式触发未说明的付费模型调用，模型辅助任务需要在产品入口明确展示处理范围。

抽取过程的状态与资料本身的状态分开：

- 资料状态：有披露、明确未披露、不适用、部分覆盖、尚未检查、来源不可达。
- 抽取状态：待处理、抽取成功待校验、自动校验通过、人工核实、校验失败、来源冲突。

只有已检查相关材料后才可认定未披露；未找到文件、下载失败和解析失败都不能记为未披露。“未经审计”“无担保”等是需要原文支持的业务事实，不是默认值。

候选事实可直接保存在同一事实表并带状态，通过查询层控制有效版本，无需复制整套待审核表。人工只重点核实冲突、低可靠度或关键异常，避免要求逐项手工审批所有正常数据。模型自报置信度不能单独决定发布。

发布按主题和报告版本组织：成功完成的主题可以独立使用，失败主题保留旧有效版本及过期提示；不把新旧版本混合成一套声称完整的明细。AI 输入显式列出哪些主题通过了哪些校验。

### 7.9 更正、重复文件与跨来源冲突

- 文档按来源业务标识和内容哈希去重；相同文件出现在多个入口时保留来源别名，不重复抽取。同一 URL 内容变化视为新版本。
- 更正文件、重述比较数和解析器修正分别记录：公司更正改变披露事实；解析器修正改变提取结果，不能伪造新的公司披露日期。
- 文档不因标题相似就整份替代；更正可能只影响某个主题或字段，应按明确范围关联。
- 同一报告期在不同年份报告中出现的比较数全部保留。当前研究可选择明确更正后的有效值，历史分析仍受当时可见资料约束。
- 新浪等接口值与正式报告冲突时，核对单位、范围、版本和日期，再决定有效证据；“官方文件优先”不等于无条件相信从官方 PDF 中抽错的数字。
- 已有 `financial_reports` 当前按股票、来源、报表类型和期间更新，不能据此承诺恢复过去未保存的版本。新增文档版本从接入起保留；跨系统点时回测完整性仍单独标注。
- AI 历史报告继续引用生成时的证据快照，不随有效事实切换而改写。人工修订保留原因、时间和原始值，不能静默覆盖来源。

### 7.10 页面与 AI 接入

第一批入口建议为“公司资料”，按主营、盈利质量、资产质量、资金限制、审计与担保展示。每个主题显示资料日期、覆盖情况、事实与来源，能够打开对应原文页。后台刷新沿用已有按股票加载方式，新增文件处理展示独立进度，避免阻塞现有财务图。

AI 接收经过选择的事实、有限原文片段及缺项影响，不默认发送整本年报。证据编号必须指向实际存储版本；长文摘要保留段落来源，报告中的数字优先来自程序事实。

暂不增加统一“资料完整百分比”。不同类型企业的必要主题不同；分别显示“现有基础数据可分析”和“本批关键资料已核实”。即使第一批资料齐全，也不自动提升为买入候选；经营质量、竞争优势和估值判断仍各有证据要求。

缺少主营拆分时，不推断增长由某产品驱动；缺少受限现金完整明细时，不把差额称为精确可用现金；审计与担保资料缺失时，不写“未发现风险”或“无担保”。

### 7.11 实施顺序与验收关口

| 步骤 | 产物 | 通过条件 |
|---|---|---|
| A：样本核查 | 来源矩阵、指标字典草案、原文样本和人工核对基准 | 明确已有字段可复用范围；每个首批主题有成功样本和失败/缺失处理样本 |
| B：证据底座 | 文档、原文定位、版本、覆盖与任务状态 | 重复获取幂等；更正版本保留；失败不冒充无披露；文件备份可恢复 |
| C：财务事实 | 主营及财务附注的受控抽取与校验 | 单位、期间、范围和合计可核对；业务分类变化不制造虚假连续趋势 |
| D：治理事项 | 审计与担保结构化及去重 | 不混淆意见类别，不重复累计担保，不把未知当作零风险 |
| E：用户与 AI 验收 | 公司资料页、证据引用及受限分析 | 事实可追溯；缺项影响明确；原有图表与历史报告可正常使用 |

样本至少覆盖消费品、制造业、软件/服务和银行等不同披露结构，并包含分类变更、非经常损益为负、受限现金部分披露、更正报告及重复担保公告。可优先沿用已有公司样本；具体公司以能取得足够真实材料为准，不预填未核实的财务事实。

人工基准中实际披露的目标项同时核查漏提与错提，不能只检查已提取数字的准确性。核心字段不得存在未解决的公司、期间、单位、范围或来源错配；确实无法抽取的项目明确保留失败状态，并确认不会进入正式分析。

数据库测试使用隔离临时库，覆盖迁移、幂等、版本选择、故障恢复和引用完整性。新功能代码通过相关测试后，按项目规则重启 8765 日常后台验收；本次计划文档更新无需重启。

验证资料沿用 `data/verification/samples/`、`reports/`、`audits/`、`tools/`、`logs/` 分类；正式披露原件不纳入一次性产物清理。

### 7.12 实施前仍需通过样本决定的事项

- 正式文件发现与下载接口的可用性、历史范围、限流和增量方式。
- 哪些三表字段可直接扩展现有解析，哪些必须读取附注。
- 复杂表格使用的解析/OCR方式及模型辅助的实际成本和错误率。
- 事实的最终唯一键、索引、字段类型与约束，以及来源证据的一对多关系是否需单独关联表。
- 行业适用性和主题覆盖规则，特别是金融企业的边界。

上述事项不阻碍先完成样本核查，但在获得证据前不把建议表结构视为已冻结的数据库设计。
