## 归属与依赖原则

1. 业务归 `domains/`；领域采集使用公共 `collection/`，领域数据访问使用通用 SQLite 能力。计算代码最终只接收输入、返回结果，不主动取数、写库或启动任务。
2. `http/` 解析请求并调用领域服务；领域模块不依赖 HTTP Handler。应用组装最终放入 `runtime.py`。
3. 公共采集机制与任务注册分清：请求预算、锁、归档为公共底层；管理和注册层可以显式适配领域采集器，不能使底层调度反向依赖业务注册。第一阶段保留既有依赖语义，架构解耦另列第三阶段改动。
4. `industries/` 提供跨行业的通用能力；`research/sectors/` 提供行业专属数据与模型。航运现有 601919 专属限制保持，其他公司模型有真实需求再扩展。
5. 第一阶段保留现有文件名、函数名、类名及兼容实现；不同时缩短前缀或重写逻辑。`core.py`、`update_service.py` 等在第三阶段按真实职责拆分和命名。
6. 不强制每个主题都建立同样的 service/repository/model 层，不新增无用途的 utils、插件框架或抽象基类。

- 作为 Python 生成缓存，不搬迁、不提交，新包运行后自然重建；保留现有忽略规则。
- 旧包源码迁移及停止旧后台后，核对解析后的绝对路径属于本仓库旧包，再清理旧包缓存；新包测试缓存按验收资料清理规则处理。
- 不递归清理 data、正式备份、运行资料或其他环境；缓存清理不代替源码引用与导入验收。
