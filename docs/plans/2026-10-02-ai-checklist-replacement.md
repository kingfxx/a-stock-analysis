# 用定性 checklist 替换页面 AI 研判的实施计划

日期：2026-10-02。状态：已按本计划实施，具体存储兼容方式和首阶段限制见下文。

## 已确认目标

- 页面启用新的 18 项定性 checklist，每项一句话，必要时两句话，默认只显示项目与结论，依据可展开。
- 保存旧 AI 研判的逻辑、提示词、校验、输入与输出版本和历史记录；当前页面不启用、不展示旧研判入口和旧报告。不是删除或覆盖旧报告。
- 复用现有 AI 登录、模型列表、调用接口、取消、队列、幂等、用量和诊断能力。
- 数值由本地程序提取和计算，模型只依据本地资料包整理定性结论。新功能不自动沿用旧“买入候选”等判断标签与旧筹码假设。
- 公司财报原件、提取文本、业务事实及来源要能复用和核对，正式资料不放在 verification 中。

## 现有系统可复用与需调整的部分

| 部分 | 现状与计划 |
|---|---|
| AI 接入 | 保留 `ai_provider.py` 及连接设置。继续沿用用户选择的模型，不更换账号或另设 API Key |
| 任务执行 | 复用 `AnalysisService`/`AnalysisRepository` 的队列、取消、幂等、失败保留与历史管理机制；按报告类型选择快照与校验器 |
| 输入快照 | 现有 `analysis_snapshot.py` 是本地只读事务快照，保留给旧研判；新增 checklist 快照，不套用旧数据准入要求 |
| 输出 | 旧输出版本继续保留；新版本 `stock_checklist_output_v1`，不产生 verdict、五维评分或买卖倾向 |
| 展示 | 现有 `web/ai-assessment.js`、CSS 的旧展示逻辑保留但不挂载，新增 checklist 展示；页面按钮改为“投资 checklist” |
| 资料管理 | 现有四表不变，新增财报文件索引、解析与事实缓存，不把业务事实塞入 financial_reports.raw_json |

兼容处理：保留迁移 007 和旧任务表结构，不重建历史表。迁移 008 只增加三张财报资料表。新任务以 output_schema_version 筛选；为满足已有成功任务约束，数据库 verdict 写入内部类型字符串 checklist，模型输出和页面均不产生投资判断标签。旧报告、输入版本及生成逻辑继续保留，公共页面与接口只使用新版本。

## 正式财报目录

根目录：`data/company_reports/`，新增 Git 忽略规则。使用交易所和代码识别股票，不用可能更名的中文名称，不在正式路径中使用样例日期。

```text
data/company_reports/
  sh600887/
    2025-12-31/
      <完整文件SHA256>/
        report.pdf
        manifest.json
        parsed/
          <解析器版本>/
            pages.jsonl
            quality.json
```

当前 A 股定期报告按报告期识别：`12-31` 为年报、`09-30` 为三季报、`06-30` 为中报、`03-31` 为一季报，目录不再增加 annual/interim/quarterly 层。报告类型仍保留在 SQLite 索引与 manifest 中，便于查询和校验，不能仅凭目录日期认定下载的是完整定期报告；摘要或其他公告不作为同一完整报告导入。中报用 `2026-06-30/`；一季报用 `2026-03-31/`。第一阶段自动准备最新完整年报、最新中报；季报文本只在明确需要更新的项目中补充，数据库四表仍采用最新适用季度。不批量下载十年 PDF，也不对全部股票自动解析。

- 目录中的日期为报告期，披露日期、下载日期、来源 URL、公告标识、文件名和内容哈希写入索引与 manifest，不混用。
- 同报告期出现修订文件时，生成新哈希目录并保留旧版；索引登记修订关系及有效版本，旧 checklist 仍引用旧快照。
- 下载到临时文件，验证 HTTPS 来源、PDF 文件头、大小及可读性后原子落盘；失败不登记为可用文件。只有指定股票新增资料或用户明确刷新时访问公告源。
- 优先使用上交所/深交所或巨潮的正式公告，公司官网为补充；无法自动确认股票、报告期及修订关系时标记待核对，不能将错误文件作为有效报告。
- 目前两个样例目录保留，导入时按文件哈希登记为正式资料，不移动或删除来源样本。重复导入不重复建档和解析。
- 日常清理 `data/verification` 不触及 `data/company_reports`。

## SQLite 中新增的复用资料

正式事实以 SQLite 为查询入口，PDF/完整逐页文本保存在文件系统；文件中的 manifest、quality 是索引与诊断副本，不是第二套业务事实真相。

| 表 | 用途和主要字段 |
|---|---|
| `company_report_documents` | 股票、报告类型、报告期、披露日期、公告标识、来源 URL、文件哈希、相对路径、解析状态由关联解析表记录、修订关系；按股票/类型/期次/内容哈希去重 |
| `company_report_parses` | 文件 ID、解析器名称及版本、状态、页数、逐页文本相对路径、质量信息、失败原因；同文件及同解析器版本唯一，成功事实按提取版本保留，原件哈希异常会使对应解析标为失败 |
| `company_report_facts` | 文件/解析版本、提取规则版本、主题、原始事实值或短原文、PDF 页码及主题原文（期间与来源从原件索引关联）、来源片段、质量状态；不可变版本，保留不同报告的事实，不覆盖历史 |

第一阶段“事实”以规则定位的原始披露片段和可靠表格单元格为主，模型不参与每次后台刷新。无法可靠识别的地区收入表、控制权图等留原页引用并标记待核对；不能只凭几个关键词猜出数值。表格保留完整表头、单位和关键脚注；正文页码与 PDF 页码分别记录。

只下载、解析相关财报，正文切片按主题组织：公司与产品、战略、市场地区、股权、行业景气、竞争、产业链、上下游。后续如要增加模型辅助事实提取，必须由用户明确操作触发，并保存提取提示词/模型/输出版本；不能因为缓存失效或普通数据刷新而暗中调用模型消耗额度。

## checklist 输入与输出

输入版本 `stock_checklist_input_v1`、计算版本 `stock_checklist_calc_v1`，与旧研判区分；定义固定 18 个项目 ID，中文标题由程序提供。

- 公司与行业：加载最新可用报告对应主题片段；新中报覆盖的内容优先，未覆盖内容沿用年报，保留实际报告期。行业景气写“截至报告期”的阶段判断。
- 财务：优先适用 gjzb，缺失回退三表；沿用既有已验证计算，附最新期及可比基期，记录直接取数和计算口径。
- 分红：去重已实施事件，按完整归属年度汇总最近 3—5 年；可包含三季度/特别分红，不能只写死中期与末期；待实施方案单列，金额缺失不当零，送转或拆股等影响可比性时注明。
- 估值：复用十年 PE/PB 分位算法，记录实际覆盖、有效样本与采样规则；采用最后有效交易数据，不让非交易日重复记录变成新行情。
- 筹码：最近三个不同统计日期的同口径股东户数，不限定必须季末；融资最近一年按自然周取最后有效余额，净买入按周求和，覆盖缺失和首末不完整周均保留；同时提供全年与近期趋势。
- 价格：同一有效前复权版本、最近三个月，提供必要趋势事实；不混合多个复权版本。
- 所有证据分配固定 ID，资料包中保留数值、基期、期间、来源及关键限制。快照在单次本地读事务中创建，不在该事务中下载或调用模型。

模型输出建议为 JSON：`schema_version`、`items`；每项包含 `id`、`conclusion`、`evidence_ids`、`status`。status 为内部资料状态：`ready`、`limited`、`missing`、`not_applicable`，不是投资评分。公司名、日期、标题、事实数字与出处详情由程序展示。

校验包括 18 项齐全且无重复、文本类型/大小、证据 ID 合法、支持性引用和资料缺失状态；每项一两句话/约90字是编辑偏好，不因轻微超长让整份合法结果失败。缺失项引用资料状态，不能为凑齐引用编造来源。保留必要的程序数值/方向核对，不宣称程序能验证所有自由文本语义。

## 页面与触发流程

1. 股票页面显示“投资 checklist”，点击打开已有 checklist；没有时显示准备状态和“生成 checklist”。已有旧研判不自动转换，也不因打开页面自动调用模型。
2. 没有可用财报时，“准备财报资料”进行下载、解析及本地汇总；首次生成操作也可显式包含准备步骤。进度分为下载、解析、生成，不能把本地准备与模型消费混在一个无说明的操作里。
3. 本地资料准备完成后一次模型请求输出 18 项。缺少个别资料允许局部标注待补；只在无法识别股票、无可用实质资料或数据更新冲突时阻止生成，取消旧的8期数据、行业分类和买入候选准入门槛。
4. 页面默认两列“检查项目/结论”，按公司、行业、财务、估值与筹码分组，依据折叠展示；保留历史、重新生成、取消和用量说明。
5. 当前页面的历史列表只列 checklist。旧研判历史与旧 renderer 保留供以后恢复，但不混入 checklist 的最新报告、按钮或列表。默认公共生成入口只走 checklist，旧生成分支不作为页面可调用选项。
6. 原“AI 设置”继续使用；查看报告、准备普通财报资料和常规数据刷新均不自动触发付费模型调用。只有明确生成/重新生成才调用。

## 缓存与更新规则

| 变化 | 处理 |
|---|---|
| 打开已有 checklist | 读取 SQLite，不重新下载、解析或请求模型 |
| 财报文件内容和解析器版本相同 | 直接复用逐页文本和主题片段 |
| 新中报/年报/修订版 | 仅解析新增文件；新资料标记现有 checklist 有更新，旧结果保留 |
| 财务、估值、股东、融资更新 | 更新本地资料包相应部分，不重解析未变的 PDF，不自动生成新报告 |
| 提取规则版本变化 | 重建受影响主题；必要时重解析，不抹掉旧版本 |
| 提示词、输入或计算版本变化 | 新生成使用新版本；旧报告按生成时版本显示，不静默改写 |
| 输入+提示词+模型相同 | 沿用现有幂等与成功报告复用机制；明确重新生成时可产生新任务 |

新输入哈希只包含实际可见事实、方法版本、证据来源与业务日期，不包含重复抓取时间/sync ID。同一股票快照、模型和提示词相同才能复用；补资料、修订或算法变化造成输入变化。

## 历史可追溯、备份与清理

- 延续现有 `ai_analysis_snapshots`/`ai_analysis_runs`，新增报告类型标识或使用版本显式分派；不为每项建一张表，也不另建一套报告任务库。
- 每份成功 checklist 固定其输入、证据片段、来源文件哈希、解析/提取/计算/提示词版本和输出。即使未来源文件暂不可用，报告与其保存的证据摘要仍可离线查看。
- 删除 checklist 历史只清理无引用任务与快照，不连带删除可复用财报。财报清理属于独立维护功能，必须检查引用，不清理被历史或当前索引引用的原件。
- 保留现有 SQLite 日备份机制；明确数据库备份不包含文件系统里的 PDF/逐页缓存。增加正式资料目录的备份说明和独立“完整资料备份”工具：数据库一致副本 + 相关原件/必要解析文件 + 文件哈希清单；不修改现有日备份的含义，不让每次生成都复制大量 PDF。
- 恢复时验证文件哈希和相对路径；资料缺失提示可重新下载，历史报告仍可读。凭据仍按现有规则不进入资料或备份包。

## 开发顺序与验收

1. **资料层**：新增迁移、正式目录、下载索引、解析缓存和主题片段；先导入现有中远海控与伊利样本。验证重复导入无重复、缓存命中不重解析、修订及失败不污染有效版本。
2. **资料包**：实现 checklist 专用快照，接入 gjzb、分红、十年分位、三期股东和一年周度融资；以两份已确认样例为数值和缺项验收基准。
3. **AI 生成**：接入新提示词与 JSON 协议，改造报告类型分派并兼容原成功约束，复用登录和任务能力；测试取消、失败、幂等、未知引用和旧记录兼容，使用模拟供应商不消耗真实额度。
4. **页面切换**：替换入口与正文展示，保留旧代码和旧记录但不挂载；确认普通打开/刷新/查看历史不会请求模型，旧研判不混入新列表。
5. **验收与资料整理**：隔离临时库回归；通过后自动重启 8765 日常后台并检查启动日志和页面，保留运行供用户验收。真实模型首次结果与耗时需单独验证，不把模拟测试当作真实效果。

重点案例：伊利“其他地区”不能等同海外；伊利2025分红必须纳入三季度0.48元；中远海控期后控制权变更优先于年末旧关系；股东日期含非季末；负PE、零值、缺失融资周、财报修订、跨版本历史读取和资料备份恢复。

首阶段范围是替换页面功能并建立可复用资料层。批量全市场 PDF、自动联网研报、自动付费事实提取、复杂 OCR、同行评分和买卖结论不纳入。解析失败的扫描文件保留待核对状态，后续确有需求再扩展。

- 调整：`analysis_service.py`、`analysis_repository.py`、`server.py`、数据库迁移/校验、备份说明、`.gitignore`。

## 首阶段验收说明

- 自动准备最新年报和中报；复用本地四表、分红、估值、价格、股东和融资数据。三期股东不足或一年融资明显不完整时标记资料有限。
- 采用版本化规则提取带 PDF 页码的主题原文，不调用第二次模型。表格保留原文与质量提示，不宣称已自动核验所有附注口径；模型必须保留未披露、抵销与分类限制。
- 优先使用中报主题，控制权、使命、议价保留年报补充；事实来源与旧快照可离线追溯。
- 完整资料备份通过 `python -m quarterly_dashboard.report_backup --output <新zip路径>` 手动生成，恢复只写入不存在的新目录，不覆盖日常库。
- 实际模型结论和响应耗时仍由用户首次点击生成验收；开发使用模拟模型，不消耗真实额度。
