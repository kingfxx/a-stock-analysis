# 后台维护页

侧边栏「后台维护」展示当前日常 SQLite 的只读统计。进入页面时读取一次，点击「刷新本地统计」重新统计；不会触发个股采集、行业更新或模型调用。接口为 `GET /api/maintenance/storage`，默认复用最多 60 秒的内存快照，`?refresh=1` 强制重新统计。

维护页分为「数据库预览」和「未关注股票管理」两个标签，默认展示数据库预览。数据库统计、数据表清单与数据库恢复放在数据库预览；已取消关注列表和未关注股票数据清理集中放在未关注股票管理，切换标签时按需读取本地列表。

## 统计内容与口径

- 表名、用途、分类、记录数、列数、索引数；支持名称／用途搜索、分类筛选及表头排序。
- 表大小和索引大小分别列出，合计默认从大到小排列。记录数包含保留的历史版本，不等于公司数。
- 大小是已分配物理页占用，包含页内空余，不是字段内容的字符串长度。数据库总占用同时显示表、索引、空闲页和系统页。
- 优先使用 SQLite `dbstat`；运行时未提供此扩展且数据库为回滚日志模式时，在 SQLite 只读事务保护下遍历 B-tree 和溢出页。格式依据 [SQLite 文件格式](https://www.sqlite.org/fileformat.html#b_tree_pages)。WAL 模式没有 `dbstat` 时逐表大小显示不可用，不估算。
- 回退统计按需读取单页，不映射整份数据库；访问标记采用每页一位的位图。页缓冲最大 64 KiB，页大小、重复引用和读取完整性均校验，统计口径不变。
- 数据更新时间取已有采集、写入或关联批次时间，页面逐表说明字段依据。报告期不会当作更新时间；缺少时间记录显示「未记录」，空表显示「暂无数据」。删除记录等未留时间的操作不能从这些字段中推断。
- 同时显示当前数据库路径、结构版本、SQLite 版本、日志模式、最近备份与备份目录总大小。备份时间来自文件修改时间；原始响应、PDF 和备份文件不计入 SQLite 表大小。

统计读取使用只读连接，表格首列、表头固定；窄屏在表格内横向滚动。用途说明维护在 `quarterly_dashboard/maintenance.py` 的 `DESCRIPTIONS`；新增表尚未登记时显示「尚未登记用途」。

本次验收资料位于 `data/verification/reports/maintenance_20261004/`。

市值来源集中保存于 `sw_cap_provenance`，`sw_cap_facts.provenance_id` 引用完整来源 JSON。维护页将来源说明与市值明细分别列出，并从关联市值导入批次读取来源表的更新时间。Schema v13 的整理报告位于 `data/verification/reports/cap_storage_compaction_20261004/`。

## 已取消关注

分组管理中，「移出当前管理组」仅解除所选管理组的归属，股票继续出现在其他分组和「全部股票」中。从最后一个自建组移除后仍保留关注，进入「未分组」。勾选一只或多只股票后点击「取消关注」，确认后从所有自建组、全部股票、未分组、最近查看及选股搜索中移除。

后台维护的「已取消关注」展示股票名称、代码、取消关注时间及仍可恢复的原分组，支持搜索、单选和批量恢复。恢复后重新加入「全部股票」及仍然存在的原分组，按保存位置插入，保持现有成员的相对顺序。原分组改名时跟随新名称；原分组已删除时不重建，也不会误加入后来复用相同编号的新组。无可恢复分组的股票进入「未分组」，最近查看在下次实际查看时记录。

取消关注仅修改整理状态，保留股票基础记录、财务与行情事实、同步水位、正式财报 PDF、解析／主题缓存、checklist 和研报历史；不删除业务资料或自动回收磁盘空间。查看保留数据时不自动更新，个股数据更新接口也会阻止取消关注股票的更新，须先恢复关注。取消前已经开始的请求可能完成并保存数据，但不会重新关注股票。全市场行业采集独立运行，仍可覆盖这些股票。恢复关注本身只复用本地资料，不立即采集或调用模型；打开股票后按原更新规则补齐数据。

Schema v15 新增 `stock_unfollowed` 保存当前取消关注状态及 `unfollowed_at`，恢复时删除该状态；`stock_unfollowed_groups` 保存可恢复的原分组归属及位置，通过外键关联取消状态和分组。前者的更新时间直接读取取消关注时间，后者关联读取该时间；空表显示暂无数据。恢复、删除分组等删除操作没有独立审计时间，不从其他字段推断。

接口：`POST /api/stock-groups` 的 `unfollow` 操作接收 `codes`；`GET /api/maintenance/unfollowed` 只读列表；`POST /api/maintenance/unfollowed` 的 `restore` 操作接收 `codes` 并返回更新后的列表及关注分组。批量操作使用单个事务，重复请求不会覆盖原取消时间／分组，非法批次整体回滚。写请求沿用本地同源检查和日备份机制。

释放空间通过下面的独立清理入口完成，取消关注和恢复本身不删除业务资料。

## 未关注股票数据清理

后台维护提供独立的「未关注股票数据清理」。候选仅包含当前已取消关注的股票，展示取消关注天数、分类别记录数、文件数和实际文件字节数，支持代码／名称搜索、最少取消天数筛选和批量选择（每批最多 100 只）。不会自动清理日常数据；先选择范围并预览，再在确认弹窗输入「清理」执行。预览有效期 15 分钟，改变选择会使页面预览失效；执行时数据、文件哈希、关注状态或引用与预览不一致则拒绝执行，须重新预览。

默认仅选择「可重建缓存」。四类分别为：

- **可重建缓存**：个股 fundamentals／valuation／筹码旧 JSON 及 `.json.bak`（有数据库事实才按可重建处理）、正式财报的已登记解析／主题记录和 `parsed/` 内 JSON／JSONL。原件缺失、哈希异常或存在保留研究引用时保留解析；未知格式附件、原始来源样本和 verification 资料不删除。
- **个股财务与行情数据**：明确允许的财报、人工修正、行情版本、估值、分红、融资和股东记录，以及相应同步水位／导入标记。必须同时选缓存，防止清理后重新导入旧文件。保留来源同步日志；部分事实仍受引用保护时，对应同步水位继续保留。
- **研究历史与导出研报**：选中个股的 AI/checklist 任务、无保留任务引用的输入快照，以及该股票独立目录下的导出研报文件。行业页引用的最近一次成功研究、其他保留研报引用的记录或文件不删。
- **正式财报原件**：不再被保留研究、共享文件或修订链引用的登记记录和 PDF，连带其解析／主题缓存。保留版本目录及微小 manifest，使后续导入继续使用递增 `vN`，不复用已删除编号。

预览逐股逐类别列出拟删除及保留数量、保留原因、具体文件清单和文件占用。记录数不换算成磁盘可释放字节数；文件字节数也不是净释放空间。SQLite 逻辑删除形成库内可复用空间，通常不会立即缩小文件，本操作不自动执行 `VACUUM`。

### 行业内对比与共享引用保护

清理使用固定表白名单，**不删除或更新任何 `sw_*` 行业表、`industry_sources/` 文件、股票基础信息、行业分类来源 `industry_snapshots`、关注状态及原分组恢复信息**。已有行业财务、市值、季度名单、来源和历史版本保持不变。勾选「个股财务与行情数据」后，所选未关注股票的 `financial_reports` 全部记录（含 `gjzb`／`lrb` 及其他报表类型）和对应财务同步／导入标记进入清理范围，不因行业成员身份、来源哈希或研究引用而保留。行业财务事实和来源记录仍保留，来源哈希不再保证能定位到在线原始行，如需追溯须使用已有备份或保留研究快照；下次行业采集缺少本地值时使用东方财富，接口缺值则留空。行业页按现有规则引用的最近成功研究及其快照／来源继续保留，因此清理其他个股历史不改变行业页已展示的摘要和比较数据。

保留研究的快照、来源清单、正文和导出研报用于检查财报 ID、内容哈希、路径和价格版本引用；相应原件、解析和其他事实保留；`financial_reports` 是明确财务清理的例外，历史研究快照自带当时的财务输入，不随原始行删除。财报修订关系及共享文件引用也受保护。价格版本仍有有效页面租约时暂不清理相关行情，可待租约到期后重新预览。

### 任务与失败恢复

预览显示正在运行的采集、行业、财报准备或 AI 任务。执行仅在没有运行任务、没有其他活动页面请求时冻结新请求，并在写事务内重新检查完整范围；无法安全执行时原数据保持不变。

所有清理类别均不在执行前创建 SQLite 或文件备份。用户确认并成功提交后，不能通过本次清理操作恢复。原有正式备份和原始来源样本不在候选清理范围内，不会删除。事务期间仍使用文件移动暂存和操作日志实现失败回滚及中断恢复；成功后删除暂存文件，不保留恢复副本。

文件先移动至 `data/cleanup_staging/<操作ID>/files/`，数据库删除及 `stock_cleanup_runs` 提交标记在同一事务完成。事务失败时回滚记录并恢复暂存文件；进程中断后，启动在旧缓存导入之前核对提交标记：未提交的操作恢复文件，已提交的操作完成暂存清理，不把已经清理的资料重新导入。不会覆盖恢复目标已存在的文件。审计报告保存在 `data/verification/reports/stock_cleanup/<操作ID>.json`。

Schema v16 新增 `stock_cleanup_runs`，保存清理范围和结果（兼容字段 `backups` 对新操作始终为空）以及 `created_at`／`completed_at`；维护统计直接使用这两个写入时间，空表显示暂无数据。接口为 `GET /api/maintenance/stock-cleanup`、`POST /api/maintenance/stock-cleanup/preview` 与 `POST /api/maintenance/stock-cleanup/execute`。写接口要求同源、本地会话凭证以及预览令牌；客户端不能传任意文件路径或表名扩展清理范围。

## 从备份恢复 SQLite

校验通过表示完整性与升级后的结构兼容性通过，不代表备份数据与当前库一样齐全。预览分别列出原备份表数、升级副本表数、迁移补建表及其记录数；补建结构不等于补齐历史数据，恢复不会合并当前库的数据。

「数据库恢复」可选择 `data/backups/*.sqlite3`，也可上传本地 `.sqlite3`／`.sqlite`／`.db` 文件（最大 4 GiB）。上传流式保存到 `data/restore_staging`，不把整份文件读入内存。仅接受本项目独立、完整、回滚日志模式的数据库备份。

点击「校验备份」只操作临时副本：核对项目标识、迁移历史及校验码、SQLite 完整性、外键和业务关联；支持的旧版本在副本中升级，再检查当前页面所需的表、字段、索引与触发器。高于当前程序的版本、损坏文件、陌生数据库和不兼容结构拒绝恢复。原备份和当前库保持不变。页面显示文件时间、大小、原版本／目标版本及已记录标的数；校验结果 15 分钟有效，取消或过期清理临时文件。

点击「恢复此备份」后，确认弹窗要求输入“恢复”。带本地会话凭证和同源校验的确认请求只能使用已经校验的令牌，不接受任意文件路径。有采集、行业任务、AI 任务或其他页面请求时拒绝确认。

确认后冻结新请求，关闭监听并排空请求线程；持有实例锁再次检查任务状态及临时副本 SHA256。先生成 `data/backups/before-restore-<时间>.sqlite3`，然后原子替换数据库。验证失败则回退至恢复前备份；清空内存服务缓存，重新打开同一端口并自动重载前端。重载时跳过外部旧缓存导入，避免将较新缓存混入恢复后的快照。此流程不会主动采集或调用模型。原 CLI 的 `restore_backup` 仍只允许恢复到新文件。

仅恢复 SQLite，不恢复 PDF、原始响应及解析文件。恢复会替换备份之后新增或修改的数据库记录，原件需单独保留。操作记录保存到 `data/verification/reports/database_restore/`；程序异常中断时提示核对当前库与恢复前备份，不自动重复执行。默认不会运行恢复；本功能验收的完整恢复流程仅使用隔离测试库。


## 整理数据库空间

「未关注股票管理 → 整理数据库空间」独立执行 SQLite `VACUUM`，将清理后形成的库内空闲空间归还磁盘，不删除业务记录、不创建备份。用户点击按钮后弹出提示框，点击「执行整理」确认，无需输入文字，完成后显示文件大小前后变化和实际释放字节数，自动刷新本地统计。没有可回收空间时释放量可能为零。

`POST /api/maintenance/compact` 要求同源、本地会话凭证及 `{"confirm":"整理"}`。执行与个股清理共用维护锁、请求冻结和财报准备锁，拒绝运行中的采集、行业、AI 任务及其他活动请求；获得 SQLite 排他锁后再次核对任务。执行前后检查 SQLite 完整性和外键，数据库目录及系统临时目录均须有至少当前库文件两倍的空闲空间，不足则拒绝整理。当前支持日常使用的 DELETE 回滚日志模式，SQLite 自身事务日志用于失败恢复。整理期间不可使用其他页面；失败或连接中断后应核对后台日志和统计，再决定是否重试。整理成功后旧清理预览失效，须重新预览。

空间和事务要求依据 [SQLite VACUUM 官方说明](https://www.sqlite.org/lang_vacuum.html)。

## 行业财务逻辑 View

结构版本 20 增加 `market_financial_industry`，用途已登记。它不保存数据、不分配数据页，统计接口在 `views` 单独返回用途、分类、零存储大小及更新时间，不计入物理表数量、记录数或空间总和，避免重复统计基础表。更新时间取利润表、业绩指标最新行的实际 `updated_at`；空视图为未记录，不用报告期代替。
