# 后台维护页

侧边栏「后台维护」展示当前日常 SQLite 的只读统计。进入页面时读取一次，点击「刷新本地统计」重新统计；不会触发个股采集、行业更新或模型调用。接口为 `GET /api/maintenance/storage`，默认复用最多 60 秒的内存快照，`?refresh=1` 强制重新统计。

## 统计内容与口径

- 表名、用途、分类、记录数、列数、索引数；支持名称／用途搜索、分类筛选及表头排序。
- 表大小和索引大小分别列出，合计默认从大到小排列。记录数包含保留的历史版本，不等于公司数。
- 大小是已分配物理页占用，包含页内空余，不是字段内容的字符串长度。数据库总占用同时显示表、索引、空闲页和系统页。
- 优先使用 SQLite `dbstat`；运行时未提供此扩展且数据库为回滚日志模式时，在 SQLite 只读事务保护下遍历 B-tree 和溢出页。格式依据 [SQLite 文件格式](https://www.sqlite.org/fileformat.html#b_tree_pages)。WAL 模式没有 `dbstat` 时逐表大小显示不可用，不估算。
- 数据更新时间取已有采集、写入或关联批次时间，页面逐表说明字段依据。报告期不会当作更新时间；缺少时间记录显示「未记录」，空表显示「暂无数据」。删除记录等未留时间的操作不能从这些字段中推断。
- 同时显示当前数据库路径、结构版本、SQLite 版本、日志模式、最近备份与备份目录总大小。备份时间来自文件修改时间；原始响应、PDF 和备份文件不计入 SQLite 表大小。

统计读取使用只读连接，表格首列、表头固定；窄屏在表格内横向滚动。用途说明维护在 `quarterly_dashboard/maintenance.py` 的 `DESCRIPTIONS`；新增表尚未登记时显示「尚未登记用途」。

本次验收资料位于 `data/verification/reports/maintenance_20261004/`。

市值来源集中保存于 `sw_cap_provenance`，`sw_cap_facts.provenance_id` 引用完整来源 JSON。维护页将来源说明与市值明细分别列出，并从关联市值导入批次读取来源表的更新时间。Schema v13 的整理报告位于 `data/verification/reports/cap_storage_compaction_20261004/`。

## 新增表交付检查项

- [ ] 在 `quarterly_dashboard/maintenance.py` 的 `DESCRIPTIONS` 登记用途和分类；表改名或用途变更时同步更新。
- [ ] 核对 `TIME_COLUMNS`、`PARENT_TIMES` 或 `table_time` 中的更新时间依据，明确实际字段或关联批次；无适用记录时说明原因并显示「未记录」，不使用报告期或交易日替代。
- [ ] 在隔离数据库迁移后核对统计接口／维护页的表发现、用途、分类、记录数、大小和更新时间显示；特殊时间规则检查空表及缺值，并更新相关文档。

## 从备份恢复 SQLite

校验通过表示完整性与升级后的结构兼容性通过，不代表备份数据与当前库一样齐全。预览分别列出原备份表数、升级副本表数、迁移补建表及其记录数；补建结构不等于补齐历史数据，恢复不会合并当前库的数据。

「数据库恢复」可选择 `data/backups/*.sqlite3`，也可上传本地 `.sqlite3`／`.sqlite`／`.db` 文件（最大 4 GiB）。上传流式保存到 `data/restore_staging`，不把整份文件读入内存。仅接受本项目独立、完整、回滚日志模式的数据库备份。

点击「校验备份」只操作临时副本：核对项目标识、迁移历史及校验码、SQLite 完整性、外键和业务关联；支持的旧版本在副本中升级，再检查当前页面所需的表、字段、索引与触发器。高于当前程序的版本、损坏文件、陌生数据库和不兼容结构拒绝恢复。原备份和当前库保持不变。页面显示文件时间、大小、原版本／目标版本及已记录标的数；校验结果 15 分钟有效，取消或过期清理临时文件。

点击「恢复此备份」后，确认弹窗要求输入“恢复”。带本地会话凭证和同源校验的确认请求只能使用已经校验的令牌，不接受任意文件路径。有采集、行业任务、AI 任务或其他页面请求时拒绝确认。

确认后冻结新请求，关闭监听并排空请求线程；持有实例锁再次检查任务状态及临时副本 SHA256。先生成 `data/backups/before-restore-<时间>.sqlite3`，然后原子替换数据库。验证失败则回退至恢复前备份；清空内存服务缓存，重新打开同一端口并自动重载前端。重载时跳过外部旧缓存导入，避免将较新缓存混入恢复后的快照。此流程不会主动采集或调用模型。原 CLI 的 `restore_backup` 仍只允许恢复到新文件。

仅恢复 SQLite，不恢复 PDF、原始响应及解析文件。恢复会替换备份之后新增或修改的数据库记录，原件需单独保留。操作记录保存到 `data/verification/reports/database_restore/`；程序异常中断时提示核对当前库与恢复前备份，不自动重复执行。默认不会运行恢复；本功能验收的完整恢复流程仅使用隔离测试库。
